# AlphaLake 数据维护

使用已有同步、查询及发布入口完成用户请求，不另写采集器，不把数据刷新变成参数选择或估值模型调整。

## 定位与任务范围

- 优先使用会话已确认的仓库或`ALPHALAKE_ROOT`，否则检查当前目录及父目录的`cmd/alphalake`和`valuation/backend/tools/publish_native_valuation.py`。Skill安装目录不是工作目录；进入仓库后读`AGENTS.md`、`README.md`及`docs/implementation-status.md`。
- 从用户请求、既有发布收据和已确认配置取得数据库、来源、报告期、证券范围和输出位置。复用已有授权；仅确实缺少必要信息时询问缺失项。当前数量与日期读实时收据，不写死在Skill。
- 主库是`workspace/alphalake.duckdb`，网页快照是`workspace/valuation.sqlite`。v12快照只含估值宽表、TTM、参考及紧凑上下文，完整事实、审核与候选分母留在主库/数据侧收据；网页运行不依赖DuckDB，详细核验不能再查询SQLite辅助事实表。动态来源归档及收据沿现有workspace布局，不能另建日常主库或把运行结果提交到仓库。
- 沪深非金融是默认业务范围；保留既有失败、金融范围外及分类待定分母，不按成功筛清单，不顺便扩展北交所、历史年限或参考分类。

按请求读取[日常同步](references/daily-sync.md)中对应部分及其链接的当前操作契约：

| 用户需要 | 操作边界 |
|---|---|
| 查看状态／数据新鲜度 | 读取主库、发布收据及来源日志，不触网刷新，不重算估值 |
| 刷新业绩预告 | 东财结构化预告＋巨潮目录／PDF入主库；不重建财务SQLite或改故事条件 |
| 刷新财务 | 已有TDX缓存／上游清单→源同步→标准物化；未发布时明确网页仍为旧快照 |
| 刷新行情／参考 | 限定当前消费范围及既有来源，更新主库；网页更新另走统一发布验收 |
| 更新数据并发布网页 | `tools.publish_native_valuation`冻结当前完整发布范围，验收后原子切换 |
| 公司估值／故事与修订 | 转用仓库`skills/alphalake-valuation/SKILL.md`；不附带全市场同步 |

只有用户要求整体刷新时才组合各来源；“刷新预告”不等于同步全部数据，“同步入库”不等于网页发布。保持手工执行，不安装定时任务。

## 执行与核验

巨潮PDF共用[归档与引用规则](../../docs/guides/workspace-layout.md#pdf归档与引用)：唯一原文在`cninfo/objects/`，按官方URL日期／公告ID建立软链接及哈希、原始取得时间收据。下载前逐URL加锁并核验共享缓存；已有健康原文不因新同步批次再次下载或归档，源角色与公告身份分别留痕。研究输出只保留来源路径、哈希及页码，原始取得未知留空；不用本次复用时间冒充首次取得或上游最新。

大库同步、物化、导出及会启动Go的Python任务，按`docs/guides/fundamental-memory-20260919.md`置于独立systemd服务并串行运行。核验独立ControlGroup及1GiB硬限额，当前MemoryHigh=960MiB、Swap=0、DuckDB=512MiB／1线程、GOMEMLIMIT=512MiB／GOMAXPROCS=1；显式设置GOPATH/GOCACHE，检查系统剩余资源。同步任务使用真实workspace；测试使用独立临时目录，不继承真实归档配置。

运行前保存相应查询和来源版本；每次收据写入新的`workspace/derived/<任务>/<运行标识>/`，不覆盖旧收据。用户已授权清理过期派生数据，不要求永久保留所有旧响应；清理时按[保留边界](../../docs/guides/workspace-layout.md#清理与迁移)核对当前发布、主库引用及唯一证据，留下必要条件、摘要和删除清单。先核对现有入口及帮助，示例中的参数从实际配置取得。

运行后同时读退出码、JSON收据、stderr和systemd结果：来源`completed`／`partial`／失败、范围是否完整、缓存回退、缺项及PDF下载分别统计。独立来源成功不能掩盖另一来源失败；不把HTTP200或进程退出0当作最新性证明。

关闭并重开查询，比较新增、删除、数值修订与仅来源／身份更新；支持离线重放的入口按相同范围和归档核验幂等，不重复在线抓取冒充重放。异常退出先查单元及内核日志，保留失败证据和WAL，不原参数盲重试、不删除WAL。

## 交付说明

简明报告报告期、取得时间、证券分母、每来源状态、变化及收据路径；区分源行、来源观测和公司数。分别注明财务期、报价日、股本基期、参考版本与实际网页发布状态。

TDX旧缓存合格不等于上游最新，离线回放不推进取得时点；无预告观测不等于零或公司未披露。更新`docs/implementation-status.md`的当前结论，历史验收不改写。Skill／文档变更做格式及链接检查，数据刷新做真实入口验收，不因此重跑无关全套测试。
