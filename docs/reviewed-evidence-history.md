# 审核证据与补充修订

本能力引入于结构版本041/042；代码及正式财务／参考库现均为44，见[发布验收](core-main-publication-20260918.md)。041 将镜像原文审核从诊断表独立，042 增加补充审核历史及撤销状态。已有数据库先在备份副本执行 `alphalake init DB`、验收后发布；只读导出不会自动升级。

## 镜像原文审核

`fundamental.document_review` 绑定公告、PDF 归档、审核 JSON 归档及哈希，保存审核时间和系统记录时间。镜像导入及估值导出不再依赖 `meta.validation_result`；清理诊断不改变有效审核。相同原文和审核重放不新增记录，原审核改写仍拒绝。

041 从旧 `reviewed_mirror_binding` 诊断迁移，要求匹配不可变审核 JSON 和 PDF；缺证、哈希不符或同一文档重复绑定使迁移失败，不任取一条。旧系统记录时间未知，保持 NULL。旧诊断不自动删除。当前镜像文档审核本身仍不可替换，未提供文档审核修订／撤销命令；本轮补充动作不等于撤销文档身份。

## 补充记录的当前投影和历史

`fundamental.reviewed_supplement` 保留当前审核头部，新增 `review_state`；`fundamental.supplement_review_history` 追加保存每次发布、修订和撤销的原始 JSON、内容哈希、前序哈希、审核时间及系统记录时间。两张表在同一事务更新。历史旧记录的两个时间未知时均为 NULL，新导入的系统记录时间由数据库产生。

原导入格式继续有效，省略 `action` 等同首次 `publish`；不新增字段时原 JSON 内容哈希保持不变。原格式重复导入仍为零新增，不允许隐式覆盖。

已有记录修订继续使用同一个命令：

```bash
alphalake import-supplements DB reviewed-revision.json
alphalake supplement-history DB 300866
```

`reviewed-revision.json` 仍是完整补充记录数组，增加三个字段：

```json
{
  "action": "replace",
  "supersedes_sha256": "当前记录的64位import_sha256",
  "reviewed_at": "2026-09-18T00:00:00Z"
}
```

此段仅展示新增字段，不能单独导入；公司代码、期间、项目、公告、金额、单位、范围、PDF哈希／页码、审核人及说明仍必填。使用 `supplement-history` 返回的 `is_current` 和完整 `reviewed_record` 确定当前头部。修订必须附新审核说明；内容可修正，但仍须绑定当前已归档原文。前序哈希必须恰好等于当前头部，不能从旧版本分叉；审核时间不得晚于当前时间或早于已知前序审核时间。

撤销用 `action: "revoke"`，保留当前金额、单位、期间口径、范围和原文定位，填写撤销原因及前序哈希。撤销状态保留在当前表：导出先选择最新公告，再排除撤销记录，避免退回更早公告的补充值。恢复需重新审核，使用 `replace` 指向撤销动作的哈希。旧发布／修订／撤销动作重放均不改变当前头部。返回计数为本次新发布审核动作数。

`supersedes_sha256` 是并发修订检查，不代表内容真实性认证；原文、范围及项目语义仍须审核。直接写 SQL 绕过导入器不在发布契约内。

## 时间与估值边界

公告披露可用时间、审核时间与系统记录时间分别保存。估值导出的 `--as-of` 仍按披露时间选择公告，消费当前有效审核结论；本轮没有增加按历史系统时点选择审核版本的估值接口。因此后来修正的审核可以改变旧披露时点的重新计算，不能冒称当时系统已拥有该输入。旧估值 run JSON 保留当次实际输入，审核历史用于解释差异，不覆盖既有运行。

撤销后依赖该补充的政策必须按缺证拒绝；修订后，固定旧 `import_sha256` 的采用政策须重新审核，不能自动改绑定。未变记录的导出字段与旧内容哈希保持兼容，当前导出不增加审核时间字段来隐式改变全部政策绑定。

## 验证范围

- 合成补充验证修订、错误前序拒绝、撤销不回退、旧动作重放不复活、批次失败原子回滚、关闭重开与显式恢复；历史查询保留全部动作。
- 苏泊尔真实镜像 PDF 验证独立归档绑定、诊断清理不影响导出及重放、错误文档哈希拒绝。
- 使用同一真实证据构造 schema40 旧存储形态，执行正式 041/042 升级及幂等重放；缺审核归档的迁移拒绝，不推进结构版本；未知旧时间不补造。
- 这些测试不等于主库升级，也不扩大已审核公司或补充字段的覆盖范围。

## 已有 CNINFO 原件的离线补归档

`import-cninfo-document <db> <raw-root> <receipt-json> <pdf>` 用于有真实下载回执的 CNINFO 原件：回执包含 `code`、`period`、`announcement_id`、`url`、`sha256`、`fetched_at`。必须匹配库内已有且已解析的公告，只填空原文；校验原始下载时间、官方URL、PDF头及内容哈希，拒绝覆盖不同文档或镜像来源。重复导入保持原获取时间，损坏的本地缓存可按相同原件修复，不推进采集检查点。

该入口不从哈希推断真实性；回执必须来自已留存的真实下载记录。镜像仍走前述独立审核入口，不可伪装成官方直接下载。安克2026H1回执来自 `internal/ingest/testdata/anker-valuation-2026/reports.json`。
