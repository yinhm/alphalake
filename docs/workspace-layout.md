# 工作目录与缓存约定

动态数据仅存放于项目 `workspace`（Python可用 `ALPHALAKE_WORKSPACE` 显式改根目录）；临时验证使用系统临时目录。代码、安装环境及冻结测试资料与动态数据分开，不把历史日期目录当作运行配置。

- `alphalake.duckdb`：唯一权威同步库。财务、公告身份、审核补充和已接入的参考数据在同一库内；达摩达兰原始工作簿另存 `damodaran/`，不是独立参考库。
- `tdx-cache/`：仅放 `gpcw.txt` 和直接落盘的 `gpcw*.zip`，不放对象目录、软链接或逐包JSON。每次按上游MD5和大小判断是否更新。
- `tdx/`：主库血缘引用的不可变原始证据；旧版本不覆盖，不参与日常手工缓存管理。
- `damodaran/`：按可识别的原文件名直接落盘，主库不可变证据文件追加12位内容摘要区分版本；无objects或哈希分层，行业名称映射保留在industry_lookup。
- `cninfo/`、`chinabond/` 等：按真实来源保存原文。`objects/` 按哈希寻址，必要的 `views/` 或估值文件名视图引用相同内容。
- `derived/valuation.sqlite`：网页消费的派生快照；`derived/valuation-runs/`：既有不可变估值运行；`derived/cleanup-audit/`：迁移清单、数据库审核快照及ID映射。

## 缓存行为

财务同步先读取本地清单，再轻量检查上游清单。上游失败时可复用本地清单；来源身份刷新失败但已有证券身份时，保留并使用已有身份，不创建猜测身份。所有回退写入 `financial.local_cache_fallback` 诊断，CLI输出 `cache_fallbacks`，运行标记partial。

每个包按MD5和大小核对，优先复用已归档证据或本地缓存。上游新包下载失败，可使用主库归档哈希验证过的旧缓存；该次只处理实际缓存版本，不把新MD5写成完成检查点。清单与包版本可能不同，主库血缘绑定实际内容；不能凭文件名或修改时间认定最新。缺文件、损坏或未能验证的缓存不会变成空事实。

清单和包都通过现有上游hosts策略访问；没有HTTP后备或自建分段重组。原始文件、首次取得记录和被历史事实引用的版本保留。缓存文件先写临时文件再替换，失败不删除原始对象。

## 本轮合并范围

财务源事实仍19,310,544条，标准事实仍5,627,307条。本轮仅迁移路径、合并参考数据，不声称新增财务同步。

主库已有达摩达兰公司行业名单；另从既有来源库合入国家风险6条、权益风险溢价4条、信用利差15条、行业Beta376条、行业资本效率94条，以及国债收益率8条。数值、来源定位、发布日期、可用时点和首次取得时间按原记录保留，发布/归档/运行ID映射有记录。该范围不是达摩达兰网站全部数据集均已解析；原估值项目的冻结资料也不自动成为标准事实。

36个财务包可与已保存的官方清单配对，只有2个匹配最近取得的清单，其余明确为较早版本；其中未来报告期占位文件仍按原规则跳过。缓存可用不等于上游新包已完成入库。

主库归档路径均改为相对workspace的来源对象路径。日期目录中的原文件去向、哈希和理由记录于 `derived/cleanup-audit/file-plan.jsonl`；旧库的小规模表及元数据审核快照压缩保留，不能把这些快照冒称可直接恢复的整库备份。保留原始证据及估值运行，移除旧库、重复导出、临时工具和重复下载。

8080网页继续使用迁移前同一SQLite内容，仅调整路径和Python环境；界面与估值方法不改。默认SQLite不再静默回退到代码目录内的示例库；缺数据需按导出命令显式建立。仓库原有冻结模板、测试与历史研究资料保留，不作为动态写入位置。

本轮清理核验了主库引用的13,132份归档，记录19,229个旧文件路径的去向、哈希及删除原因；当前workspace仅一份DuckDB。主库原有36,196,103条诊断随整库保留，其他旧库的诊断单独压缩归档，不重复导出主库诊断。运行目录清理后约7.2GiB（包括从代码目录移入的历史估值运行）；该大小随同步增长，不作为固定配额。

验收：Go全套测试及CLI构建通过；Python全套472通过、5跳过，其中一项因冻结PDF的目录引用缺失，恢复引用后与网页/路径测试一起5项通过，剩余4项为上游示例文件缺失。主库重开、WACC参考导出及94条行业资本效率导出通过；8080健康检查、安克搜索及行业目录比对通过。完整日志保存在cleanup-audit，本轮没有联网补数或改变估值方法。
