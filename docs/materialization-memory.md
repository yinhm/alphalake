## 复现入口

复用既有性能工具；`--output`必须为不存在的目录，源库须关闭且无WAL。大任务必须在上述隔离服务中串行执行：

```bash
go run ./cmd/financial-storage-bench \
  --database workspace/alphalake.duckdb --root "$PWD/workspace" \
  --output workspace/derived/materialize-memory/new-run \
  --replay-periods 2020-12-31,2021-12-31,2022-12-31,2023-12-31,2024-12-31 \
  --restore-codes-file workspace/derived/supply-expansion/codes.txt
```

不传`--restore-codes-file`则只强制选定报告期归档重放，不构造缺口；原来的单包基准入口不变。输出JSON记录输入哈希、证券清单、计数、物化耗时和副本体积，详细SQL分析写stderr，峰值RSS使用`/usr/bin/time -v`记录。

## 失败结果及边界

空冲突计划跳过、宽行标量比较、哈希预筛、包间checkpoint、临时列裁剪及索引查找分段均未同时带来足够的内存和速度改善，全部撤回。单次试验峰值仍约854—915MiB，其中checkpoint及索引分段反而增加耗时；不通过提高限额或缩小输入掩盖。运行记录与清理凭据保存在`workspace/derived/materialize-memory/`，动态产物不进入Git。

本轮只证明固定数据库背景下指定年度补录与重放的改进，不是全历史、全市场内存上界。[后续40家供给扩展](supply-expansion-next.md)已完成；真实流程暴露编排进程占用带来的回收限速，继续监控整个服务组并保留拒绝分母；金融与多市场仍不在当前主线。
