# 历史研发队列与完整利润行解耦

2026-09-28修复的是原生数据适配缺口，不是研发资本化公式或公司估值政策。

## 根因和处理

`SQLite → fetch_valuation_company → _db_record_to_company_input → M3历史序列`此前只保留同时具备收入和EBIT的年度行。历史研发摊销也从这组行取队列，因此某年度即使已有研发费用，只要该年收入或政策调整后的EBIT缺项，研发也会被一并丢弃。

当前完整财务行仍须具备收入/EBIT。被排除年份的有效研发费用单独进入完整输入中的`historical_research_expenses`（财年→报告币种金额，原生SQLite为百万单位）。该字段只承载已有数值，不进行PDF取值或源零推断；不允许与完整财务年度重复，也拒绝负数和非有限金额。手工输入未提供补充时保持缺项。

M3按真实财年建立研发队列，合并完整财务行与这些独立观测；同一年度只存在一个值。资产仍需要n个年度、摊销需要n+1个年度，只用当年及更早观测。缺队列保留NULL，不压缩年度、不缩短寿命，不为补研发创造利润、收入或资本行。审阅输出同时列出完整财务年度和补充研发年度。当前TTM及调整输入不受此历史通道影响。

这是后端数据契约扩展，网页未修改。已有冻结报告依原提交复验；使用新补充观测时保存新的完整输入和运行时标识，旧输入没有观测不冒充已补齐。基础选择器的同口径检查也包含该字段。

## 原12家复验

沿用[统一方法](native-uniform-scenarios.md)的名单、SQLite、参考、报告期及截止，未改规则或补新来源。8080已加载修复后代码。

- 安克模型历史调整利润率：2025、2024从NULL恢复为13.8435%、13.5093%；2017—2023研发观测被保留，但2023及更早政策口径EBIT仍缺，不混用SQLite原始EBIT补入。
- 苏泊尔：2025从NULL恢复为11.2097%；2024仍缺更早研发队列，不补零。
- 其余7家可计算基线的公司无变化；3家财务阻断继续保留。
- 9份基线及43份成功候选/场景的DCF与最终值，和前轮逐字段完全相同；同一12家仍是6家21场景、3家选择拒绝、3家财务阻断。全部成功请求与真实8080 API核验，并完成目录重放。

这些恢复的是**模型实际输入口径的历史利润率**，不同于独立标准报表历史。两者没有混合，也没有把历史证据增加称为估值准确率提升。研发系数及股权/股本没有改变。

## 剩余通用缺口

五年研发摊销下，当前2025基年三年利润目标需2023—2025利润及2018—2025研发；诊断2025预测时，起点2024三年目标需要2022—2024利润及2017—2024研发；诊断2024则还需要2016年研发。当前估值具备六年研发不代表历史检验具备这些更长队列。

原样本中多家公司2018年研发在SQLite为`missing_standard_fact`；这仅证明当前标准供给缺项，不能称TDX没有。本地缓存已确认有2017、2018年年报ZIP，2016年包未在当前缓存中找到，不推断上游不存在。安克/苏泊尔另有原生代理EBIT早期组成不足：原标准EBIT存在，也不等于已经完成非经营收益剔除。两类必须分别补链，不能用未调整利润填政策历史。

因此调整利润四规则共同可评分配对仍为0/24；收入诊断保持14/24。后续应批量核查2016—2018研发的本地源存在性、披露关联及标准供给，并核查代理EBIT早期缺项组成；新来源或新语义要按现有审批规则处理，不继续逐公司调参数。

## 验证和证据

59项相关Python回归通过，覆盖不完整利润行仍保留研发、n+1队列手算、删一年即NULL、重复/负数/NaN拒绝、未来观测不进入过去、当前DCF不变；Go全套（缓存）及命令构建通过。扩展引擎及集成回归236项通过、4项因既有TEST_DATA文件缺失跳过，峰值约790MiB；Python全套未重跑，2条既有依赖弃用警告保留。测试与真实批次分别在已核验1GiB硬限额的独立systemd服务中串行运行。

证据位于`workspace/derived/research-cohort-bridge/`：`batch/`、`review.json`、`comparison.json`及服务日志。比较工具首轮误读取已拒绝候选的不存在结果文件，已按状态先核对，再比较成功结果；保留该失败说明。主库及SQLite未修改，无依赖变更。
