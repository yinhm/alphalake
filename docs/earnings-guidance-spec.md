# 公司业绩预告数据链 spec

状态：2026-10-09已实现来源解析、schema58预告宽表、手工同步、只读JSON查询、唯一公告身份关联及离线重放。独立版本化证据包、权威修订裁决、正式结果比较及故事绑定尚未实现，下文明确区分。操作见[入库指南](guides/earnings-guidance.md)，实际数量与验收见[项目状态](implementation-status.md)。本轮不修改估值公式、默认参数或已发布SQLite。

## 1. 交付目标与边界

交付可批量刷新、查询、重放及追溯的**公司披露业绩预告**，供Agent和经营故事研究使用。这里的预告是公司的估计；“公司披露了某区间”可以核实，区间内的未来结果不能标为已实现财务事实。

第一版完成以下链路：

```text
东方财富结构化预告 ──→ 原始响应归档 ──→ 预告宽行观测 ──┐
巨潮公告目录／原文 ──→ 既有公告归档 ──→ 关联／修订证据 ─┤
已有TDX预告字段 ────→ 已有源包定位 ──→ 可比性核验候选 ─┘
                                      ↓
                        DuckDB主库中的来源独立记录
                                      ↓
                     只读JSON查询（已实现）／版本化证据包（待接入）
                                      ↓
                         Agent及人工经营故事研究
```

- 默认只对冻结范围内的沪深非金融公司发布预告上下文。混合市场原始响应完整保留；金融、北交所及身份未解析对象不计入发布分母；当前同步汇总仅给范围外合计，细分类别尚未输出，不计为“没有预告”。不开展多市场或金融模型。
- TDX仍是正式结构化财务主源。东财承担本模块的结构化预告供给，巨潮提供公告身份、原文及修订证据；各来源独立留痕，不改变正式财务的来源优先级。
- 预告不进入`fundamental.statement_snapshot`、标准财务事实、年度／季度／TTM财务行，也不填补正式EBIT、研发或现金流缺项。
- 本轮以数据侧采集、主库存储及只读CLI完成交付；独立版本化证据包另列后续，`valuation.sqlite`及原生估值API保持现有契约。没有预告不增加估值准入条件；采集预告不代表网页财务或估值已经更新。
- 本轮不引入参数自动选择、预告区间中点默认采用、概率分布、LLM预测、券商一致预期或新的估值策略。正式快报先分类、关联和归档，结构化快报金额接入另列后续范围。

## 2. 来源与已知证据

| 来源 | 第一版职责 | 真实验证与限制 |
|---|---|---|
| 东方财富 | 按报告期分页取得结构化预告；按来源指标归一化金额、同比及解释 | 公开网页请求无需Token，本轮成功返回2026-09-30预告。不是有稳定性承诺的正式开放API；需校验业务响应，不只看HTTP状态 |
| 巨潮 | 按公告窗口采集预告／修订目录，复用公告ID、身份解析和PDF归档 | 正确类别为`category_yjygjxz_szsh`，也含快报；关键词检索会混入业绩说明会。类别与标题须分别校验 |
| TDX | 复用完整目录及现有缓存，核对已定义预告字段与公告日期 | 现有目录为`not_reviewed`，预告目标期仍未闭合；源包报告期不能当预告目标期。没有新的生产预告采集器 |
| 交易所／Tushare | 后续来源提案 | 本轮不增加采集适配；交易所批量接口及Tushare权限未实测，不设未经验证的自动回退 |

东财访问入口为`https://datacenter-web.eastmoney.com/api/data/v1/get`，数据集为`RPT_PUBLIC_OP_NEWPREDICT`。请求使用`reportName`、`columns`、`filter`、`pageSize`、`pageNumber`及稳定排序字段；请求参数、HTTP状态、业务状态、页数／总数和原始字节一起留收据。证券字符串过滤与日期过滤的语法分别测试，禁止靠字符串拼接接收任意表达式。

本轮负向实测：证券字符串使用错误引号时，服务器返回HTTP200，但`success=false`且提示参数预处理错误。有效查询示例是`(SECURITY_CODE="300054")`，日期查询示例是`(REPORT_DATE='2026-09-30')`；两者分别已验证，组合请求仍须独立回归。业务失败不得转换成“公司没有预告”。

巨潮复用`/new/hisAnnouncement/query`，限定公告日期窗口。2026-09-01至10-09的类别小样返回16条候选，实际两页为10＋6条、公告ID无交集，但`totalpages`错误地返回1。该16条包括快报，不是有效预告数量或全市场覆盖率。

鼎龙股份交叉核对：东财记录的2026年前三季度归母净利润8.4—8.6亿元、扣非净利润7.8—8.0亿元，与[10月9日原公告](https://static.cninfo.com.cn/finalpage/2026-10-09/1225596682.PDF)四个区间端点一致。公告还单列第三季度收入、利润和业务原因；不能把前三季度区间当成第三季度单季。

原始调研请求、响应、失败及哈希收据保留在`workspace/derived/source-research/earnings-forecast/`。已选取小型必要样本固化为来源测试夹具；不把全部运行数据提交仓库。来源参见[东方财富预告页面](https://data.eastmoney.com/bbsj/yjyg.html)、[AKShare巨潮请求实现](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_disclosure_cninfo.py)、[TDX专业财务官方定义](https://help.tdx.com.cn/quant/docs/markdown/TdxQuant.md/mindoc-1h10m001ic888.html)。AKShare仅作接口参考，不新增依赖，不作为独立来源计数。

## 3. 期间、金额与范围

### 时间契约

| 字段 | 含义与要求 |
|---|---|
| `period_start`／`period_end` | 预告涉及的实际经营期间；来自明确源描述或原文。源报告截止日单独不足以推定开始日 |
| `period_basis` | `ytd`、`quarter`、`fiscal_year`或`unknown`；同一9月30日截止日可以分别对应前三季度累计和第三季度单季 |
| `announcement_date` | 来源标注的公告日期，可空；不由报告期或采集时间补造 |
| `announcement_time`／`announcement_precision` | 有可信时间戳才存真实时刻；仅日期或未知分别标明，不把午夜值当实际发布时间 |
| `first_observed_at` | 本系统首次取得该内容版本；重放和重复下载不得改写 |
| `ingest_run_id` | 本次采集与处理的来源收据；再取得时间由运行记录保存，不重复生成内容版本 |

当前上下文按“实际取得且语义合格”读取，公告日期缺失、未匹配巨潮及日期精度不足不单独阻断数值。日期异常留提示，不借此伪造时点。未知经营期间、单位、证券身份或已知数值冲突仍限制对应条目使用。

第一版不是严格历史PIT查询。导出明确记录信息截止和实际取得时间；后来获取的修订预告不宣称此前已被系统持有。将来历史查询沿[ADR022](decisions/022-financial-availability-and-disclosure.md)单独审定，不能反向增加当前数据门槛。

### 数值与披露契约

- 金额统一CNY元，每股指标CNY/股；同比单位`percent`，61.72表示61.72%，不是0.6172。JSON中的十进制数用字符串交付，带单位，避免二进制浮点二次舍入。
- 按指标分别判断单位，不能把每股收益乘万元，也不能因东财原文写“万元”就再次放大已按元返回的结构化金额。TDX万元倍率复用目录定义。
- 归母净利润、合并净利润、扣非净利润、营业收入、营业总收入分别命名并核对范围，不混称“利润”或“收入”；缺明确归母范围的扣非项目不能认证为归母扣非。
- 使用标准业务名；源指标码仅留在来源定位中。不以源编号作为查询参数、业务列或默认输出。
- 亏损和明确零保留；NULL、未列报、仅描述方向、仅单侧限额分别保留。默认不以零替代缺项，也不按所有预告字段共享零值规则。
- 本轮支持`interval`、`lower_bound`、`upper_bound`、`qualitative`和`missing`表示形式；未采用源平均值字段，没有把中点写成独立点预测。独立点值须在未来来源契约审核后接入。
- 区间端点应满足下限≤上限。源负数端点顺序与该约束矛盾时保留原始证据和待解析状态，不能静默取绝对值、交换或翻符号。同比与亏损金额符号也不能相互替代。
- 区间中点不是公司给出的点预测；同比区间不自动还原金额。还原至少需要同范围基数、增长定义与可比性，本版不自动实现。
- 多指标预告可以部分有效。一个未知指标或坏区间不清空该公告其他合格指标，不连带拒绝正式财务。
- 解释文字、约数及业务计划原样保留其性质。原文中额外收入、单季值和经营分量先作证据定位，不另建全公司PDF数值主源。

### 第一期指标范围

本轮接通四类：`forecast_parent_net_income`、`forecast_adjusted_net_income`、`forecast_eps`、`forecast_revenue`及其区间、同比与明确比较基数。营业收入已用301689真实响应及其中万元文本交叉核对元单位。源标签仅“每股收益”，不能认证为基本或稀释EPS；扣非和收入未明示归属范围时保留`unspecified`。未明确归母的“净利润”不并入归母列，营业总收入仍未接通。其他源指标原始留存并诊断，不猜语义。

预告字段目录复用现有标准命名和单位依据，新增东财映射与审核状态；TDX预告分组的`future_or_unresolved`不作为正式报表期间。两种源指标映射独立，不另造一套业务编号词典，也不把东财核验结果当成TDX源零或目标期已通过。

## 4. 主库存储：两张新表，复用既有治理

两张表及当前视图已落为正式DDL，当前schema58。旧schema57通过显式一次性升级，在事务内比较原表行数及聚合内容签名，不重算财务；没有旧schema运行时分支。

### `fundamental.earnings_guidance_observation`

一行是**一个来源、证券、经营期间、公告候选的内容版本**。金额采用固定业务列的宽行，不建逐字段源长表或BLOB层。

| 字段组 | 必需内容 |
|---|---|
| 来源身份 | `observation_id`、`source`、来源事件键、`instrument_id`可空、源证券标识、身份解析状态 |
| 类型与期间 | `guidance_kind`（forecast／preliminary／other）、经营起止、期间类型、各指标单位与归属范围 |
| 内容版本 | `content_hash`、解析／归一化版本、`first_observed_at`、运行ID；hash排除运行时间、页顺序和数据库序列 |
| 披露证据 | 公告日期及精度、可空`filing_id`、标题、预告类型、来源正文、变动原因、来源最新版提示 |
| 指标宽列 | 按标准名存上下限、同比及明确比较基数；配套各指标表示形式和语义状态，所有数值允许NULL |
| 原始定位 | `source_refs`只保存归档ID和原始行／文本位置；一个公告的指标跨页时引用全部相关页，不复制原始金额或哈希 |

业务金额使用`DECIMAL(38,10)`；超过合法精度或非有限数显式诊断。原始JSON用`json.Decoder.UseNumber`等已有标准库能力读取，不先经过float64。TDX保留其float32源精度，不用PDF或东财小数修补。

东财没有本轮已验证的独立公告ID：来源事件候选键由明确证券、经营期间、公告日期和预告／快报类别构成；预增、预亏等属于各指标，不能据此拆散同一公告，不能冒充交易所公告身份。同一候选键下重复指标冲突或可能含多份同日预告时保持歧义；完整原始行保留，禁止按行序挑一个。内容变化形成新观测版本；未变内容仅复用已有版本和取得收据。

观测ID由来源、事件候选键、规范化内容哈希和归一化版本确定，联合唯一约束锁定幂等；同一源内容的重复获取不产生新ID。规范化内容包含期间、范围、指标表示形式与数值、披露说明，不含页码、行序、归档路径或本次运行时间。来源定位独立登记；身份关联和审核关系变化不重写原观测。候选键不能唯一分组时先保留歧义，禁止靠内容哈希为同日公告推定先后。

### `fundamental.earnings_guidance_relation`

保留跨来源关联及修订／撤销的审核事件，不复制观测金额。记录关系ID、起止观测ID、关系种类、依据、证据引用、规则版本／审核人、记录时间，以及撤销所指向的前序关系。

关系种类包括`same_disclosure`、`supersedes`、`withdraws`、`conflicts`。同一声明的来源关联、声明被正式更正及审核关系被撤销是不同事件，不能都解释为公司撤回预告。规则或人工审核只能改变关系与消费状态，不能修改原观测。本轮自动写入仅限唯一身份关联；其他关系已提供有据写入与撤销的存储函数及回归，尚无自动权威修订识别或人工审核CLI。

复用`meta.artifact`、`meta.ingest_run`、`meta.checkpoint`及必要的`meta.dataset_release`记录归档、运行、完整源版本和处理窗口；公告／PDF继续进入`fundamental.filing`及`filing_document`。预告在既有定期报告分类器中仍保持`unknown/other`，目标期存新表，不让`EligiblePITAnchor`把预告当成正式报表。预告分类独立于定期报告分类，无需扩大正式事实锚点枚举。

只读视图`fundamental.current_earnings_guidance`按来源独立输出当前完整源观测及状态。全市场查询先限定证券、经营期间和所需标准列，再批量读取；没有每家公司启动进程、逐字段写入或第二权威库。

“当前源内容”依据已完成发布的来源／窗口收据及其观测关联确定，不按最大抓取时间、公告ID或哈希选一行。收据保留该版本的归档页与观测ID，支持离线重建；来源版本切换与相应观测同事务提交。离线重放旧收据不能推进在线当前版本；窗口不相交的成功发布不能替换其他窗口。来源缺少明确先后关系时并列返回候选并标歧义，不自动选一个“最新预告”。

## 5. 关联、修订与当前状态

本轮已交付第1–4、6项及有据关系的生命周期查询；第5、7–9项中的自动权威修订链和正式结果比较属于后续要求，不冒称已实现。

1. 先解析时态证券身份与经营期间。公司名称仅作核对，不据名称、集团关系或当前代码前缀猜身份。
2. 跨来源公告关联要求同发行人／证券证据、同经营期间和兼容指标范围。有唯一合格公告候选才关联；同日多份不能按公告ID、哈希或下载顺序裁决。
3. 目录唯一关联只说明文档身份匹配，不等于每个金额已核验。只有完成期间、单位、范围及原文定位核对，才对相应指标标`verified`；无需为所有公司逐份人工审批才能读取合格结构化来源。
4. 东财`IS_LATEST`仅保留为来源提示。可以报告该来源当前版本，但不能只据此宣称权威修订链已闭合。
5. 明确较晚披露的同口径来源观测与明确“更正／修正前后”的官方关系分别记录。无法确认前序的修正保留待关联；不自动制造`supersedes`。
6. 最新合格响应明确某指标改为NULL时，当前版本保留缺项，不能从旧版逐格填回；来源获取失败则保留上次可信版本并标陈旧，不用失败响应替换它。
7. 已知官方更正晚于结构化记录时标`stale_after_official_revision`。保留旧区间供追溯，不把它称最新；不从PDF静默覆盖其数值。
8. 公司明确撤回预告才记录`withdraws`。从网站列表消失、空响应或后续正式财报到来均不证明撤回。
9. 正式同期间、同字段财务可用后，标记`actual_available`并引用正式记录；预告仍保留，不替换或删除实际值。缺可比范围时不强行计算预测误差。

独立状态维度：身份（resolved／pending／out_of_scope）、语义（valid／partial／unresolved）、核验（unlinked／linked／verified／conflicting）、生命周期（current／superseded／withdrawn／unresolved）、正式结果（actual_available／not_available／not_comparable）。正式结果可用与预告曾被修正或撤回可以同时成立。不把这些压成一个“ready”：有效来源可用、原文已核验和当前最新是不同结论。

已知冲突、修订未跟进及期间歧义限制对应预告的采用；查询仍返回各版本和原因。不会删除公司正式财务、旧预告证据或已批准显式条件。

## 6. 手工刷新、缓存与原子发布

- 每次显式指定预告报告期、公告窗口及证券范围，在运行锁内冻结范围及主库版本。第一轮针对2026-09-30，巨潮公告窗口覆盖本年到实际刷新日；东财按报告期取当前全部预告，公告窗口参数不是东财历史截断条件，不默认扩采多年历史；其他时期由用户显式指定。
- 东财按报告期批量分页；巨潮按有界日期窗口批量采集，再关联到冻结证券范围。只为命中的预告／修订下载原文，不每家公司循环启动目录进程或把说明会全部下载。
- 复用HTTP超时、有限重试、限速和响应大小限制；东财同时检查HTTP与`success/result`，区分明确成功空集、业务错误、结构改变和请求失败。不能将null结果一律当空集合。
- 分页按记录总数、实际页长度及有效键推进核验；保存每页收据、去重键和跨页冲突。`totalpages`不能单独终止循环；检测重复整页、重叠漏行、异常空尾页和安全上限。
- 巨潮每页30条，使用已实测的默认排序，避免显式时间排序的同日不稳定；从既有90日窗口开始；数量变化、重叠或漏行时复用既有二分日期窗口规则，最小一天，仍不完整则失败。成功叶窗口及全部页ID随父窗口收据保存，后续在线复用划分、离线按同一页集合核验；失败父页只归档，不拼入完整版本。东财数量变化或重叠拒绝本次源版本，不套用巨潮日期拆分。源无快照令牌，不宣称网络分页取得了原子上游快照；记录扫描起止及一致性限制。这与TDX禁止自建下载切片是不同操作。
- 预告是会更新的信息。在线刷新不能因已有缓存就永久跳过源检查，也不能将正式财务gpcw的季节缓存规则照搬给预告。离线模式只重放已完整取得的归档版本，明确标`archived_snapshot_not_latest`；损坏归档拒绝。
- 先归档原始页，再解析暂存。每个来源／窗口完整的观测、诊断、源版本和完成检查点同事务发布；不完整页面保留为原始证据，不将其拼入“当前完整版本”。
- 结构化来源、公告目录和PDF补采分别报告完成情况。巨潮或PDF失败不阻断已合格东财区间，但综合运行标partial并列明失败；不能反过来把目录完成称原文齐备。
- 语义待解析或范围外记录属于已处理且有诊断的数据，不等于网络采集失败。失败范围不得推进检查点，已成功独立窗口可保留其真实完成记录。
- 空集只说明该来源／查询范围没有取得预告，状态为`no_disclosure_observed`；不能称公司不存在预告、预测为零或经营没有变化。

归档位置：新东财原始页放`workspace/eastmoney/`，按`earnings-guidance-<报告期>-p<页码>-<内容摘要>.json`可识别命名；复用`artifact.Persist`的完整哈希核验和`meta.artifact`登记，增加该来源的平铺路径规则，不另建缓存数据库或逐公司收据树。巨潮继续使用既有`workspace/cninfo/`归档；TDX读取现有`tdx-cache/`与血缘归档，不再下载第二组包。运行、锁及导出放`workspace/derived/earnings-guidance/`，原始响应不塞进主库BLOB。

## 7. 查询与导出契约

已实现两个采集／查询命令及显式迁移；独立导出仍待接入：

| 命令 | 输入与输出 |
|---|---|
| `sync-earnings-guidance` | 主库、报告期、公告起止和范围文件；默认同步东财与巨潮，生成来源分开的运行收据；`--offline`只重放已归档的完整请求集合 |
| `earnings-guidance` | 证券集合、经营期间；输出当前来源候选的宽行JSON、关联／生命周期、失败陈旧状态及无观测公司；历史版本保存在表内，没有历史查询CLI |
| `upgrade-earnings-guidance` | 在未发布的schema57副本上显式升到58，核对既有表后才提交 |
| `export-earnings-guidance`（未实现） | 后续拟从同一主库及冻结范围，输出不可变`earnings-guidance-context-v1` JSON和摘要；绑定内容签名、范围、源版本、信息截止、实际取得时间及来源文件定位 |

范围文件显式列出标准ticker，附范围来源及内容哈希；默认发布不含北交所和金融，要求保留完整输入分母。未知／重复ticker拒绝，不通过证券名称猜测。全量范围由主库已解析、已分类非金融证券生成，与固定100家回归名单分别记录。

查询保留每家公司，没有入库观测返回`no_observation_stored`；这不证明各来源采集已完成。采集状态以同步收据为准，独立导出仍待接入。数值为十进制字符串，单位明确；预告类型、期间类型、来源、核验及限制随值交付。字段缺失用NULL和原因表达；JSON不默认展示源编号。

一个消费示例（数字来自本轮实测，结构为拟议契约）：

```json
{
  "ticker": "SZSE:300054",
  "data_kind": "company_earnings_guidance",
  "guidance_kind": "forecast",
  "period_start": "2026-01-01",
  "period_end": "2026-09-30",
  "period_basis": "ytd",
  "announcement_date": "2026-10-09",
  "source": "eastmoney",
  "metrics": {
    "forecast_parent_net_income": {
      "representation": "interval",
      "lower": "840000000",
      "upper": "860000000",
      "unit": "CNY"
    }
  },
  "verification": "verified",
  "is_reported_actual": false
}
```

当前查询为`earnings-guidance-context-v1`的宽行JSON：数值为十进制字符串，包含观测ID、源版本、原始行定位、源完整窗口、取得时间及状态；示例中的嵌套`metrics`和`verified`不是当前CLI格式或核验承诺。独立不可变导出还须含观测ID、source／guidance版本、原始定位、关联依据、核验所覆盖指标和状态原因；示例不是已入库记录，也不代表所有东财金额已核验。

**当前目录期间限制（10月14日实测）：** 巨潮v2分类器把“第三季度”标题推为单季，但国网信通、深圳燃气、粤桂股份、国机精工的10月13日原文明确是1～9月；源杰同日原文确为7～9月。因此目录`period_basis`在这些情况下尚未获正文确认，不能直接作为单季事实；金额与期间解读以各自原文／明确结构化范围为准，不把两来源身份关联当作正文核验。通用修复及旧观测重建待办见[维护记录](history/data-maintenance-20261014.md#新发现的目录期间限制)，本轮未改变解析代码。

第一版不自动差分累计预告、构造“预告TTM”或还原EBIT。未来若按`前三季度预告－已披露半年`推单季，必须验证证券、范围、单位和比较口径，并保留区间及两个组成，标为预告派生，不回写已披露季度。不能由净利润区间直接推出经营利润率。

## 8. 现有消费接口与后续边界

正式财务继续沿[估值数据契约](valuation/data-contract.md)及[当前SQLite消费契约](valuation/sqlite-input-snapshot-spec.md)运行。预告证据独立于财务消费快照，不需要新增估值SQLite、修改现有SQLite版本或另建网页。

尚未交付独立内容签名及完整归档哈希清单导出；现有只读JSON可用于人工研究，但不冒称可独立移动的版本化证据包。

当前`tools.narrative_valuation.Evidence.kind`只有`snapshot_baseline/reported_fact/company_plan/reference/policy_proxy/research_judgment`，没有专门的公司业绩预告类别；报告的信息截止沿SQLite元数据，尚无独立新增证据截止。不能为接通而把预告数值标成`reported_fact`，也不能仅改名字就把未经审计估计认证成已实现事实。

因此第一版交付止于可检索的预告上下文与证据文件，供Agent和人工研究核对。**自动注册故事证据、显示不同的证据截止、预告派生及参数采用是后续独立接入项**：须先明确`company_guidance`证据类别、财务基期／新证据截止分别展示及既有调用方影响，再扩展必要的叙事输入／输出契约；不改DCF或默认政策。相关未实现事项记入[valuation TODO](../valuation/TODO.md)，不把本spec写成已完成故事接通。

正式预告可以支持或反驳短期经营判断，但不自动支持十年增长曲线。即使归母净利润区间已核验，未来EBIT、税率、研发、资本需求和WACC仍要各自有依据。公司预告、研究者采用的条件、模型现金结果分别留版本。

## 10. 验收与停止条件

### 数据正确性与恢复

1. 必须覆盖已实测的鼎龙两项区间、每股收益、巨潮预告／自愿预告／快报／说明会分类，以及真实亏损、零、单侧或纯定性预告样本；未找到的类别明确未验，不用mock冒充真实覆盖。
2. 核对元／万元／每股、累计／单季、归母／非归母、营业收入／营业总收入；篡改单位、期间、身份或区间端点须被拒绝或降为待解析，合格其他指标保留。
3. 锁定HTTP200业务失败、无效类别导致未筛选、`totalpages=1`而实际两页、重复页／重叠漏行／页间源变化及成功空集。空查询不关闭旧有效预告或推进失败检查点。
4. 同一期多指标跨页合成一条宽行；源行顺序变化不产生内容版本。相同输入重放新增观测／关系为0，保留首次取得；离线重放HTTP请求为0。
5. 两个内容版本、明确修正、同日歧义、关系撤销和最新版本NULL均可复验；旧证据留存，不能从旧字段凑出新版本。
6. 巨潮／PDF失败时东财合格观测可读且运行partial；东财失败时原版标陈旧；已知冲突仅限制对应预告。重开库仍保留失败记录及关系事件。
7. 正式财务、SQLite、参考及既有显式估值输入不变。主库新增预告本身不触发财务物化，不生成新的网页默认条件值。

### 范围、速度与交付

- 冻结跨类型小样验证规则，再对**完整选定范围**运行；沪深300／固定100家仅回归，不代替全市场分母。若源不提供预告，不强求所有证券都有区间。
- 分别报：范围证券数、实际有观测证券数、原始指标行数、预告观测版本数、可用指标数、公告关联／原文核验数、歧义、范围外、无观测、来源失败及陈旧版本。目录数量和指标行数不当公司数量。
- 比较同范围全量初次导入、增量修订、幂等重放及批量导出，记录网络／解析／入库／导出分项耗时、归档与库增量、峰值内存、缓存及资源配置。沿[性能规则](guides/financial-storage-redesign-20260925.md)，不增加固定历史秒数门槛。
- 大范围验收在已核验1GiB上限的独立systemd服务串行运行，显式`GOPATH/GOCACHE`；测试不继承真实主库workspace。元数据共享、宽行批量处理，不靠多进程或扩大内存掩盖结构问题。
- 日常默认回归使用小型离线夹具；真实DuckDB／跨语言链仅显式full或CI，新增网络烟测显式运行。源／契约变更补相应全局范围，不增加每次开发的全市场测试。
- 在未发布副本升级并验证原财务内容不变，重开验收后切换唯一主库；回滚副本依既有规则清理。不会仅为预告链重建20百万个财务值。
- 源变更、范围歧义或PDF无法读时交付具体拒绝和原因，不临时换来源、OCR或个股硬编码。本轮以“选定范围获取状态可追踪、主库持久化及可重放查询”作为入库结束条件；独立证据导出另列待办；经济采用和预测准确性单列。

## 11. 实施顺序

1. **来源契约**：固化本轮原始小样和失败，补亏损／零／修订样本；接通东财预告解析及巨潮正确分类，完成离线正负回归。
2. **主库闭合**：两表与迁移、幂等批量写入、跨来源关联和修订／撤销、来源分开的完成收据，先小样再完整选定范围。
3. **数据交付**：采集／查询／升级CLI、离线重建与完整范围统计；独立证据包仍待接入；验收数值／范围／版本／速度并更新当前状态。TDX能比对的字段单列审核，不阻塞已可用东财链。

上述三步是数据链实现范围。后续故事证据类型与截止接入、预告派生、经营参数采用另行提出具体方案；本设计不授权自动改预测或对沪深300重新估值。

### 季度标签的期间边界（v3）

`cninfo-guidance-v3`及`eastmoney-earnings-guidance-v3`不再把第二／三／四季度标签独立认证为单季。第一季度与年初累计相同，明确前三季度、半年、全年及明确月份范围沿原定义；只有截止日或季度标题时，`period_start=NULL`、`period_basis=unknown`，巨潮观测为`partial`并留诊断。标题识别的截止期仍保留，公告不因开始日未知被丢弃；金额、身份及原文独立保存，不从另一来源的期间替其作主。

真实反例：国网信通2026第三季度快报PDF p.2明确1–9月，源杰股份同季预告PDF p.1明确7月1日–9月30日，来源URL、哈希、页码及最短原文在[固定回归证据](../internal/source/cninfo/testdata/guidance/operating-period-evidence.json)。本修复不宣称已建设通用PDF经营期间解析器，不把人工核验推广成全量正文审核。

当前归档按既有完整窗口及同范围`--offline`重建v3观测与关联，再重放核验；旧v2观测和源页保留，不原地修改错误期间或伪造新取得。跨解释版本的新ID按实际引用归档记录首次时间，不无证据继承旧ID的更早时间；来源收据取得时点及同版重放保持不变。版本重建产生的新观测ID不是新公司公告，也不推进来源取得时间。未知期间不得建立累计／单季同一披露关系，仍可查询原公告及独立合格结构化金额。
