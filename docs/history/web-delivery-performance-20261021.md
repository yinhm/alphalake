# 网页加载与跨版本发布修复

2026-10-21针对研究等页面再次变慢，检查真实8080、前置反向代理、浏览器请求与服务日志。本轮修复的是前端加载、HTTP传输和软件发布；不改变财务、研究内容、估值公式或默认条件。主要代码为`2723f4f`，最终再将轻量研究／选股列表改为直接加载。

## 原因与处理

此前[目录缓存](research-catalog-performance-20261021.md)仍有效，暖首页约50—105毫秒、证券搜索约48毫秒、目录正文约12毫秒。仅测试本机API不足以解释实际网页体验，继续追踪发现：

1. 入口静态引入所有估值页面、知识页和正文排版依赖；主JS为863,011字节，研究首页下载了无关模块。重页面改用React既有按需加载；研究／选股的小列表保留直接引入，Markdown／KaTeX仅打开正文时加载。最终主JS为268,797字节，实际gzip传输82,692字节。
2. 应用及当前代理链路没有对JS／JSON压缩；知识索引325KB、研究列表21KB均原样传输。使用已安装的ASGI gzip中间件，HTML明确`no-store`，带散列资源长期缓存，缺失资源404不缓存。实际8080及本地反向代理入口均核验通过，不依赖代理另配压缩。
3. 旧发布流程整目录替换dist后删除旧资源，日志出现旧标签页请求宏观页面JS返回404；React重试不能清除已拒绝的懒加载模块。先恢复仍被引用的5份旧资源，再引入候选清单验证和发布锁，先追加完整新资源，最后原子切换HTML；保留旧散列资源，失败恢复旧HTML。资源加载失败改为用户主动刷新页面版本，避免自动刷新丢失输入。

`npm run build`现只生成`workspace/derived/frontend-candidate`，不会清空正在服务的目录；经回归后用`tools.publish_frontend`发布，操作与回滚见[手册](../guides/system-delivery.md#前端构建与发布)。不增加依赖、第二目录数据库或估值计算路径。

## 同范围实测

同机Chromium、1440×1000，每条路径新建空浏览器缓存上下文；后端缓存已暖，不清操作系统页缓存。限速为192,000字节／秒（约1.5Mbps）、往返延迟100毫秒。可见时间从导航开始到实际目录卡、正文或表格可见，资源字节包含浏览器记录的传输开销；单次观测不是p95或公网承诺。

限速首页可见时间下降约80.5%，传输下降约85.3%；本机列表接近原水平，正文首次加载增加约0.27—0.39秒以换取首页不下载排版依赖，长正文仍有约0.5秒渲染长任务。保留这些成本，不将整体传输减少说成每个冷页面都更快。全部页面本次实际测量无脚本错误或请求失败。

将所有页面都懒加载时，本机首页曾变成1,037ms；仅对首次渲染增加`startTransition`没有改善，已撤销。最终直接加载两个轻量列表，限速首页从该候选的1,800ms进一步降至1,378ms，没有因此恢复重页面或正文排版的静态依赖。

压缩前后解码JSON签名一致：研究首页21,757→2,926字节、当前目录42,233→9,881、长正文379,940→58,770、知识索引325,226→79,851、宏观257,978→22,707、选股50行92,057→14,760；左边是原响应体，右边是gzip响应体，不含浏览器传输开销。首页、搜索、两份正文、KB、宏观和选股共七条接口内容不变。
