## 唯一数值链路

`TDX ZIP → 临时解析与语义校验 → 标准财务宽表 → 查询/派生/导出`。

- `fundamental.source_record` 保存原归档ID、原始行号、证券代码、期间、字段数量及解析身份，不保存源数值、float32位数组或BLOB。
- `fundamental.statement_snapshot` 每个来源记录一行，346个通用标准列，金额为`DECIMAL(38,10)`；空值不冒充零。
- `statement_field` 固化已发布的映射语义；`statement_field_run` 只记录后续改变字段的运行血缘，未变字段沿用原血缘。
- `statement_rejection` 按记录与规则归并当前拒绝字段；`materialization_state` 保存输入签名及计数，未变包跳过解码和数值写入。
- 原始float32核验从哈希验证后的ZIP重新读取。身份修正、失效删除、单位/期间审核及原文补充继续分别留痕，不恢复源EAV或旧表别名。

同步事务共同提交解析身份、轻量定位及完整性检查点。标准物化在映射不变时按包提交数值与签名；映射语义变更时，全部受影响包与新语义同事务发布，失败保持旧发布。源同步输出统计的是记录数，不再把一条记录的数百个字段计成数百条入库记录。TDX本地缓存与默认排除北交所的规则不变。

标准查询先限定证券及期间，再按记录主键取宽列并展开。TTM仍按标准期间规则计算；期末数不相加、缺期不填零。标准字段定义和逐公司原文核验分开，存储重建不会提高财务原文覆盖率。

## 原生SQLite数据产品

当前导出契约改为`alphalake-sqlite-v3`：一次只读事务批量导出，Python标准库流式写入SQLite。原网页17列结构及交互不变，11列有标准财务映射，另6类会计定义继续明确留空。

移除重复的逐期间估值JSON、TTM和三表JSON副本。SQLite保留原生公司/年度/季度宽表、目标所需标准事实、单元格缺项与来源证据及完整证券分母。全部346个标准字段仍通过DuckDB标准财务查询提供；SQLite不是主库的全字段复制品。

旧SQLite需显式重建，没有版本别名或静默降级。`ALPHALAKE_WORKSPACE`可明确指定不可变归档根；省略时使用DuckDB所在目录。移动数据库时必须一起保留相应归档。

### 性能口径

单线程，DuckDB预算512MiB，进程组硬上限1GiB、MemoryHigh896MiB、无交换。每项串行执行，未清除操作系统页缓存；“空表重算”指临时副本删除全部标准快照/拒绝/签名后重算，不表示磁盘冷缓存。测试副本每次结束均哈希记录并删除。

| 操作 | 三次耗时 | 中位数 / 最慢 |
|---|---|---|
| 从空标准表物化7,949,683值 | 56.41 / 55.45 / 55.99秒 | 55.99 / 56.41秒 |
| 标准物化无变化重放 | 2.85 / 2.61 / 2.69秒 | 2.69 / 2.85秒 |
| 安克全字段历史查询，同进程准备后读取 | 78.307 / 70.652 / 73.057毫秒 | 73.057 / 78.307毫秒 |
| 全市场SQLite导出 | 35.97 / 40.33 / 41.20秒 | 40.33 / 41.20秒 |

历史查询另有准备时间1.481毫秒、JSON398,885字节，不含从ZIP读取源位证据；不能替代冷启动CLI测量。纯迁移一次总计76.40秒，其中非财务治理复制及冷历史归档45.26秒、财务重建31.13秒。全量离线源同步一次4.97秒，带17项冲突的重放4.30/3.84秒，尚未达到设计中的3秒重放目标；冲突包必须重新核验，不能提前写成功检查点。单新包5秒目标与冷启动CLI1秒目标本轮未单独验收。这里证明的是当前范围实测，不声称所有规模下的极限速度。

主库由7,601,139,712字节缩至 282,341,376 字节（约 269.26 MiB），标准值反而增加。SQLite为611,233,792字节（约582.92MiB），显式缺项和逐格血缘占据空间。另保留旧标准血缘Parquet113,333,143字节及历史诊断Parquet462,117,606字节（合计约548.79MiB）；不能把归档转移当成删除，也不能用主库体积冒称所有数据总占用。旧备份逐表差集还保留31,167条独有身份解析状态，其他事实/诊断没有独有记录；该小型Parquet也在同一审计目录。原始ZIP、PDF、参考数据及冻结研究结果不删。

### 回归与运行边界

- 最终 `go test -p 1 ./...`、`go build -p 1 ./cmd/alphalake`、`go vet -p 1 ./...` 通过。覆盖失效删除/恢复、字段级血缘、映射更改跨包原子性、真实归档篡改拒绝、缺期/身份/市场边界及导出。显式北交所真实证据测试使用本机Python解释器执行通过。
- Python全套先得471通过、2失败、4跳过；两项失败为测试仍调用已删除旧参数，修正测试后相关5项全部通过。4项为既有外部工作簿缺失跳过；没有声称整套再次无skip通过。SQLite完整性、三家公司后端读取以及实际8080原请求拒绝另行验证。
- 调优期间DuckDB预算不足和一次独立进程内存高水位回收停滞均记录为失败/取消。仅终止该已核对的隔离进程，恢复其WAL并标记运行取消；未杀交互终端，未提高硬限额，未发生该服务OOM杀进程。最终使用DuckDB原生allocator释放阈值，避免跨包保留过高原生内存；不是靠反复重连。[官方配置说明](https://duckdb.org/docs/current/configuration/overview)。
- 源定位只存文件身份/行号，不存源值；ZIP不可缺失或被篡改。主库移动须同时保持归档根，或显式设置 `ALPHALAKE_WORKSPACE`。schema51只允许通过 `cmd/rebuild-financial-storage/` 一次性重建；当前查询不提供旧EAV表别名。
