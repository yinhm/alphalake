# 研究目录性能修复

2026-10-21按现有5,773份登记定位并修复`/research`首页、搜索与翻页延迟，关闭维护待办17。代码提交`83403e9`，已在原8080后端加载；前端、估值规则、财务输入及报告文件未改。

## 原因与修复

原目录每次请求调用5,773次完整登记解析，重复校验73,873个附件条目，并反复解析相同workspace路径。一次profile约998万次函数调用，主要耗在路径解析、Pydantic校验及附件路径验证；不是首屏读取了全部图表，也不是估值计算慢。

现在一次扫描目录，复用规范根路径；登记首次出现或变化时完整校验，将排序、检索及不含附件的轻量元数据存入有界进程缓存。未变化的条目不重复读JSON或校验附件，只有本页内容生成独立响应。每次请求仍检查文件状态，以规范路径、设备／inode、大小、纳秒mtime／ctime组成缓存键，不使用TTL、磁盘索引或第二数据库。

新增、删除、原子替换、原地修改及时生效；恢复原mtime也会因ctime变化重新校验。软链接根目录／公司目录／登记文件继续拒绝；坏登记显式返回诊断，不返回旧缓存。不同workspace隔离，调用方修改返回列表不会污染后续请求。正文、附件与下载不走目录缓存，仍实时执行原有路径及哈希拒绝。
