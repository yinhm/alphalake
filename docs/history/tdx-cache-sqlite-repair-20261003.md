# TDX缓存校验与SQLite证据去重

本轮修复2026-10-03的数据侧review四项问题；不修改财务映射、零值政策、估值公式、默认假设或页面。主库及16个引擎文件的原哈希作为验收基线，动态日志在`workspace/derived/tdx-data-fixes/`，修复前失败复现在`workspace/derived/tdx-data-review/`。

## 修复边界

| 问题 | 修复 | 回归 |
|---|---|---|
| offline以本地MD5替换预期MD5，未知修改可自证匹配 | 清单只筛选存在的文件，保留预期大小/MD5；直接核验缓存，只有匹配清单或已有同文件SHA-256/大小收据才可读 | CRC合法但金额由100改999的未登记ZIP拒绝；已登记旧缓存与新清单不一致仍可用，检查点保持实际旧MD5；无网络调用 |
| 文件名与包头报告期错位 | 共用`ParseDat`核对日期；`.dat`内部名字不作为报告期依据 | 六月文件/三月包头拒绝；合法日期及原有扩展名大小写规则保留 |
| 零原记录包可推进检查点 | 共用解析器拒绝`StockCount=0`，与北交所过滤后无发布记录区分 | 合法报告长度的空ZIP拒绝；重开后原值100、原检查点及失败运行仍在 |
| SQLite重复持久化完整逐字段来源 | v11共享`standard_records`，事实保存精确金额、单位、期间、范围、事实ID及记录引用；年/季/TTM保存组成引用；复合主键表使用`WITHOUT ROWID` | 恢复完整事实及原单元格证据；错证券/错期间或缺来源记录拒绝；v10须重导出 |

真实缓存中的2026Q3占位包原本就因非法报告长度而拒绝，不是本轮发现的有效长度空包缺陷；没有证据表明它已污染主库。34份缓存与清单不一致但有已登记历史SHA-256，是合法历史回退，不称损坏或上游最新。

公司行情和税率文档保留原结构；去重针对财务事实及年/季/TTM组成，缺项、审核零、拒绝分量和范围代理诊断未删除。财务宽表及原生请求不变，参考仍为v2；主库不迁移。契约与发布操作见[导出说明](../guides/valuation-sqlite-export.md#sqlite证据存储契约)及[接入spec](../valuation/data-contract.md)。
