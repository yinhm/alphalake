# 原生缺口的来源核对与补链

> 历史阶段记录；其中的“当前”、命令、库版本和待办以当时提交为准。现行入口见[文档索引](../README.md)，不要直接作为日常操作手册。

本轮沿用[原生覆盖基线](native-coverage.md)，只处理已分类沪深非金融企业；金融与行业待审保留在原报告，不加入本次根因分母。目标是确认已有数据链哪里没有接通，不扩大来源、不修改估值公式或前端。

## 可重复的来源维护工具

`cmd/audit-native-sources`读取同库覆盖报告，批量核对缺失研发年度的源记录、公告关联、标准值及拒绝原因；按归档包读一次，通过现有哈希/大小/ZIP解析校验，再核对源行的代码、期间、市场标记和字段数量。标准字段来自统一目录，不建立源编号白名单。数值仅置于独立`source_evidence`，不据此写标准事实。

同时输出非金融范围的TDX行情观测总数、最早/最晚交易日、报告期窗口内及信息截止前观测数量。窗口计数只帮助诊断，不复制或替代导出的完整行情准入规则。

在独立systemd服务、已核验1GiB硬限额下串行执行：

```bash
go build -o /tmp/alphalake-audit-native-sources ./cmd/audit-native-sources
/tmp/alphalake-audit-native-sources \
  --database workspace/alphalake.duckdb \
  --coverage workspace/derived/native-coverage/full.json \
  --output workspace/derived/native-source-audit/full.json
```

覆盖报告源库哈希须与当前库一致，库在审计前后也须不变；运行后已更新的主库不能拿旧覆盖报告重新审计。副本复验须显式设置`ALPHALAKE_WORKSPACE`指向同一原始证据根目录。输出不覆盖已有文件；契约`alphalake-native-source-audit-v1`保留覆盖报告哈希、报告期及信息截止。报告用于当前本地治理，不能证明历史系统时点，也不能把未入库说成上游缺数。

## 补采前确认的根因

源库、期间和截止与上轮基线相同，4,964家参考分类非金融企业：

- 4,867家既没有TDX行情观测，也没有对应的标准日线；另外97家有报告期附近观测。此范围的市值缺口首要原因是没有同步行情，不是股本公式或多股类价格问题。
- 缺失研发年度共19,702个公司×年度单元格。关联查询保留全部版本/重复记录，产出19,714行；不将行数当成独立缺项数。
- 对19,696条唯一源记录逐包哈希及源行核对：19,359条有可解码非零数值，337条为源零待审。源数值不是已审核标准事实。
- 关联结果中19,660行为pending（在源版本观测时间前无合格披露）、11行为同等级公告歧义、19行已关联、24行没有关联记录。已关联仍缺标准研发的原因须看拒绝规则，不能将所有缺项统称未采公告。
- 19,367行没有对应年度的本地年报目录记录、347行有目录。这是源版本行计数，不能直接相加推导公司完成数；无目录也不证明上游无公告。

结论：优先用既有TDX行情同步和CNINFO目录关联补通标准供给。招股书、源零及歧义审核仍有价值，但不是这些批量缺项的共同根因。
