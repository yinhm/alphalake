# 估值行情窗口同步

`sync-valuation-quotes`只取得原生估值实际消费的历史行情窗口。在线`publish_native_valuation`已改用此入口；完整日线同步仍由`sync-daily`/`sync-daily-all`负责，不改变其语义。

```bash
alphalake sync-valuation-quotes workspace/alphalake.duckdb \
  --symbols sh600004,sh600006,sh600008,sh600009,sh600010 \
  --period 2026-06-30
```

本机须在已核验MemoryMax的独立systemd服务中运行，与其他主库写入、大导出及全套测试串行。输出JSON包含运行号、公司数、写入观测数及失败清单；存在失败时退出非零，正常公司可以保留为partial运行，不伪造整批成功。

## 数据边界

- 窗口为报告日前14个自然日至报告日，含两端；仅允许中国当日前已结束的日期。日期范围与原生SQLite市值输入选择一致，不新增更宽松的行情门槛。
- 必须已有沪深人民币股票身份，分别核对报告日、当前和每根行情所属日；代码复用或身份不明拒绝。此入口不刷新全量证券主数据，身份缺项须另行补链。
- 复用上游SDK分页与既有hosts轮询、每次请求最多三节点。翻页到窗口下界即停止；SDK传输页可能仍包含窗口外及报告日后的行，入库前过滤。不是声称服务端只传输窗口内数据。
- 仅向既有`market.daily_observation`追加观测，运行dataset为`valuation_quote_window`。不写`market.ohlcv_daily`，不修改任何完整历史续传/重试检查点；否则窗口末日会错误成为全历史起始边界。
- 原生导出和精确日期行情查询接受完成/部分完成的窗口运行，并保留原有取得时间、运行结束时间及信息截止条件。失败、取消和未结束运行不作为可用报价。
- 空窗口、非法价格、重复日期、身份或来源不一致显式失败并记录诊断；不补前期价格、不填零。重复在线取得是新的观测证据，不宣称零写入重放。无需新增表、迁移或依赖。
