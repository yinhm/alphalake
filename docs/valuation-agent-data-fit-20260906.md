# Investment Valuation Agent 数据需求匹配调研

调研日期 2026-09-06。实际目录为 `workspace/Investment_Valuation_Agent`，本地提交 `c4b86e5`（`feat(ingest): standards-first segment resolver + currency verification`）；AlphaLake 对照 `35aafde`。只读目标源码与其 SQLite 种子库，没有修改目标项目、运行其服务或安装其依赖。

结论：AlphaLake 适合作为该项目 **A 股公司财务和行情的数据供给层**，但目前不能直接替换它的完整数据包，也不能仅改字段名就可靠估值。应保留我们的标准事实、时点和缺失纪律，通过有明确口径的适配层进入其估值引擎。行业/国家风险参考和预测假设仍需独立来源；茅台还存在目标模型无法原样表达的行业政策。

## 实际数据契约

目标的代码级入口是 `backend/engine/data_dictionary.py` 的 `CompanyValuationInput`，由 `backend/api/routes.py` 的 `POST /valuation`（应用路由前缀下为 `/api/valuation`）接收，再调用 `run_full_valuation`。公司财务在 `RawFinancials`，调整、宏观风险、行业、期权及预测假设分组输入。可以直接构造 JSON，不必模拟 Capital IQ Excel 公式或依赖 Windows COM。

Excel 备选入口是 `CIQ_Data`＋`_RowMap`，读 D 列已解析值。模板文档规定 11 个损益/现金流变量和 6 个余额变量，年度 FY-0…FY-10、季度 FQ-0…FQ-7；数据库路径则说明 10 个年度＋8 个季度。文档中的“最低可用”是至少两个年度的收入/EBIT，加市场、债务、权益、现金、税项、利息及日期。实际 Python 模型必填字段更少，很多缺值会被后续代码转成默认数；能通过数据类型校验不等于财务输入完整。

目标前端和 CIQ 数据库惯例是 **金额以报告币种百万元、股数以百万股**，每股价格不缩放，比例为小数。RawFinancials 没有强制缩放单位，因此导出适配必须明确这些单位。AlphaLake 的 CNY 元/股先按标准映射完成单位归一化，再各除以 1,000,000；不能对 FN439/FN581 再重复应用万元倍率。

## 公司财务字段对应

下表是字段语义匹配，不是所有公司和所有历史期已经有值。标准范围仍是 `provider_default`，样本对账不能把全市场范围无条件改写为合并报表。

| 目标输入 | AlphaLake 候选 | 判断与必要处理 |
| --- | --- | --- |
| `revenues` | FN230 单季营业收入；年度/TTM 查询 | 可派生供应，必须四季求和或使用标准窗口；不把年报包 FN230 当全年收入 |
| `ebit` | FN86 累计营业利润、FN231 单季营业利润及调整分量 | 有基础，无通用等价；中国营业利润中的投资、金融、补助等与目标 CIQ EBIT 不一定同口径 |
| `ebitda` | 经审核 EBIT＋折旧摊销 | 尚无独立标准映射；先统一 EBIT、折旧、使用权资产及投资性房地产范围 |
| `net_income` | FN232 归母净利润 | 可由季度/年度窗口提供，不用 FN233 扣非归母代替 |
| `interest_expense` | FN305 利息费用 | 有标准字段；累计转单季，核对是否包含租赁、金融业务和其他融资费用 |
| `d_a` | FN136、137、138、581 | 可构成已识别合计；投资性房地产等其他折旧须另审，零值歧义/缺季不能补零 |
| `capex` | FN114 现金购建长期资产付款 | 可提供；目标用正支出，不能换成投资现金流净额或自动当成维持性支出 |
| `operating_lease_expense` | 附注，现有租赁负债/ROU 折旧不是租金 | 未标准化；主要进入 AdjustmentInputs，不能把负债余额当租赁费用 |
| `r_and_d_expense` | 安克六年 PDF 历史等补充 | 尚无生产标准映射/全公司历史；原始包有字段不等于已审核 |
| `earnings_before_tax` | FN92 利润总额 | 名称相近，但目标 CIQ 映射实际为 EBT Excl Unusual Items，需明确是否剔除非常项目 |
| `total_tax_expense` | FN93 所得税费用 | 有标准字段；不是应交税费或所得税现金付款 |
| `cash_and_marketable_securities` | FN8、FN133 和已识别金融资产 | 部分；货币资金、现金等价物、短期投资不能互相等同或重复加总；财务公司受限资产不是自由现金 |
| `bv_equity` | FN72 总权益或 FN271 归母权益 | 两者均有；目标模板“股东权益”、CIQ“Total Equity”的范围需要锁定，尤其与少数股权桥接配合 |
| `bv_debt` | FN41、55、52、56、439 及到期分拆 | 可政策派生，不能直接取总负债；FN52 内含到期债券/租赁，注意重复扣除 |
| `shares_outstanding` | FN238 期末总股本 | 可提供期末源精度股数；模板混称稀释/加权股数，实际模型写 primary shares，必须统一为估值分母口径 |
| `cross_holdings` | FN25 长期股权投资及补充投资分类 | 部分；不是所有长期金融资产都属于同一类可加回投资 |
| `minority_interests` | FN69 少数股东权益 | 可提供账面值；目标桥接扣项不自动等于少数股权公允价值 |

引擎还使用模板核心清单之外的 `noncash_wc`、`change_in_noncash_wc`、`net_debt_issued`。AlphaLake 的两公司完全分类经营营运变动仍有缺口；净融资现金流不能替代净债务发行。不能为了让引擎算出历史 FCFF 就把这些缺口填为零。

## 历史长度与时点

当前标准链验收是两家公司 2025Q1—2026H1 六期，432 条标准事实，H1 合计 76/76 个已映射窗口完整。该分母不是目标完整数据包的分母。29 个后来加入的标准映射目前 `valid_from=2025-01-01`；原单季/股本目录允许更早日期，也不意味着旧包已归档和数值已验收。两家公司六年 PDF 历史只覆盖选定子集，不是十年全字段标准历史。

对目标的 H1 LTM 分支，K=2 至少需要 K+4=6 个季度，当前样本期数在形式上够；但它逐字段消费单季度值。TDX 的资本开支、税项、利息、折旧是累计，必须做季度差分；缺 Q1/Q3 时不能从年度/半年合计反推唯一季度分量。某些标准累计 TTM 已完整，不等于目标所需每个单季度也完整。

AlphaLake 以公告可用时点筛选版本，再生成报告期窗口；目标对象主要保存 fiscal year、最近年/季报期末和 FX 日期，没有等价的逐字段公告 ASOF、版本选择和缺期约束。目标种子库的公司级 `data_as_of` 也不能替代这些信息。适配时需要保留导出信息截止、财务期末、行情日期、源事实/公告身份及映射版本；报告期不是公告时间，不能把截至 9 月的半年报倒填成 6 月底已知。

## 目标缺失处理与我们原则的冲突

源码 `engine/ltm_calculator.py`：

- 季度列表长度足够时，单字段为 None 的季度不加入求和，相当于该季度贡献零，仍返回一个数值。
- 季度长度不足时，保留 FY0 流量，但继续用最新季度覆盖资产负债余额，可能混合时间口径。

本轮隔离执行该文件的原函数验证了两条路径：FY 收入 100、K=2，当前季度收入 `[20, None]`、上年对应 `[10,10]`，结果仍为 100；仅提供两个季度时，也保留收入 100，同时把债务从 FY 的 50 换成季末 99。仅用最小对象协议代替未安装的 Pydantic，未声称完整应用联调；探查脚本/结果在 `workspace/valuation-agent-research-20260906/`。

`engine/module_3_cashflow.py` 将缺 capex、DA、营运变动等取 `or 0.0`；`module_4_dcf.py` 将缺债务/现金/少数股权取零，缺股数取 1。`capiq_adapter.py` 对缺历史研发或租赁承诺也补零。前端存在 UnresolvedFieldsPanel，并不意味着这些计算路径都会阻断。接入前必须增加消费端完整性门控，或明确将某条结果标为不可计算；不能把下游默认值回写 AlphaLake。

## 非公司财务输入

| 需求 | 当前匹配情况 |
| --- | --- |
| 股价、市场权益、波动率/股息率 | A 股日线和公司行动有生产基础；需要同一估值时点的行情、股数、复权收益计算及质量检查，尚非现成全量估值输入接口 |
| Damodaran 行业 beta、D/E、ROIC、利润率、WACC 基准 | AlphaLake 没有此标准数据域；目标已有参考数据模块，可继续作为独立来源，需审核版本及适用地区 |
| 无风险利率、ERP/CRP、法定税率、债务利差/评级 | AlphaLake 本轮模型只有显式假设，不能当作市场观测供应；目标有参考/手工输入渠道 |
| 行业匹配 | TDX/申万行业不等于 Damodaran 行业，需要有版本的映射或人工确认 |
| 地理收入分布 | 没有全市场标准数据；目标经营地区 ERP 分支需要额外分部证据 |
| 租赁未来付款及期权 | 没有全市场到期阶梯、行权价、剩余期限、期权数量及波动率输入；不能用租赁负债或总股本代替 |
| 美股、港股及汇率 | 当前 AlphaLake 主线为 A 股，不是目标多交易所/多币种数据集的完整替代品；人民币 A 股首批可明确 FX=1，跨币种不能照搬 |

## 两家公司模型政策匹配

安克适合先做接口样本，但需要锁定 EBIT 调整、研发/租赁政策及转债处理。目标 M1 会把未来经营租赁付款资本化并加到债务；若输入已含表内租赁，再启用同样加回会重复计算。只有确实不重复的表外承诺才可进入该调整。原五年研发示例或已调整 EBIT 也不能再次重复资本化。

茅台不能原样搬过去：目标 M4 是合并单体 DCF，加现金/投资、减债务/少数股权；没有现成对应本样本“剔除财务公司全部账面块再按 51% PB 加回”的输入组。其 `reinvestment_lag_years` 实际截断在 0—3 年，全部再投资共用资本周转路径；我们茅台分开建模五年储酒和两年长期投入，单个 lag 参数无法保持同一政策。即使数据齐全，两套估值也不应被要求输出相同每股值。

## 建议的最小接入顺序

1. 先定义消费契约和门控：金额/股数缩放、证券身份、报告期与信息截止、原始/调整 EBIT、租赁处理、缺失状态及源身份。保留独立血缘清单；不要只沿用 CIQ 标签冒充数据源。
2. 以安克构造一个 JSON 对接样本：从标准事实取值，附注补充明确分开，行业/宏观参考由独立来源提供，预测假设显式输入。逐项验证边界后再运行目标引擎。
3. 解决 LTM 消费：要么提供完整、已验证的单季度序列，要么明确支持已计算 TTM 的基期输入；不能将 TTM 伪装成全年、再靠 K=0 隐藏二次旋转。
4. 随需求补历史：先满足两年最低完整口径，再扩到五/十年研发、季度折旧与其他关键字段。以公司×期间×必需字段定义分母，不用现有 38 映射或 68/158 样本取值比例声称目标完成率。
5. 茅台作为第二阶段政策兼容验收，先决定财务公司估值和提前储酒投入如何表达，再对照模型。不要为适应其默认模型去修改我们的标准事实。

本轮结果是源码、只读种子库及隔离函数探查的需求评估；未启动 API、未安装目标依赖、未运行其完整测试，也未实现适配器。目标工作区保持不变。

## 后续：安克实际模块验证

已增加[可复现的安克适配实验](../internal/ingest/testdata/anker-agent-adapter-2026/README.md)，在独立环境安装 Pydantic，实际调用目标 LTM、完整编排器及 M1/M2/M4。完整编排器仅用于缺失处理反例；有效预测使用显式 TTM 基期直接进入模块，未伪装成年报。实验逐年独立复算目标预测，并沿用 AlphaLake 股权桥接对照原模型。

已确认收入的六季度 LTM 转换可用，但资本开支缺少单季度输入时会错误保留 FY 值；历史营运变动缺失仍会生成 FCFF。目标预测的增长、利润率、税率、再投资政策也不同于原安克模型。正式接入需要显式 TTM 入口、共享计算入口的缺失门控和明确的预测/股权桥接政策。本实验不等于 API 接入完成，也不增加全市场财务完整率。
