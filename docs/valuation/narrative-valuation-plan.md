# 估值叙事：公司证据到原生估值的方案

状态：2026-10-08已在既有链路补沪深300经营报告证据，并修订300家故事：304条记录，216家主研究条件可计算，4家另保留旧恢复诊断，共220家有条件值；80家没有本轮任何值，原因与分母保留。未来百分比仍是未获定量认证的人工研究条件，不因报告归档而宣称准确预测。原生8080及保存输入／现金结果核验通过，详见[本轮记录](../history/csi300-company-narratives-20261008.md)。前版533条条件和12家试点冻结保留。DCF、网页默认和财务数据不变，未实现参数自动选择；短历史估计、金融及多市场不启动。

## 目标与架构

为不同公司写出可检验的经营解释，把每项主张连到证据、年度假设及现金后果。交付是可复用的研究与输入流程，最终由原生valuation计算；故事属于发行人的业务，股价与每股索取权在股权桥中另行处理。

主线：**公司事实与参考 → 经济特征 → 经营主张和反例 → 显式年度条件 → 原生API → 算术与经济审阅 → 版本化修订**。

达摩达兰的[叙事书籍说明](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/NNPreface.html)把故事、数字、可信程度和反馈连起来；[公司生命周期](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/CLC/CLCPreface.html)解释不同阶段为什么面对不同经营与估值问题。下文类型、记录格式、阶段和验收是本地设计，不冒称作者给出的统一分类或默认参数。

AlphaLake管理证据和显式假设，valuation消费现有`CompanyValuationInput`，KB负责教学。叙事不写入标准财务事实，知识面板不计算，不新增DCF引擎。先复用来源、typed输入、完整API及审阅器；第一阶段无需新增数据库表、语言模型依赖或前端表单。

## 如何为不同公司形成故事

先回答四组问题：

1. **生意与阶段**：客户为何付钱，收入怎样确认，业务是商业化、扩张、成熟还是收缩？上市时间和经营阶段分开。
2. **需求与竞争**：增长来自数量、价格、份额、新产品还是收购？谁可能夺走客户或利润？
3. **资源与时间**：已有产能能支持多少增长，新厂、研发和周转什么时候投入，多久产生收益？
4. **终点与存续**：较稳定状态为什么成立，优势能维持多久，有无期限和资金约束？

再按达摩达兰的三层检验提问：**可能（Possible）**——有没有违背市场容量、资源和会计约束？**可信（Plausible）**——公司的产品、竞争位置和执行能力能否支持这条路径？**较可能（Probable）**——与其他解释相比，目前证据为什么更支持它？三层不能互相替代，也不等于已经知道某故事的数值概率；没有依据就保留条件，不编造情景权重。

经营阶段、经济机制及存续条件可以叠加；申万用于发现同业，不直接给公司选择故事。单年亏损、最近同比和估值高低不决定类型。建议研究以下机制库，每类提供问题和证据清单，不预填统一百分比。

| 机制 | 可检验的故事主张 | 应量化的变量 | 最关键的反例 |
|---|---|---|---|
| 品牌／成熟优势 | 客户愿意持续付溢价，数量增长受市场和供给约束 | 量价、成本、维护投入、回报持续期 | 客户流失、竞争压价、增长需大量新增资本 |
| 产品／渠道扩张 | 新产品或覆盖范围扩大带来份额，但需要获客和周转 | 市场规模、份额、产品组合、费用、库存 | 收入增长主要来自降价或并购，毛利与资本回报恶化 |
| 周期恢复／回落 | 供需和价差变化使经营偏离可持续水平，再按明确速度调整 | 价格／数量、正常利润、库存、维护与扩产、融资 | 结构性替代、产能过剩、正常利润口径不再可比 |
| 研发商业化 | 当下研究形成未来产品，成功与失败会改变回报 | 费用、产品收入、经济寿命、摊销、税基及投入 | 商业化延迟、产品被替代、投入增加但收益机制不成立 |
| 扩产／经营杠杆 | 先建设再爬坡，利用率提高改善利润，随后新增投入 | 产能、利用率、单位成本、建设年份和周转 | 延期、爬坡损失、订单不足或资本成本超支 |
| 合同／受监管 | 收费和成本传导规则限制增长与回报 | 费率、合同期、服务量、允许资本及回报 | 续约不成立、监管削价、维护和环保投入增加 |
| 结构性收缩 | 需求减少、成本难同步下降，有条件回收资本 | 负增长、费用黏性、可释放资本和剩余期限 | 将账面减少当现金回收，假定企业必然复苏 |
| 多业务／有限寿命／困境 | 不同业务、期限或清偿条件改变现金归属 | 分部、剩余期限、残值、融资和索取权 | 一个合并增长率或永久终值掩盖关键约束 |

最后一类含当前未完备的引擎能力；识别问题仍有价值，但不能为接通伪造永久经营、续期或恢复。研发是可叠加机制，费用金额不自动证明创新成功。原始方法要求利润、研究资本及再投资一致，见[研发与估值](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/R%26D.htm)。

安克、茅台和江波龙的既有材料分别用于产品扩张、成熟优势和供需价差的提问。已完成的12家试点固定跨机制样本；经营增长、资本比例及压力幅度是人工显式条件，没有获得公司预测或价格认证，不继续围绕一家调参。

## 逐证券显式条件展开

### 经营报告证据准备

`tools.collect_narrative_evidence`只消费主库已解析的公告目录清单，不发现证券、不裁决同名公告、不提取标准财务值，也不选择预测参数。当前研究窗口明确限定2025年报和2026半年报；清单保留冻结证券范围、公告ID、官方URL、类型、报告期、解析状态及已有归档定位/哈希。全文候选的英文版、H股版、更新版及误标摘要均先保留，采用哪一份须另记内容依据，不能按ID大小猜测。

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.collect_narrative_evidence \
  --inventory "$ALPHALAKE_REPORT_INVENTORY" \
  --output workspace/derived/narrative-valuation/company-evidence/full
PYTHONPATH=valuation/backend .venv/bin/python -m tools.collect_narrative_evidence \
  --verify workspace/derived/narrative-valuation/company-evidence/full
```

原PDF统一存`workspace/cninfo/objects/`，按官方URL日期／公告ID建立目录引用；文本、选择清单及失败收据放指定derived目录。采集契约为`narrative-document-collection-v3`，下载前在逐URL锁内复用共享收据或已知哈希对象，不因输出目录变化重复下载。已有登记哈希须匹配；缓存核验不认证发行人或经济语义。新下载限定官方公告URL、校验PDF响应，文本提取复用系统`pdftotext`；扫描件/空正文拒绝，不静默换OCR。两个采集任务共享隔离服务的1GiB预算，没有新增Python依赖。`--verify`核对规范原文路径、PDF与文本哈希并保留失败分母，**不认证发行人、业务语义、公司计划实现或预测准确度**。具体路径与迁移见[PDF约定](../guides/workspace-layout.md#pdf归档与引用)。

每份成功报告附`budget_review_index`：定位资本承诺、资本开支计划、重要在建项目、管理层经营计划及研发计划的候选物理页；`read_pages`包含命中页及实际存在的后一页，防止表头和金额跨页割裂。索引只存页码／主题，不再复制正文，不提取金额或认证计划。`unmatched_topics`表示关键词未命中，不能推断无义务或无投入。`--verify`还从同版文本重建索引，篡改页码／主题拒绝。旧v2冻结报告按原提交复验；当前重新生成v3，不增加旧版兼容或复制PDF。

人工故事应分别记录业务组成、需求/竞争机制、反例及数字条件。报告写“扩张市场”并不支持某个精确增长百分比，管理层日历年度计划也不能直接当模型未来滚动一年收入。可以使用现有完整年度接口提出研究条件，但须标明判断来源和未闭合项，不把读过报告等同于已核实十年预测。

本轮输入及报告在`workspace/derived/narrative-valuation/company-evidence-v2/`、`csi300-company-evidence-v2/`与`csi300-company-report-v2/`。增长曲线、业务解释和条件先写入后计算，未根据价差选参数；原文页码采用PDF物理页，文字核对不等于独立经济认证。新主表区分“主研究条件”和“旧恢复诊断”，诊断保留旧输入及值，不能充作新预测。所选年度收入增长不直接宣称公司进入成熟期；融资、稳态增长及资本倍率继承原生条件，各自仍需经济依据。

`tools.narrative_conditions`消费人工指定的`explicit-narrative-assignments-v1`，不执行行业分类或经济参数选择。每个证券明确写出画像、机制、主张、反例、修订触发、限制、证据以及`recipes`；完整证券集合必须等于已准备范围。`evidence`沿用故事契约。未来路径不能覆盖事实、身份、股本或索偿；已有年度路径不被自动替换。

每条recipe保存`id/title/narrative`，并显式指定以下条件：

| 输入 | 可用锚点／含义 |
|---|---|
| `growth_anchor` | `latest_fy`为最近完整FY同比；`three_year_cagr`要求连续四年收入；`flat`为规模持平条件；`existing_cycle`复用既有周期条件 |
| `hold_years/stable_year` | 前者保持锚点增长、之后线性过渡，后者到达原生稳态增长；均为人工指定年数，不是作者统一规定 |
| `margin_anchor/margin_year` | 当前报表TTM利润率、最近三年收入加权报表利润率，或既有周期条件；从当前报表利润率于指定年到达目标，再逐年加研发费用减摊销桥 |
| `cycle_variant` | 周期明确指定`arithmetic-3y`或`revenue_weighted-3y`；复用原观察窗、利润、研发及资本过渡，不另造“正常”数值 |

一般路径保持当前研发费用／收入比，复用普通扣除具名条件及原寿命／队列，现金税由原引擎处理；税率、融资、资本倍率及终点未覆盖项继承同版基线。历史增长不是未来预测；利润率目标也不是同业或公司经济合理性认证。缺年、过界、亏损恢复条件及口径不匹配保留不适用，不能裁剪、补零、改生命周期或静默换锚点。一般路径本轮以正报表利润终点作为条件边界，不反向删除亏损事实或禁止其他已授权输入入口。

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.narrative_conditions \
  --prepared "$ALPHALAKE_PREPARED_STORIES" --assignments "$ALPHALAKE_ASSIGNMENTS" \
  --output "$ALPHALAKE_NEW_STORIES"
```

输出故事文档及`.anchors.json`保留实际历史位置、增长／利润锚点、研发依据和拒绝。文件须在`workspace/derived`，不能覆盖旧文件。随后沿下文`narrative_valuation run/verify`计算。完整值与收盘价列表从已核验故事及同版SQLite生成：

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.narrative_conditions \
  --run "$ALPHALAKE_NARRATIVE_RUN" --database workspace/valuation.sqlite \
  --output "$ALPHALAKE_NEW_PRICE_REPORT"
```

报告保留完整证券、A/B输入顺序、故事、拒绝、收盘日期、两种条件值／价差、隐含非研发资本释放与终值衔接；JSON、CSV、Excel、Markdown及可搜索HTML共同留哈希。A/B不是乐观／悲观、概率或自动胜出者：规模不扩张时利润恢复也可能使B高于A。只读取原生结果，不增加DCF公式或修改网页默认。本轮名单及报价有冻结时点，不能称今日最新。

## 每个故事保存什么

当前使用`narrative-valuation-v2`故事文件及同版原生基线，运行后生成中文说明和逐项结构化证据。v2仅改变PDF引用与归档方式，不改变估值字段、参数或计算；冻结v1按原提交复验。以下内容已落实为输入侧记录；没有扩展`CompanyValuationInput`或新增财务表。

| 内容 | 最少需要记录 |
|---|---|
| 绑定 | 证券／发行人、财务与股本基期、信息截止、行情日、SQLite／参考版本、实现提交 |
| 经济画像 | 阶段、业务机制和适用范围；未确认的标签保留候选 |
| 主张 | 简短的因果链，例如“投产→利用率提高→单位成本下降”，并给适用年度 |
| 证据 | 具名字段或原文定位、期间、单位、范围；事实、公司计划、行业参考、代理和个人判断分开 |
| 参数映射 | 每个主张影响的typed字段、年度值、税前／后及报表／调整口径；说明转换步骤 |
| 边界与反例 | 未知组成、可推翻观察、哪些参数应随证据变化，保留替代解释 |
| 采用与版本 | 人工给定还是未采用候选、理由、旧版本及完整输入／结果摘要；不赋伪概率 |

证据既可支持也可反驳主张。公司披露的产能事实不同于管理层的收入目标；收入目标又不同于研究者采用的销售预测。建议记录“有支持／有冲突／证据不足”，不把它换成未来实现概率或一个自动批准分数。

有效TDX事实照常导出；经营依据不足限制的是新故事的采用，不反向拒绝已有财务或条件计算。原文仅补业务机制和核验，不重建PDF财务主源。对现有证据没有的问题，列出哪项估值判断需要补充，再决定来源和成本，不默认全公司PDF取证或扩采早年。

## 怎样把故事变成数字

先算绝对经营规模，再转成现有接口需要的增长率。若有同范围价格和销量，可分业务算收入；市场份额法须说明可服务市场、份额及平台抽成，不能将交易额、订单或市场规模直接当确认收入。缺细分证据时保留合并条件与限制，不编出分部。

利润率目标来自成本和竞争机制；与当前研究调整后的利润使用同口径，不能直接拿未调整行业均值作研发调整后的目标。[增长公司原始方法](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/littlebook/growthvaluedrivers.htm)要求关注规模、可持续利润及资本需求；长期经营利润的增长关系不能直接当收入增长公式。

投入按故事选择一种明确路径：

- **新增资本倍率**：能够说明新增收入与投入配对关系时使用；存量收入／资本和行业均值只作明确代理。
- **总净再投资预算**：扩产、收入持平仍有研发投入、资本回收等不能用倍率清楚表达时，直接给每个实际投资年的总预算。包含资本化研发净投入，不重复扣减。

只有已知预算分量才作资本开支、折旧、周转及研发的独立核对；现有历史现金和营运资本口径未闭合时，不把分量凑出来的数字当审核完成的预算。负投入可能合理，但必须说明是可回收资源、经营收缩还是折旧与资本开支时点不同。

### 从报告证据到资本预算

先用报告页码索引定位，再人工核对以下范围；关键词、哈希或金额相加均不能替代此步骤。事实数值优先沿TDX标准证据，PDF的承诺／计划作为独立上下文，不反写标准事实。

| 证据 | 可以说明 | 不能直接变成 |
|---|---|---|
| 期末已签约资本承诺 | 当日存在未履行的具体义务；须区分建造资产、无形资产及对外投资 | 下一年现金支出、总净再投资或新增有息债务 |
| 已批准但未签约项目 | 公司计划或授权范围 | 同等强度的合同义务；不能和签约金额混称全部已签约 |
| 自然年资本开支计划及完成额 | 同一公司范围／口径下的年度计划与进度 | 下一个TTM预测年预算；计划减完成只是未完成计划额度，不保证支付或执行 |
| 在建余额、项目总预算及累计进度 | 资产状态或项目全寿命范围 | 全公司下一年支出；不按余额差或总预算差自动估算现金 |
| 募集资金、授信及融资来源 | 可用资金或拟采用的融资安排 | 资本用途、投资回报或额外的FCFF支出 |

将证据按已有`Evidence.kind`分别登记：已报告合同及已完成支出是`reported_fact`，管理层未来预算为`company_plan`，分年分配或执行判断为`research_judgment`。每项写明原文、单位、合并／母公司、报告日及适用期间；没有付款年度不自动分摊，财报计划不自动升级为已核实预测。

与既有条件并排读取总净再投资、研发净投入及隐含非研发分量。正资本承诺与负净投入并存并不矛盾，仍须解释折旧、周转回收及其他分量；不得仅因承诺为正就拒绝，或将承诺总额再扣一次FCFF。不能完成同范围分解时保留未知，原条件可计算与经济依据充分分别报告。固定12家的真实证据与既有条件对应见[本轮记录](../history/capital-budget-evidence-20261017.md)。

税务、研发、风险和终点同组供给。经营故事没有理由改变无风险率；融资／国家风险须有对应政策及来源，不能因故事“很不确定”随意加WACC。存续概率和折现的风险处理避免重复计价，当前复杂困境和税务限制仍保留。

稳定期继续核对再投资率g/ROIC、同币种WACC及现金范围，见[终值原文](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/termvalueexreturns.htm)。无新增超额回报与持续优势是不同条件。不能只改单个ROIC而保留不相容的资本和投入；有限合同不能用永久0%增长代替结束。

### 一个输入桥接例

虚构普通经营公司，人民币百万元，基期收入1,000；没有研发税基差异、亏损或特殊索取权，现金经营税25%。明确给两年经营条件：收入1,100／1,210，税前利润率12%／13%，实际年份总净投入80／90。

对应`annual_forecast`的增长10%／10%、利润率12%／13%、税率25%／25%；`annual_net_reinvestment`为80／90。两年EBIT为132／157.3，NOPAT为99／117.975，FCFF为19／27.975。这只是解释路径如何落到输入；没有供给稳态和融资就不是完整公司估值。

正式使用必须完整覆盖所选`projection_years`，另给终值及风险条件。金额、年度长度和增长界限由现行typed契约校验，示例不回写默认。

## 当前valuation能够接收什么

输入路径相对于`inputs`，金额为百万元报表币种、比率为小数；具体定义以[数据接入spec](data-contract.md)和[显式政策](explicit-policy.md)为准。

| 故事输出 | 当前字段／入口 | 适用及实现边界 |
|---|---|---|
| 完整年度经营路径 | `valuation_assumptions.annual_forecast[].growth/margin/tax` | 覆盖所选全部年数；年度增长>−100%且≤100%，利润率−100%至100%，税0至100%；末年利润率／税率进入终值，不截断超界故事来凑契约 |
| 简单标量路径 | 次年／后续增长、次年／目标利润率和收敛年数 | 网页可编辑，复用生效参数响应；完整年度路径优先，被覆盖标量只读 |
| 新增效率 | `annual_sales_to_capital`及投入领先期 | 全期有限正倍率；原倍率分支实际领先期限制在0–3年。故事入口明确拒绝超界，不让原截取行为误表达故事；更长时差可使用既有实际年预算，不改算法 |
| 实际投入预算 | `annual_net_reinvestment` | 全期有限值，0及负值保留；与年度倍率互斥，直接预算不按领先期再移动；终值仍按g/ROIC |
| 研发费用和税基 | `research_tax`、既有历史队列／经济寿命 | 完整年度费用／扣除及终值首年，复用经济摊销；不从故事自动估计缺历史或优惠资格 |
| 初始融资 | `methodology_choices`与现有参考组件 | 参考版本及CNY口径绑定；实际信用、经营地域和行业代理分别标记 |
| 未来融资 | 稳态WACC覆盖或完整`debt_tax_shield` | 年度经营路径不会同时覆盖融资过渡；`high_growth_years`仍影响原WACC时序。完整融资路径须有配套组件和依据，NOL到期／限额等未实现 |
| 稳定条件 | `stable_growth_rate`、`roic_stable_override`及稳态WACC | 使用实际生效值审阅；预测末期与稳态不能断裂，ROIC留空沿原无超额回报条件 |
| 运行与审阅 | 原生完整API、`evaluate_native_policy`、`review_native_policy.review_report` | 现有输入／响应可保存、重放、显示现金及资本限制；审阅不自动证明公司经济依据 |

核对调用链为 `api/database.py` 的数据库准备 → `api/routes.py` 的完整POST／PATCH → `engine/orchestrator.py` → `module_4_dcf.py`。原生网页的来源初值保留作对照，不因新故事覆盖历史、研发、股权桥或默认。零收入商业化、有限寿命、完整分部估值和复杂困境不能仅靠现有标量准确表达；这类记录为当前路径不适用，而非公司没有价值。

现有`StoriesToNumbers.tsx`仍是参数、历史／行业比较及敏感性的视图，没有自由文本理解或故事编辑表单。显示BUG已修：ROIC直接读取引擎同范围税后利润／期初资本结果，新增资本倍率与历史存量周转分开；终值文案区分无超额回报条件和有依据的持续优势。DCF和默认不变，详见[台账E39](engine-change-ledger.md#e39stories回报与终值显示bug2026-10-07)。

## 最小接入方式与产出

统一使用`tools.narrative_valuation`。先从同版SQLite和完整范围收据准备草稿，再登记业务证据、主张、反例及采用的年度条件；状态明确改为`conditional`才计算。命令在仓库根目录、[独立1GiB服务](../guides/fundamental-memory-20260919.md)中串行执行，示例中的文件必须换成本次真实配置：

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.narrative_valuation prepare \
  --database workspace/valuation.sqlite \
  --coverage workspace/derived/cyclical-income-history/published-coverage.json \
  --ticker SZSE:300866 --ticker SHSE:600519 \
  --output workspace/derived/narrative-valuation/new-prepared

# 人工审核并编辑new-prepared/stories.json后，使用新运行目录。
PYTHONPATH=valuation/backend .venv/bin/python -m tools.narrative_valuation run \
  --database workspace/valuation.sqlite \
  --stories workspace/derived/narrative-valuation/new-prepared/stories.json \
  --output workspace/derived/narrative-valuation/new-run \
  --web http://127.0.0.1:8080

PYTHONPATH=valuation/backend .venv/bin/python -m tools.narrative_valuation verify \
  workspace/derived/narrative-valuation/new-run

# 新故事注明previous_run_id，改动的故事增加revision，再计算new-revised。
PYTHONPATH=valuation/backend .venv/bin/python -m tools.narrative_valuation compare \
  workspace/derived/narrative-valuation/new-run \
  workspace/derived/narrative-valuation/new-revised
```

`--coverage`是与SQLite哈希、主库哈希、报告期及截止完全匹配的`alphalake-native-coverage-v1`收据，位置从当前发布证据核对，不能复用旧快照或仅改哈希。`--web`可选；指定后所有计算条件逐项复验实际原生完整API，不发布故事或替换网页默认。

### 故事文件与机械转换

- 顶层`snapshot/scope`由`prepare`生成；完整保留指定证券分母。`evidence`登记workspace相对文件、SHA-256、原文定位、说明及来源类型。类型区分原生基线、报告事实、公司计划、参考、政策代理和研究判断；文件哈希不证明经济主张为真。
- 每条`stories[]`有稳定`id`、递增`revision`、`ticker`、共享原生基线、中文叙事、经济画像、机制、限制及状态。一个发行人可有多个故事；`draft`不算，`not_applicable`保留边界，`conditional`只表示明确供给条件，不是自动批准。
- `claims[]`记录主张、参数集合、证据ID、`supported/conflicting/insufficient`、反例及修订触发。必须覆盖`revenue/margin/tax/capital/research/financing/terminal`及每项完整覆盖路径；资本、研发、融资或终点沿基线时也须说明继承依据和限制。
- `annual_operating_plan`连续覆盖第1至N年，字段为`year/revenue_million_cny/adjusted_operating_margin/tax_rate`；金额百万元人民币，百分比用小数。先从绝对收入算相邻年度增长，机械编译为原`annual_forecast`，不裁剪超界值、不自动推导经营假设。
- `assumption_overrides`按原生点路径给既有假设、融资／参考方法参数，如`valuation_assumptions.annual_net_reinvestment`。完整数组仍遵守原长度与互斥契约。年度经营字段由计划生成；财务、身份、股本、期权、转债／优先索偿、困境及现金桥输入不能由故事覆盖。其他未覆盖条件继承同版基线，实际融资政策的计算影响仍需审阅。

完整typed请求只包含`{"inputs": CompanyValuationInput}`；故事文件在计算外保存。条件计算前，每家已准备基线与当前实际`from-database`响应核对，不能通过改证据哈希替换财务。年度计划和返回收入、调整EBIT及税率逐项核对；研发、税盾、投入与终值沿现有计算规则。

每家公司建议最多先研究三条因果连贯的条件，例如“既有产品扩张”“竞争压价”“新产品延迟”。这是本地控制工作量的建议，不是三条必须同数值规则或发生概率。在看估值及股价之前写清主张、参数与选择理由；选择主故事须由证据和判断决定，不由价格决定。

最小结果包括：故事摘要与证据状态；完整年度请求；收入、调整利润、现金税、净投入与FCFF；终值占比与约束；经营价值、股权桥和每股值；相对同版默认的输入及结果差异；未闭合依据与可推翻条件。来源和请求留痕放`workspace/derived/narrative-valuation/`，不能成为第二财务库。

中文`report.md`与`summary.csv`读取已有响应；完整请求、绑定、结果、审阅及非PDF证据保存在同目录。PDF只保留来源目录的相对路径与哈希，CNINFO须引用规范原文对象；`manifest.pdf_references`登记引用，报告直接链接归档，不复制到运行目录。run ID在计算前由规范故事内容与实现版本生成，`manifest.json`登记产物与外部原文引用；已存在目录不覆盖，运行计算阶段失败保留`failure.json`且不产生完整manifest。逐条业务拒绝保留分母，退出0也不表示每条故事已算或获经济认证。

`verify`验证归档成员、PDF来源引用及哈希，重新编译请求、重放共享引擎并独立聚合现金流／终值；即使篡改响应并同步改哈希，也不能代替引擎结果。冻结旧契约按原提交复验，归档迁移的旧路径仅在隔离workspace按收据恢复；当前故事用v2重新准备，不增设兼容分支。实现变更本身不拒绝旧证据，须报告版本差异并实际重放；行为不再相同则按合法新输入重建。`compare`要求明确的`previous_run_id`，改动故事递增版本，列内容、输入与结果变化，不自动归因多因素或选胜出者。核验／比较收据放运行目录之外，避免污染不可变归档。

结构化编排现已实现；原生网页未新增故事编辑器、叙事目录或文字转参数能力。KB可供理解与人工复核，不是默认参数规则库。

## 验收与修订

四项分开报告：

1. **输入完整**：字段、长度、单位、期间和来源版本正确；保留有效事实、全部证券及条件分母。
2. **算术一致**：同请求原生API重放；税基、总净投入、FCFF、资本与终值相互衔接。有资本释放或高超额回报并不自动判错，列出证据问题。
3. **经济可辩护**：每项重要参数能回到经营主张，证据范围与主张一致；有反例和未知项。不能把来源初值、可算或审阅器通过当本项完成。
4. **预测有效**：以后用未参与选择的新经营结果检查收入、EBIT和可核验投入；指标定义和比较基线事前固定。完整历史FCFF尚未闭合时不伪造实际FCFF评分，不为本方案扩采早年或重开长期回测。

合法新证据可修订故事与假设，重建完整基线并解释变化。拆分事实刷新、经营路径、投入、折现和股权桥；多因素共同改变不称单因素贡献。不同变更顺序可能有交互效应，不将顺序对照冒充唯一归因。手工刷新沿原发布流程；故事修订不自动替换全市场网页默认，也不安装调度。
