# 估值叙事：公司证据到原生估值的方案

状态：2026-10-07研究提案，未实现叙事编排或参数自动选择，未改引擎、默认、网页及数据。当前接入能力按代码核对；方法依据、公司判断和建议的产品规则分别说明。范围仍为沪深非金融，短历史估计、金融及多市场不在本轮方案中启动。

## 目标与架构

为不同公司写出可检验的经营解释，把每项主张连到证据、年度假设及现金后果。交付是可复用的研究与输入流程，最终由原生valuation计算；故事属于发行人的业务，股价与每股索取权在股权桥中另行处理。

主线：**公司事实与参考 → 经济特征 → 经营主张和反例 → 显式年度条件 → 原生API → 算术与经济审阅 → 版本化修订**。

达摩达兰的[叙事书籍说明](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/NNPreface.html)把故事、数字、可信程度和反馈连起来；[公司生命周期](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/CLC/CLCPreface.html)解释不同阶段为什么面对不同经营与估值问题。下文类型、记录格式、阶段和验收是本地设计，不冒称作者给出的统一分类或默认参数。

AlphaLake管理证据和显式假设，valuation消费现有`CompanyValuationInput`，KB负责教学。叙事不写入标准财务事实，知识面板不计算，不新增DCF引擎。先复用来源、typed输入、完整API及审阅器；第一阶段无需新增数据库表、语言模型依赖或前端表单。

## 如何为不同公司形成故事

先回答四组问题：

1. **生意与阶段**：客户为何付钱，收入怎样确认，业务是商业化、扩张、成熟还是收缩？上市时间和经营阶段分开。
2. **需求与竞争**：增长来自数量、价格、份额、新产品还是收购？谁可能夺走客户或利润？
3. **资源与时间**：已有产能能支持多少增长，新厂、研发和周转什么时候投入，多久产生收益？
4. **终点与存续**：较稳定状态为什么成立，优势能维持多久，有无期限和资金约束？

再按达摩达兰的三层检验提问：**可能（Possible）**——有没有违背市场容量、资源和会计约束？**可信（Plausible）**——公司的产品、竞争位置和执行能力能否支持这条路径？**较可能（Probable）**——与其他解释相比，目前证据为什么更支持它？三层不能互相替代，也不等于已经知道某故事的数值概率；没有依据就保留条件，不编造情景权重。

经营阶段、经济机制及存续条件可以叠加；申万用于发现同业，不直接给公司选择故事。单年亏损、最近同比和估值高低不决定类型。建议研究以下机制库，每类提供问题和证据清单，不预填统一百分比。

| 机制 | 可检验的故事主张 | 应量化的变量 | 最关键的反例 |
|---|---|---|---|
| 品牌／成熟优势 | 客户愿意持续付溢价，数量增长受市场和供给约束 | 量价、成本、维护投入、回报持续期 | 客户流失、竞争压价、增长需大量新增资本 |
| 产品／渠道扩张 | 新产品或覆盖范围扩大带来份额，但需要获客和周转 | 市场规模、份额、产品组合、费用、库存 | 收入增长主要来自降价或并购，毛利与资本回报恶化 |
| 周期恢复／回落 | 供需和价差变化使经营偏离可持续水平，再按明确速度调整 | 价格／数量、正常利润、库存、维护与扩产、融资 | 结构性替代、产能过剩、正常利润口径不再可比 |
| 研发商业化 | 当下研究形成未来产品，成功与失败会改变回报 | 费用、产品收入、经济寿命、摊销、税基及投入 | 商业化延迟、产品被替代、投入增加但收益机制不成立 |
| 扩产／经营杠杆 | 先建设再爬坡，利用率提高改善利润，随后新增投入 | 产能、利用率、单位成本、建设年份和周转 | 延期、爬坡损失、订单不足或资本成本超支 |
| 合同／受监管 | 收费和成本传导规则限制增长与回报 | 费率、合同期、服务量、允许资本及回报 | 续约不成立、监管削价、维护和环保投入增加 |
| 结构性收缩 | 需求减少、成本难同步下降，有条件回收资本 | 负增长、费用黏性、可释放资本和剩余期限 | 将账面减少当现金回收，假定企业必然复苏 |
| 多业务／有限寿命／困境 | 不同业务、期限或清偿条件改变现金归属 | 分部、剩余期限、残值、融资和索取权 | 一个合并增长率或永久终值掩盖关键约束 |

最后一类含当前未完备的引擎能力；识别问题仍有价值，但不能为接通伪造永久经营、续期或恢复。研发是可叠加机制，费用金额不自动证明创新成功。原始方法要求利润、研究资本及再投资一致，见[研发与估值](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/R%26D.htm)。

安克、茅台和江波龙的既有材料可分别用于练习产品扩张、成熟优势和供需价差的提问；这里不为三家批准新参数、分类结论或价格。正式试点选跨公司固定样本，不继续围绕一家调参。

## 每个故事保存什么

先使用一份可阅读的说明及请求旁的结构化证据，复用既有运行归档；以下是建议内容，尚非新API或已实现schema。

| 内容 | 最少需要记录 |
|---|---|
| 绑定 | 证券／发行人、财务与股本基期、信息截止、行情日、SQLite／参考版本、实现提交 |
| 经济画像 | 阶段、业务机制和适用范围；未确认的标签保留候选 |
| 主张 | 简短的因果链，例如“投产→利用率提高→单位成本下降”，并给适用年度 |
| 证据 | 具名字段或原文定位、期间、单位、范围；事实、公司计划、行业参考、代理和个人判断分开 |
| 参数映射 | 每个主张影响的typed字段、年度值、税前／后及报表／调整口径；说明转换步骤 |
| 边界与反例 | 未知组成、可推翻观察、哪些参数应随证据变化，保留替代解释 |
| 采用与版本 | 人工给定还是未采用候选、理由、旧版本及完整输入／结果摘要；不赋伪概率 |

证据既可支持也可反驳主张。公司披露的产能事实不同于管理层的收入目标；收入目标又不同于研究者采用的销售预测。建议记录“有支持／有冲突／证据不足”，不把它换成未来实现概率或一个自动批准分数。

有效TDX事实照常导出；经营依据不足限制的是新故事的采用，不反向拒绝已有财务或条件计算。原文仅补业务机制和核验，不重建PDF财务主源。对现有证据没有的问题，列出哪项估值判断需要补充，再决定来源和成本，不默认全公司PDF取证或扩采早年。

## 怎样把故事变成数字

先算绝对经营规模，再转成现有接口需要的增长率。若有同范围价格和销量，可分业务算收入；市场份额法须说明可服务市场、份额及平台抽成，不能将交易额、订单或市场规模直接当确认收入。缺细分证据时保留合并条件与限制，不编出分部。

利润率目标来自成本和竞争机制；与当前研究调整后的利润使用同口径，不能直接拿未调整行业均值作研发调整后的目标。[增长公司原始方法](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/littlebook/growthvaluedrivers.htm)要求关注规模、可持续利润及资本需求；长期经营利润的增长关系不能直接当收入增长公式。

投入按故事选择一种明确路径：

- **新增资本倍率**：能够说明新增收入与投入配对关系时使用；存量收入／资本和行业均值只作明确代理。
- **总净再投资预算**：扩产、收入持平仍有研发投入、资本回收等不能用倍率清楚表达时，直接给每个实际投资年的总预算。包含资本化研发净投入，不重复扣减。

只有已知预算分量才作资本开支、折旧、周转及研发的独立核对；现有历史现金和营运资本口径未闭合时，不把分量凑出来的数字当审核完成的预算。负投入可能合理，但必须说明是可回收资源、经营收缩还是折旧与资本开支时点不同。

税务、研发、风险和终点同组供给。经营故事没有理由改变无风险率；融资／国家风险须有对应政策及来源，不能因故事“很不确定”随意加WACC。存续概率和折现的风险处理避免重复计价，当前复杂困境和税务限制仍保留。

稳定期继续核对再投资率g/ROIC、同币种WACC及现金范围，见[终值原文](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/termvalueexreturns.htm)。无新增超额回报与持续优势是不同条件。不能只改单个ROIC而保留不相容的资本和投入；有限合同不能用永久0%增长代替结束。

### 一个输入桥接例

虚构普通经营公司，人民币百万元，基期收入1,000；没有研发税基差异、亏损或特殊索取权，现金经营税25%。明确给两年经营条件：收入1,100／1,210，税前利润率12%／13%，实际年份总净投入80／90。

对应`annual_forecast`的增长10%／10%、利润率12%／13%、税率25%／25%；`annual_net_reinvestment`为80／90。两年EBIT为132／157.3，NOPAT为99／117.975，FCFF为19／27.975。这只是解释路径如何落到输入；没有供给稳态和融资就不是完整公司估值。

正式使用必须完整覆盖所选`projection_years`，另给终值及风险条件。金额、年度长度和增长界限由现行typed契约校验，示例不回写默认。

## 当前valuation能够接收什么

输入路径相对于`inputs`，金额为百万元报表币种、比率为小数；具体定义以[数据接入spec](data-contract.md)和[显式政策](explicit-policy.md)为准。

| 故事输出 | 当前字段／入口 | 适用及实现边界 |
|---|---|---|
| 完整年度经营路径 | `valuation_assumptions.annual_forecast[].growth/margin/tax` | 覆盖所选全部年数；年度增长>−100%且≤100%，利润率−100%至100%，税0至100%；末年利润率／税率进入终值，不截断超界故事来凑契约 |
| 简单标量路径 | 次年／后续增长、次年／目标利润率和收敛年数 | 网页可编辑，复用生效参数响应；完整年度路径优先，被覆盖标量只读 |
| 新增效率 | `annual_sales_to_capital`及投入领先期 | 全期有限正倍率；目前倍率分支实际领先期被限制在0–3年，超界被截取。故事需要更长时差时明确表达边界，可评估已有实际年预算入口，不擅改算法 |
| 实际投入预算 | `annual_net_reinvestment` | 全期有限值，0及负值保留；与年度倍率互斥，直接预算不按领先期再移动；终值仍按g/ROIC |
| 研发费用和税基 | `research_tax`、既有历史队列／经济寿命 | 完整年度费用／扣除及终值首年，复用经济摊销；不从故事自动估计缺历史或优惠资格 |
| 初始融资 | `methodology_choices`与现有参考组件 | 参考版本及CNY口径绑定；实际信用、经营地域和行业代理分别标记 |
| 未来融资 | 稳态WACC覆盖或完整`debt_tax_shield` | 年度经营路径不会同时覆盖融资过渡；`high_growth_years`仍影响原WACC时序。完整融资路径须有配套组件和依据，NOL到期／限额等未实现 |
| 稳定条件 | `stable_growth_rate`、`roic_stable_override`及稳态WACC | 使用实际生效值审阅；预测末期与稳态不能断裂，ROIC留空沿原无超额回报条件 |
| 运行与审阅 | 原生完整API、`evaluate_native_policy`、`review_native_policy.review_report` | 现有输入／响应可保存、重放、显示现金及资本限制；审阅不自动证明公司经济依据 |

核对调用链为 `api/database.py` 的数据库准备 → `api/routes.py` 的完整POST／PATCH → `engine/orchestrator.py` → `module_4_dcf.py`。原生网页的来源初值保留作对照，不因新故事覆盖历史、研发、股权桥或默认。零收入商业化、有限寿命、完整分部估值和复杂困境不能仅靠现有标量准确表达；这类记录为当前路径不适用，而非公司没有价值。

现有 `StoriesToNumbers.tsx` 是参数、历史／行业比较及敏感性的视图，没有自由文本理解或证据到参数的编排。回报口径和终值文案问题已进入[TODO](../../valuation/TODO.md)，应先按明确BUG规则修正解释，不能让该页成为错误的故事认证器。

## 最小接入方式与产出

现阶段可由研究者直接准备故事说明和完整请求，调用现有完整`POST /api/valuation`；也可用[具名交付入口](../guides/company-valuation-entry.md#原生具名条件自动交付)保存请求及核验结果：

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.evaluate_native_policy \
  --database workspace/valuation.sqlite \
  --explicit-input workspace/derived/narrative-valuation/company-request.json \
  --output workspace/derived/narrative-valuation/new-run \
  --web http://127.0.0.1:8080
```

这是已有命令的用法，不表示本轮已创建请求或执行估值；按独立1GiB服务串行运行。不同故事按独立请求／运行保存，因为当前具名批次不允许同一证券重复。其自动附加的3／5／10年增长及资本对照仍只是固定条件，不等于研究者的替代故事；不能混为一张故事概率表。批次聚合及故事证据绑定尚未产品化。

请求文件仅为既有后端`{"inputs": CompanyValuationInput}`；故事和证据保存在旁侧说明中，不向现有typed输入塞入未知字段。完整请求只证明显式数值已交付，仍须核对它们与来源快照、所采用故事的一致性。

每家公司建议最多先研究三条因果连贯的条件，例如“既有产品扩张”“竞争压价”“新产品延迟”。这是本地控制工作量的建议，不是三条必须同数值规则或发生概率。在看估值及股价之前写清主张、参数与选择理由；选择主故事须由证据和判断决定，不由价格决定。

最小结果包括：故事摘要与证据状态；完整年度请求；收入、调整利润、现金税、净投入与FCFF；终值占比与约束；经营价值、股权桥和每股值；相对同版默认的输入及结果差异；未闭合依据与可推翻条件。来源和请求留痕放`workspace/derived/narrative-valuation/`，不能成为第二财务库。

当前完整API没有自动读取故事文件或公司叙事目录的能力，也不会把外部完整请求中每个显式数值都认证为公司事实。第一阶段请求旁保留业务证据即可；后续新增结构化编排、证据到字段校验、故事选择或展示都须明确授权并同步契约。KB已经提供叙事／自测及经济策略，可以用于理解、编辑与复核，但不作为默认参数规则库。

## 验收与修订

四项分开报告：

1. **输入完整**：字段、长度、单位、期间和来源版本正确；保留有效事实、全部证券及条件分母。
2. **算术一致**：同请求原生API重放；税基、总净投入、FCFF、资本与终值相互衔接。有资本释放或高超额回报并不自动判错，列出证据问题。
3. **经济可辩护**：每项重要参数能回到经营主张，证据范围与主张一致；有反例和未知项。不能把来源初值、可算或审阅器通过当本项完成。
4. **预测有效**：以后用未参与选择的新经营结果检查收入、EBIT和可核验投入；指标定义和比较基线事前固定。完整历史FCFF尚未闭合时不伪造实际FCFF评分，不为本方案扩采早年或重开长期回测。

合法新证据可修订故事与假设，重建完整基线并解释变化。拆分事实刷新、经营路径、投入、折现和股权桥；多因素共同改变不称单因素贡献。不同变更顺序可能有交互效应，不将顺序对照冒充唯一归因。手工刷新沿原发布流程；故事修订不自动替换全市场网页默认，也不安装调度。

## 建议实施顺序与停止条件

**第一阶段：证据与人工输入试点。** 固定12–20家现有已准入、跨机制非金融样本及同一来源快照；保留默认，人工写主张／证据／反例，使用现有年度API完成条件。新接口尚不需要。先修现有Stories显示BUG，独立于经营参数研究，不改DCF。

**第二阶段：确定性输入编排。** 经批准后，增加最小故事记录到既有typed请求的连接，校验参数与来源定位，沿现有运行收据及审阅器。机械计算、完整性和版本匹配可自动；缺需求／竞争证据仍由研究者给条件，不填编造的增长。

**第三阶段：更新与展示。** 先做版本比较和手工重估；若获前端授权，再在原Stories页面展示业务问题、依据与反例，复用KB及当前响应。网页提供普通语言和数值编辑，不暴露JSON，不另建估值流程。

**参数自动选择／LLM叙事仅作后续研究。** 当前延期约定不因本提案解除。若以后获准，可用模型辅助提取经营证据和生成可审阅草稿，逐条引用并保留冲突；不能从漂亮文章直接生成获认证的参数或概率。经济选择规则须另建基线与验证，不能伪装为输入编排。
