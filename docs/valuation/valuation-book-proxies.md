# 标准财务输入与资产代理

原生网页/API统一读取DuckDB导出的SQLite标准财务列；来源EBIT不按证券代码自动替换。`input_contract`标明利润基础、无公司自动覆盖和经营范围尚未认证。用户在原页面的显式修改仍保留来源记录。

## 当前规则

| 输入 | 使用方式 | 边界 |
|---|---|---|
| EBIT、EBITDA | 直接使用各自标准出口；TTM按同期间年度＋本期累计−上期累计计算 | 来源报告值不等于已剔除非经营、非经常项目的经营利润；不再因专项EBIT改写而清空EBITDA |
| 现金及长期投资 | 使用[SQLite契约](../guides/valuation-sqlite-export.md)内已批准、留痕的通用代理 | 已知组成不等于完整范围或公允价值；未知不归零 |
| 债务 | 使用已批准的五分量账面代理 | 不冒充市场价值，注意到期项范围及租赁重复资本化 |
| 多股类市值 | 当前仍可用A股价格×总股本代理 | 缺B/H股价格及汇率，不称真实分股类市值 |
| 研发资本化、租赁调整 | 由显式估值调整输入及共享引擎计算 | 不写回财务事实；寿命、队列及是否已入表分别核实 |

## 收益与资产的配套

达摩达兰[现金与交叉持股](https://pages.stern.nyu.edu/adamodar/New_Home_Page/valquestions/a22.htm)要求：经营价值未包含收益的资产另行计价，已包含的不能重复加入。这不证明所有投资收益、公允价值损益均为非经营；套期损益是已存在的反例。

当前标准EBIT与现金/投资代理的精确配套仍未逐公司完成。既有授权允许条件计算，API继续明确提示重复计价或遗漏风险；不能把接通数据宣称为完整经营口径认证。证据明确的调整应在估值政策层显式表达、保留原值及调整组成，不能隐藏在基础取数入口。

### 按类别核对

| 机制 | 已有标准证据及当前消费 | 可以确定什么／不能自动做什么 |
|---|---|---|
| 现金及利息 | `cash_and_cash_equivalents`期末余额→现金代理；`interest_income`为TTM流量 | 余额不是超额现金；先确认报告EBIT是否已排除利息收入，不能再整项扣一次。货币资金和现金等价物不能简单相加 |
| 权益法投资 | `long_term_equity_investments`与`associates_and_joint_ventures_investment_income`；后者是`investment_income`的其中项 | 其中项不能在投资收益外再次相减。长期股权投资可能还有成本法等组成，余额与当期收益不是逐项一一配对；账面金额不自动等于持股价值 |
| 其他金融工具 | 交易性／衍生金融资产、债权投资、其他权益工具及其他非流动金融资产；投资收益及公允价值变动 | 当前长期投资代理已含五项长期余额，但现金代理未自动加交易性金融资产。套期、经营相关收益、其他综合收益及金融负债须区分；不能把全部损益认作这些资产的收益或整桶剔除 |
| 资产处置 | `asset_disposal_income` | 非零不证明一次性，也不等于出售收到的现金。正常化利润、更新资本开支和可回收资产价值须配套，不能见处置收益就删 |
| 合并及少数权益 | `equity_parent + noncontrolling_interests`核对`total_equity`；原生使用合并经营、单独扣少数权益 | 合并资本核对是账面恒等式，少数权益账面代理仍不是市场价值；不能把少数权益当母公司的交叉持股加回 |

[财政部报表格式附件2](https://www.mof.gov.cn/gkml/caizhengwengao/wg201901/wg201905/201909/P020190912379331344319.pdf)第10–13页明确区分这些损益行及其中项。国内“营业利润”也包含投资、公允价值和资产处置损益，不能改读该行就声称得到纯经营利润；利息收入是冲减财务费用的其中项。各类资产的计量及损益去向见同附件第3–5、14–15页，不能把其他综合收益当当期利润。

方法依据为达摩达兰[现金／非经营资产](https://pages.stern.nyu.edu/~adamodar/pdfiles/papers/cashvaluation.pdf)、[交叉持股估值](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/valcrosshold.htm)及[回报测量](https://pages.stern.nyu.edu/~adamodar/pdfiles/papers/returnmeasures.pdf)的Cross Holdings部分：经营收益、资本及单列资产保持同一范围；账面代理、投资市值及合并扣减分别处理。原文的旧会计分类不是当前中国报表的映射目录。

### 通用数据对账入口

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.review_profit_asset_scope \
  --database workspace/valuation.sqlite \
  --source-database workspace/alphalake.duckdb \
  --output workspace/derived/profit-asset-scope/coverage.json
```

按[隔离规范](../guides/fundamental-memory-20260919.md)运行。输出已存在时拒绝覆盖；新复验先按派生清理规则退役旧输出。工具保留完整发布证券分母，仅审阅已分类非金融；一次批量读取所需标准字段，流量取完整累计三项、余额只取期末。核对源版本与发布财务内容签名，校验每家公司输入签名、身份、单位、期间、范围和源记录；缺项不补零，源冲突拒绝本次审核，不更改已有发布。

输出`alphalake-profit-asset-scope-v1`包含标准组成、每报告一次的源记录引用、原生五项消费金额对账、机制观测及算术核对。金额为元，原生值为百万元；`cross_holdings`按既有五项已知小计代理对账，仍列缺失组成，匹配不冒称完整资产。

报表EBIT分别与“利润总额＋利息支出”“利润总额＋财务费用”“利润总额＋利息支出−利息收入”核对，报告TTM及每个累计期间的残差和源float32舍入界限。它们是明确列出的算术候选，不是推断出的供应商公式或经营范围认证；累计差额抵消不算各期均闭合，已知利息成分不重复扣除。合并权益另核对父级与少数权益之和。少量反例不扩成新个股政策，不新增准入阻断。

`observed_pairs`只表示所列资产／收益非零或缺组成。未观测、全零、缺项和反向收益分别保留；不存在“配对非零即重复计价”“未配对即没有业务”的结论。程序不重算DCF、不自动生成新假设、不改主库／SQLite；最新冻结验收见[本轮记录](../history/profit-asset-scope-20261017.md)。

### 待审批共同口径

下一项如需改变估值，应提交**成套显式调整**，而非只替换一列EBIT：

1. 保存原报表利润及每项已识别的非经营收益，标明该项是否已经排除、是否包含子项及同期间同合并范围；扣减损失按原符号处理。普通利息、经营套期和权益法收益不按名称自动统一处置。
2. 将收益归属与现金／持股资产的单独计价对应，记录保留的经营现金、账面／市场代理、限制及未知。可复用现有完整API的`raw_financials`、`prepared_ttm`和显式年度预测；接口可表达不等于允许自动改写数据库新会话。
3. 同步税项、研发／租赁、合并资本和少数权益。当前M3/M4投入资本只扣现金，不单独扣长期投资；若切换为剔除投资收益的经营口径，还需明确对应资本及历史比较口径。不能修改`consolidated_book_equity`来源值来暗中模拟经营资本。
4. 如确需新增经营资本输入或改变现有分母／默认政策，先在[TODO](../../valuation/TODO.md)审批；只提交本期具备证据的类别及原生同条件对照，不启动自动选择器、逐公司PDF数值主源或新来源全量扩采。保留原条件，分别报告算术差异和经济分类依据；不能为使估值更接近市价而选口径。

本轮只完成数据组成、对账和具体方法边界，不自动采用上述调整；没有证据的拆分仍未知，也不撤销已批准代理或清空有效财务。

## 已撤销的接通特例

2026-09-26的两家公司政策同时改写现金、投资和EBIT，且专项分量缺失会把已存在的报表利润清空。2026-09-29删除其执行模块及包装入口，政策仅作[历史证据](../history/tdx-book-assets-v1.json)保留；[旧验收](../history/valuation-book-proxies.md)不再描述当前行为。主库和SQLite事实不变，新会话统一使用标准出口，旧结果按原版本复验，不混作价格更新。

恢复标准EBIT不保证估值更高、更低或更准确；它恢复统一、可追溯的数据基础。具体方法审核见[方法契约](methodology-contract.md#标准输入与方法复核2026-09-29)。
