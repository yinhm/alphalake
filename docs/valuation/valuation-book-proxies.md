# 标准财务输入与资产代理

原生网页/API统一读取DuckDB导出的SQLite标准财务列；来源EBIT不按证券代码自动替换。`input_contract`标明利润基础、无公司自动覆盖和经营范围尚未认证。用户在原页面的显式修改仍保留来源记录。

## 当前规则

| 输入 | 使用方式 | 边界 |
|---|---|---|
| EBIT、EBITDA | 直接使用各自标准出口；TTM按同期间年度＋本期累计−上期累计计算 | 来源报告值不等于已剔除非经营、非经常项目的经营利润；不再因专项EBIT改写而清空EBITDA |
| 现金及长期投资 | 使用[SQLite契约](../guides/valuation-sqlite-export.md)内已批准、留痕的通用代理 | 已知组成不等于完整范围或公允价值；未知不归零 |
| 债务 | 使用已批准的五分量账面代理 | 不冒充市场价值，注意到期项范围及租赁重复资本化 |
| 多股类市值 | 当前仍可用A股价格×总股本代理 | 缺B/H股价格及汇率，不称真实分股类市值 |
| 研发资本化、租赁调整 | 由显式估值调整输入及共享引擎计算 | 不写回财务事实；寿命、队列及是否已入表分别核实 |

## 收益与资产的配套

达摩达兰[现金与交叉持股](https://pages.stern.nyu.edu/adamodar/New_Home_Page/valquestions/a22.htm)要求：经营价值未包含收益的资产另行计价，已包含的不能重复加入。这不证明所有投资收益、公允价值损益均为非经营；套期损益是已存在的反例。

当前标准EBIT与现金/投资代理的精确配套仍未逐公司完成。既有授权允许条件计算，API继续明确提示重复计价或遗漏风险；不能把接通数据宣称为完整经营口径认证。证据明确的调整应在估值政策层显式表达、保留原值及调整组成，不能隐藏在基础取数入口。

### 按类别核对

| 机制 | 已有标准证据及当前消费 | 可以确定什么／不能自动做什么 |
|---|---|---|
| 现金及利息 | `cash_and_cash_equivalents`期末余额→现金代理；`interest_income`为TTM流量 | 余额不是超额现金；先确认报告EBIT是否已排除利息收入，不能再整项扣一次。货币资金和现金等价物不能简单相加 |
| 权益法投资 | `long_term_equity_investments`与`associates_and_joint_ventures_investment_income`；后者是`investment_income`的其中项 | 其中项不能在投资收益外再次相减。长期股权投资可能还有成本法等组成，余额与当期收益不是逐项一一配对；账面金额不自动等于持股价值 |
| 其他金融工具 | 交易性／衍生金融资产、债权投资、其他权益工具及其他非流动金融资产；投资收益及公允价值变动 | 当前长期投资代理已含五项长期余额，但现金代理未自动加交易性金融资产。套期、经营相关收益、其他综合收益及金融负债须区分；不能把全部损益认作这些资产的收益或整桶剔除 |
| 资产处置 | `asset_disposal_income` | 非零不证明一次性，也不等于出售收到的现金。正常化利润、更新资本开支和可回收资产价值须配套，不能见处置收益就删 |
| 合并及少数权益 | `equity_parent + noncontrolling_interests`核对`total_equity`；原生使用合并经营、单独扣少数权益 | 合并资本核对是账面恒等式，少数权益账面代理仍不是市场价值；不能把少数权益当母公司的交叉持股加回 |

[财政部报表格式附件2](https://www.mof.gov.cn/gkml/caizhengwengao/wg201901/wg201905/201909/P020190912379331344319.pdf)第10–13页明确区分这些损益行及其中项。国内“营业利润”也包含投资、公允价值和资产处置损益，不能改读该行就声称得到纯经营利润；利息收入是冲减财务费用的其中项。各类资产的计量及损益去向见同附件第3–5、14–15页，不能把其他综合收益当当期利润。

方法依据为达摩达兰[现金／非经营资产](https://pages.stern.nyu.edu/~adamodar/pdfiles/papers/cashvaluation.pdf)、[交叉持股估值](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/valcrosshold.htm)及[回报测量](https://pages.stern.nyu.edu/~adamodar/pdfiles/papers/returnmeasures.pdf)的Cross Holdings部分：经营收益、资本及单列资产保持同一范围；账面代理、投资市值及合并扣减分别处理。原文的旧会计分类不是当前中国报表的映射目录。

### 通用数据对账入口

```bash
PYTHONPATH=valuation/backend .venv/bin/python -m tools.review_profit_asset_scope \
  --database workspace/valuation.sqlite \
  --source-database workspace/alphalake.duckdb \
  --output workspace/derived/financial-asset-scope/recheck.json
```

按[隔离规范](../guides/fundamental-memory-20260919.md)运行。输出已存在时拒绝覆盖；新复验先按派生清理规则退役旧输出。工具保留完整发布证券分母，仅审阅已分类非金融；一次批量读取所需标准字段，流量取完整累计三项、余额只取期末。核对源版本与发布财务内容签名，校验每家公司输入签名、身份、单位、期间、范围和源记录；缺项不补零，源冲突拒绝本次审核，不更改已有发布。

输出`alphalake-profit-asset-scope-v2`包含标准组成、每报告一次的源记录引用、原生五项消费金额对账、机制观测、算术核对及`asset_boundary`。金额为元，原生值为百万元；`cross_holdings`按既有五项已知小计代理对账，仍列缺失组成，匹配不冒称完整资产。冻结v1按原提交复验，当前不保留旧格式回退。

报表EBIT分别与“利润总额＋利息支出”“利润总额＋财务费用”“利润总额＋利息支出−利息收入”核对，报告TTM及每个累计期间的残差和源float32舍入界限。它们是明确列出的算术候选，不是推断出的供应商公式或经营范围认证；累计差额抵消不算各期均闭合，已知利息成分不重复扣除。合并权益另核对父级与少数权益之和。少量反例不扩成新个股政策，不新增准入阻断。

`observed_pairs`只表示所列资产／收益非零或缺组成。未观测、全零、缺项和反向收益分别保留；不存在“配对非零即重复计价”“未配对即没有业务”的结论。程序不重算DCF、不自动生成新假设、不改主库／SQLite；原组成核验见[初轮记录](../history/profit-asset-scope-20261017.md)，v2见[现金／投资／套期验收](../history/financial-asset-boundaries-20261017.md)。当前冻结报告压缩归档，复验指定新的输出，比对后按派生清理规则压缩／退役临时副本，不覆盖旧证据。

### 现金重叠、投资组成与套期

`asset_boundary`单独报告以下事实边界，均不新增准入门槛或自动调整金额：

| 审阅项 | 输入／规则 | 不代表什么 |
| --- | --- | --- |
| 现金等价物组成 | 期末`cash_and_cash_equivalents − closing_cash − closing_cash_equivalents`按源舍入界限核对；任一缺项保留缺项，负余额单列 | 仅组成齐全且等价物明确为0时标明未报告等价物余额；不因主项等于现金部分就补出缺失0，也不由此认证所有交易性资产可加回 |
| 货币资金差额 | 期末货币资金减现金及现金等价物；正、负、缺项分别保留 | 不是受限资金、超额现金或可回收定期存款的自动估计 |
| 交易性金融资产 | 保留正余额、源零、负余额和缺项；同时核对原生现金及长期投资代理是否仍匹配来源 | `not_separately_projected`表示没有单独投影这一总项，不证明其未含在现金中、全部非经营或漏计同额价值 |
| 净敞口套期收益 | 用完整累计三项形成TTM，任一标准项缺失不补零 | 该行零／缺失不证明没有套期；实际套期还可能进入投资收益、公允价值损益、经营收支或其他综合收益 |

只有聚合投资／公允价值损益时，不能把它们与交易性资产机械一一配对；相同会计总项可以混合理财、权益投资、经营对冲及金融负债损益。原文可核验组成和排除重叠，但不能静默把PDF分量建成第二数值主源。不能使用“总项−权益法其中项”就声称剩余全是理财收益，也不能把投资收益现金流当应计利润替代。

[全范围及原文验收](../history/financial-asset-boundaries-20261017.md)已保留晶晨纯理财／结构性存款、安克混合套期和茅台金融兼营三类控制。现有API可通过显式投资输入做独立桥接敏感性；若对应收益尚未从经营预测排除，只能标记敏感性，不能称完整正常化估值或自动发布。未来正常化仍沿[成套契约](#显式共同口径交付)交付，不改变引擎及默认。

### 显式共同口径交付

**先复用现有完整API，不为这一步扩展引擎。** 经营利润、对应资产单列、税务与未来投入须成套交付；书面说明、原生完整请求、响应及共享审阅结果分别保存。没有经营拆分证据时保留原生条件和缺依据，不在数据库新会话中自动执行本节调整。接口可表达、公司经济依据成立和允许默认采用分别判断。

| 交付项 | 既有输入及处理 | 必须说明／核对 |
|---|---|---|
| 来源与条件利润 | 保存原`reported_ebit`，人工明确需要额外剔除的有符号收益；显式请求使用`raw_financials[*].ebit`，有prepared输入则同时核对实际消费的`prepared_ttm.financials.ebit` | 原报表值与条件输入分别留存，后者不称TDX报告事实；已排除项目不能再减；损失的剔除是减负数；权益法其中项不重复计算。普通利息、经营套期不按名称自动处置 |
| 未来经营路径 | 使用`valuation_assumptions.annual_forecast[*].margin/growth/tax`，或现有两阶段显式字段 | 基期EBIT变化不会覆盖已填写的未来利润率。需独立说明未来经营利润率为何改变、改变多少，不能把TTM收益率扣减机械永久外推；研发／租赁调整前后口径须一致 |
| 现金及投资单列 | 当前消费行的`cash_and_marketable_securities/cross_holdings`；实际行由年末／prepared路径决定 | 记录经营现金保留、收益归属、已计价资产及账面／市场代理；持股价值加一次。货币资金与现金等价物不简单相加；股权桥接市值不反用于账面资本 |
| 经营税务 | `macro_inputs.tax_rate_effective`与显式年度税率／终值首年税率；需要时用既有`research_tax`及NOL／融资入口 | 剔除免税投资收益后，原报表有效税率可能不再代表经营税率。保存原利润总额／税费，不改源税项来凑比率；公司税制及经营税率依据不足时只能作为条件，不能自动推25%或照搬源比率 |
| 再投资与终值 | 显式`annual_net_reinvestment`或已批准的年度／两阶段资本倍率，终值仍用既有`g/ROIC` | 总投入已含研发净投入，不另扣一次；投资资产不作为经营资本开支重复投入。增长、利润率、税、投入及稳态回报须同范围；账面资本的重新分类不自动生成未来投入或成熟回报 |
| 合并及诊断 | `consolidated_book_equity`保留真实合并账面数；少数权益单列，已有`annual_capital_evidence`给出资本敏感性 | 不为模拟经营资本而改来源权益；合并利润与少数持股范围须对应。当前引擎资本不单扣长期投资，相应历史ROIC／存量倍率仍待审，不能据此自动选择预测参数 |

其中`raw_financials`、`prepared_ttm`是**现有完整请求的显式输入**；本节不新增数据覆盖器或规范源值的第二套存储。非年末只改年度行不代表prepared基期已经改变；反过来，仅调整当前TTM也不能声称年度利润率已同步正常化。prepared来源声明和请求旁记录须保留原报表依据、补充人工条件说明，不能改金额却仍称未调整报表数。来源EBIT、条件EBIT及研发／租赁后的EBIT分别核验，不通过重写来源账面权益绕过范围限制。

同条件比较先固定证券、财务／股本、信息截止及SQLite／参考版本，再固定实际未来收入、税、再投资、WACC和终值；分别替换利润路径及资产单列，并记录完整输入差异。直接WACC、无困境控制的结果不能泛化到所有分支：如果采用依赖EBIT的合成评级、账面清算价值等，利润／资产变更可能同时改变融资或处置结果，必须另行归因与核对范围。

### 资本诊断与DCF的边界

当前M3/M4投入资本为合并账面权益＋债务−现金＋研发／租赁调整，不单独扣长期投资。若未来经营利润已剔除投资收益，诊断的资本分母尚不能称完整经营范围；已有只读`capital_scope_bridge`可并列显示“扣投资账面代理”的敏感性，不能宣称引擎已经采用。

**这不构成所有条件DCF的前置阻断。** 在完整未来收入／利润率／税率、总净再投资、折现和终值回报已经显式给定的路径中，FCFF直接消费未来NOPAT及总净投入，期初账面资本主要用于隐含ROIC等诊断。达摩达兰[增长原文](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/growth.htm)也区分已有资产回报与未来新增回报，不能把重算后的历史ROIC自动当未来回报。此边界不是历史资本无用；若依据其改选资本倍率、投入或终值回报，就会影响估值，必须明确另一个条件变更。

完整链路已用8个虚构输入对照核验，见[契约验收](../history/operating-scope-contract-20261017.md)：只改基期EBIT不覆盖显式未来路径；同期调整未来利润率改变FCFF；独立持股估值只改股权桥；研发调整不重复；源有效税率不自动代表经营税率。它们证明当前接口的取值和优先级，不认证公司预测或全球经营分类规则。示例请求及响应保存在workspace，可用现有`tools.review_native_policy.review_report`重放。

### 已有公司证据的条件交付

[权益法收益真实对照](../history/real-operating-scope-conditions-20261017.md)已按上述契约交付晶晨及安克：TDX标准权益法收益取完整累计三项，PDF核对为非合并联营持股，且期末持股已包含在现有投资单列代理内。显式条件只减这一有符号其中项，不再减上级投资收益、不追加同一持股价值；同时明确未来利润率条件、匹配研发／税务／投入及折现路径。亏损剔除提高经营利润，盈利剔除降低经营利润；只改基期、未来路径不变的控制保持DCF不变。

这是两家公司验证的人工条件交付，不是自动正常化规则或纯经营利润认证。其余投资／套期、公允价值及现金范围仍单列；账面持股不冒充公允价值，报表历史资本不冒充已重建经营资本。茅台金融兼营控制保留，不能将金融资产归为普通超额现金；未因该边界阻断已有条件API。后续同类交付复用已有完整API及本节清单，不增加公司代码覆盖或修改冻结算法。

### 待审批共同口径

若确需在引擎内输出完整经营资本／ROIC，最小拟议扩展为`RawFinancials.nonoperating_investments_book_value`：百万元报表币种、期末账面非经营投资，排除已扣现金，非`cross_holdings`市场估值；TTM取期末、不相加，历史诊断用对应期初。同口径采用后在资本分母扣一次，不改合并账面权益来源值，也不把总投资代理自动认证为非经营。研发／租赁调整仍各一次。

**该字段尚不存在，不能发送后据HTTP成功声称已经生效。** `None`须表示该经营分类未提供，显式0才是所选范围零余额；省略时保留现有默认行为及范围限制，不静默认证“没有非经营投资”。若批准实现，须同步数据字典、LTM／prepared余额传递、M3历史／期初资本、M4资本路径及对应展示／审阅，并验证固定未来路径下DCF不变、经营ROIC按新分母变化。当前不修改接口、分母或默认；是否开发独立于条件估值已能执行。

## 已撤销的接通特例

2026-09-26的两家公司政策同时改写现金、投资和EBIT，且专项分量缺失会把已存在的报表利润清空。2026-09-29删除其执行模块及包装入口，政策仅作[历史证据](../history/tdx-book-assets-v1.json)保留；[旧验收](../history/valuation-book-proxies.md)不再描述当前行为。主库和SQLite事实不变，新会话统一使用标准出口，旧结果按原版本复验，不混作价格更新。

恢复标准EBIT不保证估值更高、更低或更准确；它恢复统一、可追溯的数据基础。具体方法审核见[方法契约](methodology-contract.md#标准输入与方法复核2026-09-29)。
