# A 股自动化估值

目标是所有已发现的 A 股都有可解释的处理结论：完成条件估值、缺数据、缺政策或模型不适用。字段齐全不等于估值完成，不能为提高成功率将未知值补零。

## 财务就绪度扫描

```bash
alphalake valuation-readiness ./alphalake.duckdb \
  --period 2026-06-30 --as-of 2026-09-09T18:00:00Z > readiness.json
```

只读查询同一事务中的本地证券主数据和标准 ASOF/TTM 窗口，不读取 PDF 直算，不修改事实。分母包括本地已知、未退市的沪深北人民币股票，无标准事实或无唯一 TDX 身份也保留。ETF、指数、外币股票排除。证券身份有效日取信息截止的中国日期。

输出逐公司最新可用财报期、全部已审核字段窗口及源事实 ID、15 项核心字段缺项和汇总计数。核心检查覆盖收入、营业利润及利息/非经营损益、股本、现金、借款/债券/租赁/到期负债和少数权益；它是筛查契约，不是通用 DCF 的全部输入契约。未披露零仍缺失，核心齐全仍明确要求模型政策与市场输入评估。

`universe_scope` 明示：这是本地已发现集合，尚未与交易所完整名单对账；主数据名称/状态不是完整历史快照，不能据此声称无幸存者偏差的历史全市场覆盖。指定期间缺项不会静默退回上一份年报。

## 推进顺序

1. 建立真实证券分母、标准财务覆盖及缺项排行。
2. 将既有标准导出/政策校验/共享引擎接入批量任务，按公司隔离失败，保留成功版本及失败原因。
3. 增加普通非金融企业的通用、版本化假设规则和适用门槛；公司特有政策继续独立，金融企业不套普通 FCFF。
4. 根据实际阻塞补数据、行业映射和市场输入，做跨公司真实源验收，再扩增量调度。

扫描入口已实现；其余步骤按实际提交更新，不将计划记为完成。安克、茅台验收库只有两家公司，不能将其中的完整率当作全 A 股完整率。

## 独立刷新证券名单

```bash
alphalake sync-instruments ./alphalake.duckdb
```

复用既有分区主数据刷新与三节点重试，不下载日线。健康分区独立发布，分区失败使运行标为 partial 并返回非零退出码；失败诊断保留，不能把部分名单当完整市场。已有历史名单的保留和两次缺失确认规则不变。

## 批量运行已有审核政策

在 `valuation/backend` 下执行（使用已安装后端依赖的 Python）：

```bash
python -m tools.batch_valuate_alphalake /absolute/path/alphalake.duckdb \
  --period 2026-06-30 --as-of 2026-09-09T18:00:00Z \
  --policy batch-policy.json --output-dir ./data/batch_runs
```

`batch-policy.json` 包含 `policy_version`、`review_note`、`assignments`。`assignments` 按六位代码索引，每项包含现有完整 `policy` 和可选 `wacc_binding`，与单公司 API 契约一致。可将既有示例政策装入任务：

```python
import json
from pathlib import Path
policy = dict(policy_version='reviewed-2026H1-v1', review_note='仅已审核双公司，其他公司不外推', assignments={})
for code, name in [('300866','anker-2026H1-revised.json'), ('600519','moutai-2026H1-central.json')]:
    policy['assignments'][code] = dict(policy=json.loads(Path('../examples', name).read_text()))
Path('batch-policy.json').write_text(json.dumps(policy, ensure_ascii=False, indent=2))
```

批量命令直接调用与 HTTP 相同的 `evaluate`，无需启动 API 服务。先扫描本地分母，再逐证券导出同一请求期间/信息截止的标准数据；每份证券导出有独立事务，整批不是跨证券/跨库原子快照，应在同步完成后运行。

缺政策、缺项、错误身份/政策和执行失败分别列示。单公司成功结果继续保存在 `ALPHALAKE_VALUATION_RUN_DIR`（默认后端 `data/alphalake_runs`），按输入/政策/引擎版本寻址；每次批量尝试另存独立 JSON，保留失败记录。重跑会重新检查数据并重试失败，成功内容不覆盖；当前仍重新执行引擎，尚无计算缓存或守护调度进程。

这一步自动化执行已有政策，尚不自动生成全市场政策。双公司实际数据库试跑成功、默认测试覆盖重放、缺附注隔离和身份错配；它们不代表新增行业已经验收。

## 通用经营价值筛查

新增 `nonfinancial-earnings-power-v1`，API 与批量 assignment 均可使用，不绑定特定证券代码。政策示例：

```json
{
  "policy_id": "nonfinancial-earnings-power-v1",
  "approved_report_period": "2026-06-30",
  "scenario": "zero-growth-10pct",
  "review_note": "零名义增长、维持性投入等于折旧的经营价值敏感性；非市场目标价",
  "nonfinancial_scope_review": "需填写公司属于适用非金融经营范围的审核依据",
  "wacc": 0.10,
  "tax_rate": 0.25
}
```

自动读取并核验 TTM FN230/86/305/306/83/82/301，计算 `EBIT=营业利润+利息费用−利息收入−投资收益−公允价值变动收益−资产处置收益`。正收入、正 EBIT 且 EBIT 不超过收入才进入共享引擎。已知非零金融业务收入/支出或吸收存款字段拒绝；这些字段缺失不等于金融业务不存在，仍须显式范围审核，尚不自动全市场分配。

十年预测和终值保持零名义增长、当前调整后利润率、政策税率和 WACC，净再投资为零。它是“维持性资本开支等于折旧”的假设，**不是历史 FCFF 已闭合，也不是未来增长预测**。销售资本倍率在零增长下不影响结果。模型结果应等于 `EBIT×(1−税率)/WACC`，测试用这个独立公式核验。

输出状态为 `illustrative_enterprise_value_only`，与完整条件估值分开统计；每股值及历史 FCFF 仍为空。没有补零或隐式赋予现金、债务、少数权益、期权任何数值。套期经营影响尚未恢复、研发仍费用化、维护投入与税率/WACC均为情景；不能将此筛查结果当完整自动估值。生产 API 的真实安克标准链已通过，真实茅台因金融业务被拒绝。

## 深分页自动恢复

每页30条的全市场运行仍在5个大日期窗口发现后续页面停滞（首个为2025-04-01至2025-06-29第58页）。流程现在自动将该窗口二分后分别重新采集，直到可完整遍历，或细分到单日仍失败。父窗口原始响应与拆分诊断保留，父窗口部分公告不发布；只有成功子窗口获得检查点。单日失败仍计入运行失败，不用部分结果冒充完整目录。

已有 v4 成功窗口不受影响；旧 v3 仍不受信任。重放会先探测尚无完成键的父窗口，然后复用成功子窗口检查点；目前不缓存分割计划。回归覆盖真实重复页的单日拒绝、二分后的两子窗口完成、诊断保留及重放跳过子窗口。

最新全量2026H1包另含两对完全相同的证券行，原逻辑因此拒绝全包。生产解析继续保留全部原始行，协调阶段现仅合并完全相同的重复记录；冲突处理已进一步改为证券隔离（见后文），原包和五行真实裁剪回归保留。这不改变80个FN的语义或字段位模式。

## 通用每股 DCF 与历史规则预测

`nonfinancial-book-fcff-v1` 接受显式十年 `annual_forecast`，复用标准窗口校验与完整共享引擎，从 FN238、FN133、FN41/52/55/56/439、FN69 自动构造财报日股本、现金、债务和少数权益桥接。输出单独标为 `illustrative_book_equity_scenario`。非正股权剩余拒绝并要求困境/期权模型，不给负股价或默认为零。

其取舍必须逐项提供：现金回收率、经营现金准备、债务/少数权益账面倍率、额外稀释、附加索偿情景，以及明确“不转股”和“未分类金融投资不计入”。FN52 全额按债务代理；没有把未分类投资宣称为零，也不把附加索偿情景当成披露事实。它尚不闭合当前证券滚动、转债选择权及其他索偿公允价值。

`nonfinancial-history-fcff-v1` 进一步自动生成预测，模板见 [`nonfinancial-history-template.json`](../valuation/examples/nonfinancial-history-template.json)。规则为：

1. 读取截止报告期最近四季度内可获得的同季度收入同比，至少两组；每个历史源值也核对原始位模式、币种、季度期间和公告血缘。
2. 同比中位数加情景偏移后按显式上下限截断，作为前五年增长，第六至十年线性过渡到终值增长。
3. 从 TTM 调整后 EBIT/收入取得当前利润率，五年内过渡到当前值加显式偏移。税率、销售资本倍率、WACC及稳态ROIC仍由政策给出。
4. 自动生成完整十年政策，保存历史同比分量及源事实ID、观察中位数、截断后增长、生成政策和规则哈希，再走同一 DCF/股权桥接。

这是机械初始情景，不是研究预测；模板的10% WACC、25%税、3倍销售资本等都没有被称为全市场合理参数。操作人仍需审核非金融经营范围及配置政策；未自动分配给全部证券。历史增长样本不足、源位篡改、已知金融业务、缺股本/现金/债务及终值无效均拒绝。安克真实标准链已完成逐年现金流、终值和每股值的独立复算；茅台金融业务拒绝。跨公司新增样本验收和自动行业路由仍继续推进。


## 行业规则自动分配

批量政策支持 `industry_rules`：每条规则提供唯一可识别的 `rule_id`、来源 `source`、分类体系 `taxonomy_code`、精确的 `node_codes` 清单、`max_age_days`（1–366天）、审核说明 `review_note` 和完整的 `nonfinancial-history-fcff-v1` 政策。`assignments` 可以为空；已有公司专用配置优先。规则中的非金融范围与所有参数仍须审核，行业归属不会自动证明参数合理。

扫描同时输出数据库里的行业成员证据：节点、有效起日、最近实际观察时间及观察运行完成时间。只接受截止时点已完成或部分完成运行中实际写入的行业成员，不因另一体系成功就刷新缺失成员。匹配零条或多条规则分别记录 `blocked_no_reviewed_industry_policy` / `blocked_ambiguous_industry_policy`；过期、未来或未发布证据不能触发估值。命中的规则和证据进入批量审计报告，模型自身的金融业务与数据缺项检查仍生效。

迁移032新增最近观察时间/运行，首次观测不变；旧库仅为尚未关闭的成员从原始观察回填，绝不把迁移日当同步日。`sync-industries` 对再次看到的成员刷新时间，不刷新部分快照中缺席的成员。当前只保留最近一次观察，早于它的历史截止可能缺行业，**不支持完整历史行业回测**；如需历史路由，应增加不可变逐次观察日志。先通过 `alphalake init DB` 或写入同步命令应用迁移；只读扫描不会静默迁移。

离线回归覆盖未完成运行隔离、重复观察刷新而首次观察不变、部分快照不刷新缺席成员、行业匹配/过期/冲突/公司覆盖/坏日期隔离。该路由测试的行业成员为合成数据，财务输入为真实安克导出，尚不代表全市场行业配置或新增公司原文验收完成。

## 有限内存部署

全市场六期重放在本机约4GiB内存环境实测被 Linux OOM 终止（PID2416089）；数据库恢复后源事实仍为0，未把中断当成包完成。已根据内核证据将遗留运行7记为失败。外部强杀不能执行进程内终态回调，日常应检查 `status` 中长期 running 的记录，并核实进程是否仍存活，不能仅按运行时长断言失败。

支持驱动原生资源参数：`ALPHALAKE_DUCKDB_MEMORY_LIMIT`、`ALPHALAKE_DUCKDB_THREADS`。不设置时保留 DuckDB 默认；非法值在打开库时拒绝。低内存机器可先按实际空闲资源设置，例如：

```bash
ALPHALAKE_DUCKDB_MEMORY_LIMIT=768MiB ALPHALAKE_DUCKDB_THREADS=2 GOMEMLIMIT=256MiB \
  alphalake sync-financial ./alphalake.duckdb --latest 6
```

DuckDB 限制与 Go 的 `GOMEMLIMIT` 各管各的内存，二者都不是整个进程 RSS 的硬上限。中间计算可溢写，但不能溢写的操作仍可能明确报内存不足；需保留磁盘空间并根据实测调整，不能将上述示例视为全量导入容量保证。原始归档和事务回滚仍承担失败恢复，不能通过少导源字段来隐瞒容量问题。

## 一次刷新到估值

在 `valuation/backend` 下运行：

```bash
ALPHALAKE_DUCKDB_MEMORY_LIMIT=768MiB ALPHALAKE_DUCKDB_THREADS=2 GOMEMLIMIT=256MiB \
python -m tools.refresh_valuate_alphalake /absolute/path/alphalake.duckdb \
  --period 2026-06-30 --filings-start 2025-04-01 --latest 6 \
  --policy /absolute/path/batch-policy.json --output-dir ./data/refresh_runs
```

顺序是 `sync-financial` → `sync-filings --metadata-only` → `sync-industries` → `materialize-fundamentals` → 既有批量估值。证券名单由同步命令刷新；不另建常驻服务。可由本机 cron/systemd 定时调用此命令，尚未替用户安装周期任务。进程锁按数据库绝对路径保护同一入口的重叠运行，其他直接写库命令仍依赖 DuckDB 自身锁；不支持跨主机调度锁。

`--filings-end` 默认中国当日，`--as-of` 默认取本轮同步/物化结束后的实际时点，避免刚刷新的行业因晚于启动时点被误排除。报告期及对应审核政策仍须显式更新，默认六期回填不能保证任意历史报告期齐全。若使用固定 WACC 导出绑定，需显式给出与绑定一致的截止时点；此入口尚不自动刷新 WACC/行情参考，不会把情景 WACC 冒充市场测算。

每次运行保存独立目录：逐阶段日志、持续原子更新的 `run.json` 和批量报告。采集失败不阻止其他采集及缺项检查，但总任务返回非零；物化失败则跳过批量估值，避免将旧物化结果当作本轮成果。`completed` 仅表示命令执行完成，估值覆盖率仍看批量报告，全部公司被阻断也不能称为估值完成。

单阶段默认上限3600秒，可通过 `--stage-timeout` 按真实市场规模调整；超时先发送中断、等30秒后才强制结束，退出码124保留。SIGTERM/交互中断记录取消。进程被系统强杀时只能留下 running 的审计记录，须结合实际进程状态诊断。离线检查覆盖采集失败后继续检查、物化失败阻止估值、逐阶段日志保留和真实子进程超时结束；完整市场流水线的在线验收仍在推进。

财务同步每个失败包现在立即输出包名和具体错误，失败计数和最终运行状态仍保留；因此长批次后续下载期间也能定位前一包的失败阶段，不必等待只含首错的终场摘要。

容量复现进一步将失败定位到 `provider_record_resolution` 的逐条 UPSERT；现改为标准库 JSON 参数加单个 `INSERT SELECT ... ON CONFLICT`，仍在同一事务发布，既有人工确认保留/重新解析后清除的规则不变，重复原始代码明确拒绝。新增6000条记录、128MiB DuckDB限制下的写入与重放回归。

另以真实全包数值、合成证券ID做独立容量诊断（不能作为真实证券链验收）：约324万源字段在768MiB限制下于事实合并失败；1024MiB、单线程下写入成功，用时约44秒，峰值RSS约1.93GiB。生产全市场回放正在按新配置继续；这些容量试验不替代真实身份解析、公告关联或估值验收。


## 重复记录的冲突隔离

真实运行已导入五期、16,061,752条源字段；2025年报中300750两行只在FN337冲突，原先因此整包失败。现在保留原始替代值、将该证券整体标为待解析，让其他证券继续发布；不选择13.67或30中的一个，不将冲突列补零。待解析仍阻止包完成检查点，CLI 对存在待解析或主数据分区失败的 partial 同步返回非零退出码，便于周期任务发现问题。

迁移033提供 `provider_conflicts_asof`，按源观察时间选择同证券/报告期最新已观察记录；历史源事实仍保留。扫描和导出增加 `source_conflicts`，批量及单公司正式入口都阻断仍有冲突的证券，不能因为旧版本字段齐全而回退旧值宣称完成。新版本真正恢复无冲突状态后才解除其后时点的阻断。扫描范围与导出一致：目标报告期前一年的1月1日至目标报告期。

当前按证券隔离，即使冲突发生在未审核字段也不将该证券交给模型；逐字段共识尚未实现。真实四行裁剪包验证隔离、无检查点、归档重用和重开，合成后续观察验证时间边界，真实安克旧完整输入上的负向测试验证 API/批量不得绕过质量门槛。


## 行业未知成员与部分发布

真实全市场申万快照包含无法在同轮证券主数据中解析的 `sz300728`（X150202）。此前整个体系因此回滚。共享分类写入现在记录 `classification.unresolved_member` 诊断，发布可确认成员，并将该快照视为不完整：**不关闭任何既有成员区间，也不刷新未观察到的成员**。行业与概念两路都将运行标为partial，命令非零退出；`synced` 计数表示有提交，可能同时有该体系的不完整诊断，不能与failure计数相加理解为独立集合。

严格的身份歧义仍回滚整个事务；源叶节点缺名称等构建错误仍拒绝该体系（本次另有TDX的T00缺名称），不伪造身份或名字。CLI逐个输出体系问题，而非只保留首错。旧归属在持续不完整快照下可能保持开放，因此行业政策仍检查最近实际观察与年龄，归属冲突继续阻断。

真实适配器输出裁剪覆盖未知成员诊断、9个可确认成员发布和扫描可见；它不是原始协议文件回放。另有128MiB下6000成员和未知成员的重复刷新回归，旧归属保留由独立区间测试锁定。现有主数据不匹配的原因尚未推断。

本次年报补入3,246,456条，六期累计写入19,308,208条源字段；其余五包按已验证检查点跳过。年报仍因300750冲突保留1项待解析、无完成检查点，命令如实返回partial。全市场公告的日期细分采集继续运行，标准事实完整率与新增公司估值尚待后续实际物化/验收，不将源字段总数当估值覆盖率。
