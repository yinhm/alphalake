# ADR 011——年度与 TTM 的公告时点查询

状态：已接受，2026-09-06。

## 决策

迁移 020 增加两个 DuckDB 表宏，直接组合已有标准事实，不再建立派生持久化表、缓存或计算任务。修正或删除标准事实后，下一次查询立即反映变化。

```sql
SELECT * FROM fundamental.annual_asof(TIMESTAMPTZ '2026-09-06 00:00:00+00', 2025)
WHERE provider_code='002920';

SELECT * FROM fundamental.ttm_asof(TIMESTAMPTZ '2026-09-06 00:00:00+00', DATE '2026-06-30')
WHERE provider_code='002920';
```

目标期末仅支持 3/6/9/12 月最后一天；非季度末返回零行。年度宏使用自然年度的 12 月 31 日。先通过 `fact_asof` 选出给定公告时点各报告期的可用版本，再组合，禁止先用最新版本计算后倒填日期。

## 三种期间

| 输入口径 | 年度 | TTM |
| --- | --- | --- |
| FN230–237 单季度流量 | 同年 Q1＋Q2＋Q3＋Q4 | 截至目标期末的四个连续季度 |
| 年初累计流量 | 直接取 FY | 上年 FY＋本年累计－上年同期累计；12 月直接取 FY |
| 期末存量，包括 FN238 股数 | 直接取年末余额 | 直接取目标期末余额 |

年度流量输出 `period_type='FY'`，TTM 流量输出 `TTM`；存量两种查询都标 `instant`，绝不加总股数或现金余额。FN86 累计营业利润与 FN231 单季度营业利润保持独立字段。

使用标准 DECIMAL 值计算，万元换算已在物化阶段完成。不会将全年值误当 Q4，不累加多个累计值，也不对最终总数再次进行 float32 舍入。

## 缺期、口径与血缘

输出中的 `coverage_status` 为 `complete` 或 `missing_inputs`。缺任何必要输入时 `value=NULL`，返回应有/实际输入数及 `missing_periods`，不返回部分和，不延用旧期末余额。

每个输入必须匹配证券、数据源、源代码、标准字段、源字段、报表范围、单位、币种及所需期间类型。该保守规则不跨不同代码或口径拼接。可见证券集合来自该公告时点、目标期末之前已存在的标准事实；应有字段来自目标期末有效的已审核映射。因此该查询不能统计完全没有标准事实的证券，也不是全市场覆盖率。

`input_periods`、`input_coefficients`、`source_fact_ids`、`source_filing_ids` 按相同顺序排列；缺失位置的 ID 为 NULL。系数为 1 或 -1。`latest_input_announcement_time` 是已找到输入中的最晚公告可用时间，缺期时不代表结果完整可用。原始归档、源版本和规范化规则可通过事实 ID 继续追溯。

“完整”仅代表当前 38 个已映射字段的窗口输入齐备，不代表通用 DCF 就绪，也不证明抓取前的系统观察历史。沿用前述 ADR 的零值歧义、未知历史和估值调整约束。

## 验收与升级

- 合成回归覆盖跨年四季、累计差额、存量、年度、缺中间季度、尚未披露、未来更正、输入血缘、单位不一致及非法期末。
- 真实验收覆盖两家公司 2025Q1–2026Q2 连续六季度、38 个财报原文金额；四季加总与独立累计差额交叉复核，并覆盖 H1 公告边界和重放。
- 去掉缺期空值保护后，缺一季的部分和被回归测试捕获。

已有数据库执行 `alphalake init DB` 即可增加宏，不改变已有源事实或标准事实，也无需重物化。完整输入缺失时，仍需按现有采集与物化流程补齐数据。本轮真实样本及覆盖矩阵见[样本说明](../../internal/ingest/testdata/ttm-2026/README.md)。
