# ADR020：官方定义批量映射与规范三表快照

## 决策与依据

用户明确要求：最大化复用TDX原始落库数据，取得指定报告期、指定信息时点的规范化三张表；未明确审核的记录原因，统一单位。官方已明确的定义可以作为标准映射依据，逐字段PDF金额核验不再作为全部接入的前置门槛。此约定已写入AGENTS.md。

依据为已归档的[官方专业财务数据项](https://help.tdx.com.cn/gspt/docs/markdown/redword/Profinance/profinancedatalist.html)、[官方量化字段说明](https://help.tdx.com.cn/quant/docs/markdown/TdxQuant.md/mindoc-1h10m001ic888.html)及专业财务默认单位规则。双目录差异、SHA256与portfolio参考的credit继续保留，见[交叉核对](../history/cashflow-reconciliation-review-20260919.md)。本轮不重新下载PDF，不以目录名称冒充逐公司财报审计。

## 完成度口径

源目录共584位置：461项官方定义、1项参考定义、122项未知。当前三张表及其现金流补充资料共283个源位置：

| 范围 | 位置数 | 已映射 | 未明确 |
| --- | ---: | ---: | ---: |
| 资产负债表 | 126 | 123 | 3 |
| 利润表（含单季度与每股收益） | 68 | 68 | 0 |
| 现金流量表主表（含单季度） | 60 | 60 | 0 |
| 现金流量补充资料 | 29 | 29 | 0 |
| 合计 | 283 | 280 | 3 |

三表标准映射280/283=98.94%。两个同名贷款位置合并显示一项待消歧业务名称，因此快照有282行，而非283行。其余179个已命名位置属于股本股东、来源比率、来源TTM、预测、快报、日期、代码及其他指标；其中总股本已是标准事实，原其他178项当时保留来源观察；现已[补入其中65项](../history/tdx-supplementary-fields-20260925.md)，不混入三表金额。加上总股本，本轮历史交付为281项，当前总标准字段346项，较schema49新增124项；不能用281/462代替三表供给完成率。

三处待审源位置仅在此源维护说明中标识：71“非正常经营项目收益调整”的期间不明；440与453均为“发放贷款及垫款”，缺少变体消歧。查询使用通用名称，值为NULL并注明原因。122个未知位置不编造报表归属。每个源位置的处理结论保存在统一`catalog.csv`，并随`fundamental.source_field`入库，不维护第二套待办词典。

此完成率表示目录覆盖，不表示每家公司均披露所有行业专属项目，更不把横线/源零当作真实零。两家公司真实包回归只能证明相应样本链路，不冒称全市场逐公司原文审核。

## 数据层与单位

原始ZIP保留完整float32位和原始数值，`source_record`仅保存定位与解析身份。`source_field`保存三表归属、分区及审核状态；`provider_field`承载审核映射，`field`保存通用定义。schema52按[宽表切换](../history/financial-storage-cutover-20260925.md)从`statement_snapshot`查询标准金额，源位核验回读ZIP，不再复制源数值或持久化标准长表。

- 金额规范为人民币元（`CNY`）：万元编码在物化时乘10000，普通金额乘1。
- 股数规范为股（`share`），每股收益为元/股（`CNY/share`），每股值不得再乘万元或当成金额求和。
- 源位所含的精度不恢复成PDF小数；DECIMAL输出是源编码的规范化表示，不代表额外会计精度。
- 期末余额为`instant`；年初累计为`ytd`；明确单季度为`quarter`。现金期初余额新增`opening_instant`，报告身份仍是当前报告，实际余额日明确为前一年12月31日。
- 每股指标和期初余额不参加普通年度/TTM聚合；三表快照可查询这些原报告观察。当前`annual_asof`/`ttm_asof`继续只供可加总流量和期末存量，不伪造每股TTM。
- 现金流补充项单独标记`supplement`；处置损失不是处置现金，间接法总额不与主表总额相加。新旧报表格式、合计与明细分别保留，不自动相加成总计。

新124项均为`official_mapping`，表示官方定义审核，不是公司金额逐项PDF认证；原157项保留`reviewed_mapping`及既有样本依据、准入日期和零值政策。新映射按官方当前源语义解释已有历史包，生效下界1900-01-01只代表不人为限制报告年份，不是官方发布日期或历史版本逐期认证。其中19项资本分量现按下述显式审核扩展历史区间，其余原审核有效期不变；快照对超出映射有效期的值明确阻断，历史版本可比性仍需按用途核验。

新增映射全部拒绝歧义零，已存在的允许零规则不扩大。未审核、无公告关联、不完整或有冲突的数据不得绕过标准事实成为可用数值。供应商默认报表范围保留为`provider_default`，不声称所有证券均经逐公司合并范围审核。

## SQL与CLI

```sql
SELECT statement,section,field,value,unit,period_basis,balance_date,status
FROM fundamental.statements_asof(
  TIMESTAMPTZ '2026-09-19 00:00:00+00', DATE '2026-06-30', '300866'
);
```

```bash
go build -o /tmp/alphalake ./cmd/alphalake
/tmp/alphalake financial-statements workspace/auto-valuation-20260909/market.duckdb 300866 \
  --period 2026-06-30 --as-of 2026-09-19T00:00:00Z
# 明确请求血缘时添加 --include-evidence
```

SQL宏直接消费标准公告时点事实；CLI返回`alphalake-financial-statements-v1`结构化JSON，分为`balance_sheet`、`income_statement`、`cash_flow_statement`，附逐表状态计数。报告期和信息截止必须显式提供；余额、累计、单季共同展示各自期间标签，不自动互相替代。

默认使用通用字段名、十进制字符串，不暴露来源编号。显式证据模式返回独立`source_evidence`，包含事实、源事实、公告ID与来源修订；大整数ID不经过float64。后续可用这些ID追溯不可变归档。

`available`仅表示匹配当前标准映射且在截止前可用。无公告关联或尚不可用显示`no_linked_source_at_asof`；可见源零显示`source_zero_ambiguous`；有非零来源但未物化显示`not_materialized`；有效期外显示`mapping_unavailable_for_period`；语义损坏、源冲突及身份未知/歧义均显式阻断。没有标准事实的公司也保留282行及拒绝状态。当前时点规则沿用公告可用性，不宣称下载前的系统历史已留存。

## 验证及发布

真实安克、茅台六期裁剪包经过原始归档、身份/公告关联和物化。新增124项产生194条非零事实、1,294个歧义零拒绝；逐源位与倍率检查所有新增值；三表每公司282行，原事实不变。错误倍率导致整批撤除、恢复重建、重开零变更重放均通过。

独立边界回归覆盖公告次日、更正时点、无身份、身份歧义、最新源冲突、错误单位及大整数ID。官方归档回归逐编号检查标签，并对三表已映射项检查元/万元和每股单位。

本地主库接入、实际CLI、重放与回归结果记录在[接入收据](../acceptance/official-statements-20260919.json)。旧版本不增加兼容分支；一次性接入先备份，完成原内容比对与重开后轮转旧备份。标准报表供给与估值适用分开，本轮不更改达摩达兰公式或预测政策。

代表性单位抽检另核对安克三期9个当期值和9个比较列：基本EPS按四位、稀释EPS按两位进入源float32，而PDF均列四位；2026H1稀释EPS原文3.1270、TDX约3.13。这是样本精度发现，不推成所有公司通用舍入规则；[证据与重提取命令](../../internal/ingest/testdata/official-statements-2026/README.md)已进入CI。

全套回归暴露既有就绪度查询在281字段目录下超过128MiB测试上限。根因是固定128证券批次聚合的字段数增加；共享入口已将批次降至64，保持原内存上限、全部字段和大整数血缘，不通过删字段或放宽测试解决。

本地主库本批4,039,052候选中新增527,086事实、拒绝3,511,966；既有3,876,699事实零更新、零删除，接入后4,403,785。新增事实报告期从2024Q1至2026H1，各期证券分母见收据，2026H1为5,527。两份实际数据库均已重开，原157字段的安克、茅台、苏泊尔估值输入逐项一致；源事实核对行数及内容XOR摘要，其他业务表双向EXCEPT一致。21个分批重放全部零增改删，不把21批声称为单次全市场运行。

### 全量重放资源事故与验收边界

2026-09-19 11:37:36及11:50:02 UTC，两次默认全字段重放触发系统OOM，内核记录匿名RSS分别1,982,288与2,643,528 KiB；机器总内存3.8GiB。第二次设置的DuckDB `memory_limit=1536MiB`并非进程RSS硬上限。systemd随后停止同一tmux scope，11:51:33超时强杀bash、重启后的Codex及其工具进程。没有第三次新OOM，第三次退出是延迟清理。不得将这两次算作成功重放；上述21批验收仍是分批结果。

后续大任务必须在独立systemd服务中串行执行并核验`MemoryMax`，不能只调整DuckDB参数。当前验收采用1GiB硬上限、768MiB软阈值、零swap和单线程，DuckDB限256MiB；安克、茅台、苏泊尔实际三表CLI均已在此约束下通过复验。禁止删除WAL或未完成记录冒充恢复。上述为原失败记录；后续[工作集分批修复](../guides/fundamental-memory-20260919.md)已在1GiB硬限额下完成两次默认全字段运行，第二次零增改删，原子事务保留。

本轮Go全套、构建、vet、相关Python20项、工作流YAML解析及本地文档链接校验通过；Python依赖pypdf 6.17.0，通过uv临时环境执行，新增原文精度校验已加入CI。

## 资本分量历史区间审核（2026-09-27）

固定五家公司追踪发现，2024年资本分量大量缺项来自旧映射仅始于2025年，并非TDX归档没有数值。沿用官方定义批量映射原则，为19项增加`[1900-01-01,2025-01-01)`历史区间：借款、应付债券、租赁负债、一年内到期非流动负债、总权益、货币资金、现金及现金等价物、长期股权投资、利润总额、所得税费用、五项折旧摊销分量和三个现金流营运资本调节项。标准名称、单位、期间和倍率必须逐项匹配官方源目录；不匹配或与已有历史审核重叠即事务拒绝。

新增区间一律拒绝歧义源零，2025年以后的审核与零值政策保持原样。下界1900仍仅表示不人为限制年份，不是历史各版报表逐期认证。租赁准则变更、追溯调整及分量合计范围须按估值用途另审；五项折旧不能直接固定相加，现金流调节项也不等于已分类非现金营运资本。

新库初始化包含该审核；既有schema54使用显式离线副本重建（在已核验资源硬限额的隔离服务内，目标文件必须不存在）：

```bash
ALPHALAKE_WORKSPACE="$PWD/workspace" alphalake extend-capital-history \
  workspace/alphalake.duckdb /tmp/capital-history-candidate.duckdb
```

这不变更物理schema或标准字段总数，首轮映射区间由346行变为365行；2026-09-28另补六个余额字段后为371行。命令只复制已checkpoint且无WAL的源库，在未发布副本审核目录并沿用既有包级事务从原ZIP重建；成功返回也不自动发布。须比较原有数值、验证重放与资源门槛，再原子替换主库并重开验收。全目录单事务重建曾在本库触及512MiB DuckDB内存限额；副本方式将原子边界放在最终文件发布，不提高内存预算，正常同步的目录变更事务规则不改。失败副本不是可用快照，日志及校验结果保留。未关联公告继续拒绝，不扩大披露补采或估值预测权限。

首轮副本新增98,652值、原值零变更，最初61.916秒重建及3.578秒完整重放未过门槛；后续通过限定有效映射重建范围和批量公告身份解析达到门槛，已发布主库，见[性能验收](../history/capital-history-performance.md)。

2026-09-28复用同一审核入口扩展流动资产、流动负债、应收账款、存货、应付账款、交易性金融资产，共25项历史区间。六项均由既有官方目录确认CNY、倍率1、期末余额；不新增标准名称或估值分类。已有19项历史审核及全部当前区间保持不变，缺公告关联、歧义源零继续拒绝。真实2024年报ZIP六项金额及19→25增量审核已加入回归，见[余额历史验收](../history/capital-balance-history.md)。

2026-09-28再将归母权益独立加入历史审核，合计26项，映射372行；不是以总权益推导替代。真实2024包金额、25→26增量、撤销仅删除归母权益均有回归。主库重建及原生历史输入验收见[归母权益历史](../history/parent-equity-history.md)。
