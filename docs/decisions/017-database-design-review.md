## 1. 当前状态与目标职责

| 目标领域 | 职责 | 当前差异 |
| --- | --- | --- |
| `core` | 公司、证券、上市记录、交易所、时态外部标识 | 当前名为 `ref`；公司与 listing 关系仅限定样本完整 |
| `market` | 行情、公司行动、股本、交易日历、利率、汇率、融资事件 | 日历目前在 `ref`；日线保留证券级兼容结构 |

`reference.security_industry` 和 `reference.security_code_transition` 是外部证据观察，不等于已解析的核心身份或标准分类成员，暂不为名称整齐迁移。`ref → core` 后实际引用、序列、外键、查询宏和工具均须同步；历史迁移和冻结研究证据不批量改写。

## 2. 存储与分层

保留 DuckDB 和文件系统组合：不可变源文件由 SHA-256 寻址，`meta.artifact` 保存定位；TDX `provider_fact` 保留源 float32 位模式，`fundamental.fact` 保存审核映射后的标准值；`reviewed_supplement` 独立保存原文补充。DECIMAL 不恢复源精度。事实依据失效时重建或撤除标准投影，原始证据保留。

年度和 TTM 由标准查询派生，不另存一套手工维护宽表。政策、预测、经济分类假设及估值运行 JSON 与公司历史事实分开；保留既有 run ID、查询、比较和增量重估机制，不为“全部入库”增加结果数据库。

## 4. 自查发现与实施要求

### 4.1 字段映射的版本关联：导出修复已完成

`provider_field` 主键包含 `valid_from`，允许同一 FN 多版本。自查时 `valuation_export.go` 的 facts 查询没有按报告期限定映射，可能重复导出或关联错误倍率；未证明主库已经产生错误结果。2026-09-18 已修复为按标准字段及报告期半开区间关联，并在同一只读事务中检查 TDX 已审核目录的重叠区间。目录损坏时整个估值导出拒绝，不任取一条；物化原有的源事实映射重叠保护保留。

回归已覆盖同一 FN 两个历史映射、边界日切换倍率、同语义拆分前后完整导出一致和重叠拒绝。进一步绑定具体映射版本时，应采用内容或明确版本身份，不能用可修改行假装永久语义版本。

### 4.2 审核补充与审核依据版本

当前 `reviewed_supplement` 以代码、期间、项目、公告为键，相同内容幂等，变化内容拒绝。它防止覆盖，但缺少同一原文提取错误的正常修订／撤销路径，也没有独立审核时间和系统记录时间。后续需要保留旧记录、审核事件、替代关系与明确选择规则；不能手工删除旧行再导入。

镜像 PDF 的有效审核绑定目前保存于 `meta.validation_result.details`，估值导出依赖该记录。迁移到持久审核证据结构后再考虑清理诊断；不得把所有诊断都视为可删除日志。新结构须绑定公告、文档哈希及审核证据，支持撤销而不抹去历史。

### 4.3 报告主体与版本选择

当前财务按 `instrument_id` 组织，`fact_asof` 按证券、标准字段、报告期排序选择；没有把报表范围、币种等纳入分区。现有受限来源路径不能外推为多范围、多准则财务兼容。

目标关系为“公司／报告主体→报告版本→事实”与“公司→证券类别→listing→行情”。报告范围、期间、币种和会计准则应参与可比性和版本身份；集团、母公司及子公司不能仅靠同一个公司 ID 合并。A/H 两个证券不得重复累计同一合并财务。实际接入第二种报告范围之前完成粒度迁移，不要求本轮创建空表。

### 4.4 时间语义

分别保留报告期、业务生效日、公开可用时间、首次取得时间和系统记录时间。`fact_asof` 当前是按披露可用时间重建，不等于完整系统双时态；后下载包及后来审核不得宣称当时已留存。现有 JSON 运行快照继续保存当次实际消费的输入。未知时间不能用另一个时间字段填补。

### 4.5 市场层与约束

`ohlcv_daily` 是当前投影，`daily_observation` 保存采集版本，`listing_close_observation` 是限定上市身份报价；暂不强行合表。`share_capital` 的来源股本与 `share_count_observation` 的公司／类别、发行／库存／在外股数也不能互换。出口须明确使用哪一种口径。

listing 的场所／币种白名单、补充导入的六位代码和 CNY 单位是首批范围限制；扩展须随真实新市场证据和回归完成，不能仅删除约束。主键、外键和 CHECK 与应用层的身份区间、跨表血缘、批次完整性校验共同生效，不宣称数据库约束已单独覆盖所有语义。

## 5. 实施顺序与验收

1. 字段映射时间关联修复：多版本正向／歧义拒绝回归，单版本既有导出不变。
2. 审核版本与证据独立：同原文修订、撤销、历史选择、重放及错误审核拒绝；证明诊断清理不再影响正式证据。
3. `ref → core`、日历归属及风险参考拆分：使用新增迁移；空库初始化与旧库副本升级均通过；逐项检查身份、引用、导出及固定版本重放。不能直接编辑既有迁移冒充升级。
4. 公司报告与多市场粒度：在真实第二范围／市场接入时实施，验证不重复计财务／股本、不混币种与报表范围。

所有代码改动按 AGENTS.md 运行相关回归、Go 全套和构建；Python 消费变化运行对应回归。主库发布前备份、副本比较和关闭重开验收；设计确认不等于主库已升级。命名迁移不得无意改变估值数值。

设计整理后的第一轮已完成 4.1 的导出修复，无结构迁移；其他审核版本和命名迁移仍待实施，主库未升级。
