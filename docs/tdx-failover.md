# TDX 自动换节点重试

所有现有 TDX 协议入口已统一使用请求级故障切换：单个交易所代码分区、证券日线／GBBQ、分类文件或报表文件请求，**最多尝试三台不同服务器（含首次）**。连接失败也占一次；配置不足三台则最多尝试实际数量，不循环凑次数。整次全市场同步包含多个独立请求，每个请求分别计数。

## 连接与重试

`DialDefault()` 保留原调用接口，改为延迟连接：第一次实际请求才拨号，连接失败与请求失败共用三台预算，也能由已开始的采集运行记录错误。SDK 后台重连关闭，避免 SDK 与应用重试叠加。地址复用 SDK 内置列表，按上海、北京、广州、武汉节点组交错排列；这些是服务器地区，不代表交易所能力。成功连接保留供后续操作复用，失败才关闭并移动到下一节点。

SDK 请求返回错误时重试完整操作。北交所代码使用完整 `zhb.zip`／`tdxbjmore.cfg` 获取路径；分页日线、分块文件均从新节点重新开始，不拼接旧节点的半份结果。空代码分区和空报表文件也视为失败；GBBQ 无事件或其他允许的空结果仍由原领域规则处理。源标准化和业务语义校验保留在重试边界之外，不通过更换服务器绕过校验。

- 单次 TCP 拨号超时 5 秒，SDK 单帧等待 5 秒。
- 每台节点尝试使用 45 秒上下文预算；预算到期关闭连接，并等待当前 SDK 调用退出，可能另需当前帧等待结束。
- 调用方取消后关闭当前连接，不再尝试下一台。客户端关闭后不能再次使用。
- 一个 Client 串行使用一条连接，防止换节点打断同连接上的其他请求；需要并行时使用独立 Client。
- 可通过 Go API `DialHosts([]string{...})` 显式给地址及顺序；省略端口默认 7709，规范化地址／端口并去重。当前 CLI 继续使用默认列表。

## 失败记录

切换日志记录操作、节点、尝试编号、连接／请求阶段及错误；恢复日志记录成功节点与尝试次数。三台用尽后输出警告，并返回携带全部节点原因的错误，不返回半份结果。

既有采集流程把错误保存到运行或诊断表：部分市场失败时记录 `meta.validation_result` 并保留该分区旧数据；全部市场失败时，`meta.ingest_run.error_message` 也保留各分区的节点错误详情，不再只留下“无可用分区”。重试层不直接持有数据库，独立使用适配器时由调用者保存错误，日志仍会输出。

专业财务原有官方 HTTP 下载通道继续保留：行情协议三台用尽先记录协议失败，再尝试原 HTTP 通道，仍须通过文件大小与 MD5 核验。这不是第四次行情服务器连接；若 HTTP 也失败，最终错误同时保留协议节点与 HTTP 原因。其他协议请求没有这条财务专用后备通道。

## 验证

回归覆盖：连接失败计数、请求失败换节点、重复地址去重、最多三台、成功节点复用、丢弃失败的部分结果、关闭／取消后停止、错误保留各节点与阶段。真实本地关闭端口走生产连接路径，三台用尽后重开 DuckDB 核验 failed 状态及节点信息。并发安全通过重试相关 race 测试。

2026-09-09 真实默认连接验收调用生产 `InstrumentSnapshot`：沪市 27,911、深市 24,223、北交所 346 条观测，三个分区 Complete=true，合计 52,480 条；这些包含多种证券工具，不是股票数量。用时约 105 秒。北交所从首选节点失败后，自动在第二台 `62.234.50.143:7709` 恢复，日志为 `operation=codes/bj ... attempts=2`。结果与日志留在 `workspace/tdx-auto-fallback-20260909/`。本次验收取得并规范化真实主数据快照，未把该探测结果写入生产市场库。
