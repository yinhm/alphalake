# 工作目录与缓存约定

动态数据仅存放于项目 `workspace`（Python可用 `ALPHALAKE_WORKSPACE` 显式改根目录）；临时验证使用系统临时目录。代码、安装环境及冻结测试资料与动态数据分开，不把历史日期目录当作运行配置。

- `alphalake.duckdb`：唯一权威同步库。财务、公告身份、审核补充和已接入的参考数据在同一库内；达摩达兰原始工作簿另存 `damodaran/`，不是独立参考库。
- `tdx-cache/`：仅放 `gpcw.txt` 和直接落盘的 `gpcw*.zip`，不放对象目录、软链接或逐包JSON。每次按上游MD5和大小判断是否更新。
- `tdx/`：主库血缘引用的不可变原始证据；旧版本不覆盖，不参与日常手工缓存管理。
- `damodaran/`：按可识别的原文件名直接落盘，主库不可变证据文件追加12位内容摘要区分版本；无objects或哈希分层，行业名称映射保留在industry_lookup。
- `eastmoney/`：业绩预告原始JSON按报告期／页码／12位内容摘要平铺，完整哈希记主库，不新增objects树。
- `derived/earnings-guidance/`：同步锁、证券范围、候选、运行收据及验收；候选和回滚库验收后清理。
- `cninfo/objects/<摘要前2位>/<完整SHA-256>.pdf`：巨潮PDF唯一原文；`cninfo/documents/<官方URL日期>/<公告ID>.PDF`仅为相对软链接，扩展名大小写沿用URL。相邻`.json`保存官方URL、哈希、原文相对路径和原始取得时间。公司、报告期、公告类型由主库目录及研究清单登记，不再按公司或研究批次复制PDF。
- `chinabond/`等：按真实来源归档；其他来源PDF不改称巨潮。必要的`views/`或文件名视图仅引用原文，不能另存一份内容；审核JSON和教学PDF不冒充公告原文。
- `valuation.sqlite`：网页消费的唯一财务发布快照，可重建，不是权威源。顶层仅保留它和主DuckDB；原始证据按来源归档，测试产物不写真实workspace。
- `research/<id>/`：正式中文研究报告、论点、模型及最终结果；`research.json`登记后在`/research`及详情页读取，不提交Git。原PDF继续引用来源归档，既有冻结计算可显式引用、不重复写事实；临时计算与内部验收继续用derived。见[研究交付契约](research-delivery.md)。
- `derived/system-delivery/`：发布候选、回滚副本、排他锁、当前`.delivery.json`和`.publication.json`，逐轮日志在`run-*`；`derived/valuation-runs/`保存仍在保留范围内的不可变估值运行，过期记录可按下述规则退役。`derived/archives/`只保存仍有用的人工条件、研究及紧凑输入；`derived/cleanup-audit/`保存迁移／删除清单及ID映射。
- `knowledge/`：词条编辑稿及 `knowledge.sqlite` 阅读库，独立于财务事实和数值参考；不随代码提交。词条 schema、只读 API 与构建命令见[知识库契约](valuation-knowledge.md)。
- `derived/pdf-cache/`：跨语言逐URL锁及一次性归档迁移收据；不存第二份PDF原文。

## 缓存行为

服务器不可用时可显式[完全离线同步财务](tdx-offline-sync.md)：`sync-financial workspace/alphalake.duckdb --offline --all`，不会等待网络重试。

财务同步先读取本地清单，再轻量检查上游清单。上游失败时可复用本地清单；来源身份刷新失败但已有证券身份时，保留并使用已有身份，不创建猜测身份。所有回退写入 `financial.local_cache_fallback` 诊断，CLI输出 `cache_fallbacks`，运行标记partial。

每个包按MD5和大小核对，优先复用已归档证据或本地缓存。上游新包下载失败，可使用主库归档哈希验证过的旧缓存；该次只处理实际缓存版本，不把新MD5写成完成检查点。清单与包版本可能不同，主库血缘绑定实际内容；不能凭文件名或修改时间认定最新。缺文件、损坏或未能验证的缓存不会变成空事实。完全离线模式保留原清单校验值，并直接核验缓存；只有匹配清单或已有同包历史SHA-256收据才放行，不用本地重算MD5替换预期值。文件名/包头报告期不一致及零原记录包拒绝推进检查点。

清单和包都通过现有上游hosts策略访问；没有HTTP后备或自建分段重组。原始文件、首次取得记录和被历史事实引用的版本保留。缓存文件先写临时文件再替换，失败不删除原始对象。

### PDF归档与引用

下载前持有同URL锁，依次检查已登记的健康源版本、共享URL收据和已知哈希对象；通过哈希、路径、大小及PDF头校验的本地原文直接复用，不依赖某个旧文件名是否仍在。Go公告／股本／融资参考与Python经营研究共用这套缓存。损坏内容不得当作成功；只有缺少合格原文时才下载官方PDF。同URL并发查找、下载和登记须在同一个锁内完成。

官方URL日期、报告期、原始取得时间和本次复用时间分别记录。复用不改首次取得、不宣称上游最新；无法恢复的原始取得时间留空，不从文件时间推断或靠重复下载制造。主库原始取得记录必须明确的导入路径保留此缺项，不重复请求。

Python下载或导入复用`data_sources.cninfo_documents.document_lock`、`read_reference`和`publish_reference`；调用发布方法时必须持锁，已有源哈希必须匹配。输出使用收据的`local_path`和`sha256`；页码、标签、报告期及采用依据写在本次派生证据清单中。新故事使用`narrative-valuation-v2`，在`manifest.pdf_references`登记原文引用，报告直接链接归档；运行目录不复制PDF。验证引用的原文缺失或篡改时拒绝，不以研究目录副本掩盖。

## 清理与迁移

不可变来源证据、有效审核记录和已引用源版本保留；回滚副本在重开验收通过后清理，留下路径、哈希及原因。派生候选可重建不代表可以删除其不可重建的审核依据。用户已授权清理过期派生数据，冻结过的旧运行也不自动永久保留；禁止永久保留多个权威库、按日期重复同步目录，或向代码目录写运行产物。

清理先核对正在运行的服务、当前发布收据及文件引用，按实际用途处理，不按修改日期批量删除：

- 内容相同的不可变PDF和冻结结果可在同一文件系统共享硬链接；须核对SHA-256、大小和访问权限，保留原路径及去重清单。更新必须写新文件后原子替换，不原地改写共享内容；活动数据库、缓存、配置和发布控制文件不参与此类去重。
- 当前发布验收需要保存完整依据时，复用`tools.publish_native_valuation.archive_check`压缩，流式逐文件核对哈希后删除展开副本。已被替代的验收批次可清理完整响应，只保留仍有意义的条件、摘要、失败结论和退役清单，不把所有旧响应压缩成另一个永久大仓库。
- 已被新发布替代的候选库及回滚库，在核实当前版本可读、编辑稿及验收依据仍在后删除。当前发布收据、证券清单和锁必须保留；与源登记或有效审核无关的重复财务快照、过期估值记录及已结束研究可以退役。估值记录压缩保留typed输入、政策及结果时可撤除重复源事实，但必须注明无法按原run ID逐字节重放，不能冒称完整原请求。
- 近期人工故事、论点和独立模型保留；不再直接使用的研究按原路径归档必要输入及解释，逐成员核验后删除展开目录。PDF只留源目录原文和恢复映射。复验可恢复的历史运行时，在隔离临时workspace解包、恢复引用并使用原提交；已退役的完整响应不承诺重放，不给当前运行时增加兼容路径。
- 大规模哈希或压缩串行放入独立、已核验1GiB硬上限的服务；清理后核验权威库、发布库、KB及TDX缓存内容，检查网页服务，并按唯一inode统计实际磁盘占用，避免把硬链接重复计为多份数据。
