# 财务存储与导出的性能基线

当前结构为原ZIP＋轻量记录定位＋标准宽表；不持久化重复源BLOB、源位值或逐字段源长表。完整架构见[数据分层](../design.md)，旧原型和改造过程见[历史方案](../history/financial-storage-redesign-20260925.md)。

## 固定数据集与验收


固定本机、单线程、1 GiB 进程硬上限；冻结本地全部已到期包、身份目录、可选CNINFO元数据和映射版本。区分缓存校验、解压解析、源写入、标准物化和导出各段；每项至少三次，报告中位数及最差值。读取分别测进程冷启动和进程复用，未清页缓存不得称冷磁盘。

以下为早期规模下的参考目标，并非全部已经实测的基线，也不是固定发布上限。数据范围变化后应建立新基线，不以超过旧秒数单独判定回退或阻止发布：

| 工作负载 | 早期参考目标／保留约束 |
|---|---|
| 当前全部已到期缓存源入库 | ≤60 秒；无逐字段持久化 |
| 全量标准物化 | ≤60 秒；保留全部拒绝分母 |
| 单期更新＋受影响标准重算 | ≤5 秒 |
| 相同输入重放 | ≤3 秒；源/标准数值及拒绝内容零重复写入 |
| 单公司完整历史标准查询 | 复用进程≤100毫秒，冷进程端到端≤1秒 |
| 沪深全市场默认10年/8季 SQLite 财务导出 | ≤60秒；含输出落盘及验收；无逐公司子进程 |
| 财务数据/索引/诊断的当前工作集 | ≤对应全部版本解压源体积的3倍，争取2倍；整库其他域另列 |
| 资源 | 全程RSS≤1GiB；失败/取消不得破坏已发布数据 |

对照必须使用相同证券、期间、版本集合与输出字段。缓存只有当前版本而主库含更多版本时，补齐分母，不用删历史得到漂亮比值。压缩旧审计证据可移至 workspace 的归档文件并用哈希/清单引用，但必须计入总存储报告，不能隐藏转移量。总耗时随合理工作量增长不视为问题；比较每秒记录/字段/字节、单位数据体积及峰值内存，区分解析、数值写入、诊断、落盘和校验。旧实现因错误门槛跳过的数据不能当作等量工作。缺可比旧测量时明确尚不能判断回退，不凭旧秒数或数据量比例直接下结论。证实不合理退化后再剖析和优化；不得牺牲正确性、证据、幂等或资源安全换取速度。

2026-09-29用户进一步明确：原来的基线不是硬限制；此前schema56/SQLite v9的单次例外记录保留为历史，后续不再需要因超过旧秒数请求例外。当前数值从845.88万增至1,932.57万（2.28倍），宽行从50,592增至176,504（3.49倍）。139.71秒测量是完整范围规则重算并新增1,086.69万个标准值，不是日常下载或无变化同步；同一扩大后工作负载本轮从260.54秒优化至139.71秒。重放3.28秒且数值增改删为零。没有旧版本相同完整工作量的可比测量，不能断言耗时变化完全由规模解释，也不能据此认定回退。

正式性能对照至少三次；日常功能发布无需为赶固定秒数重复全量重建。当前1GiB进程硬上限及失败不得破坏已发布数据仍是安全约束，不能随基线调整而放宽。组合流程时间不能替代单独导出基准。当前测量与后续工作见[项目状态](../implementation-status.md#性能基线与观察)。

## 实施纪律

按证券、期间和所需标准列批量读写，先裁剪再展开；共用连接及事务，不逐公司启动导出进程。报告元数据按报告/记录保存，不逐字段重复血缘或诊断。重放按内容变化判断失效，失败或取消保留可信发布与检查点。

复验不得借缩小样本替代全范围性能结论。已完成的小批或某一阶段只能说明该范围，后续结构变更仍需用同一真实数据集测入库、重放、查询、整批导出及峰值内存。运行方式见[内存隔离](fundamental-memory-20260919.md)。

已有测量：[存储切换](../history/financial-storage-cutover-20260925.md)、[物化内存](../history/materialization-memory.md)、[资本历史查询](../history/capital-history-performance.md)。当前数量与未完成项统一见[项目状态](../implementation-status.md)，不把早期原型速度或旧长表体积当成现行性能。
