# Investment_Valuation_Agent 原生数据适配：偏差审计与修正规格

状态：2026-09-24，审计及待实施规格。审计基线为 AlphaLake `aebfaa5`，本轮不修改运行代码、SQLite、8080 服务或估值方法。

后续执行进展：用户已批准按本规格推进，并允许明确BUG修复与必要后端API适配。原页面/请求恢复、已知错误映射修复及缺项诊断已实施；数据闭合仍被阻断，见[完整字段契约、验证与待审批方案](valuation-native-data-contract-20260924.md)。下文“本轮”保留为制定规格时的审计范围，不表示后续没有实施。

## 1. 目标及边界

本阶段目标是完善 TDX 等数据供给，经 AlphaLake 标准化后导出符合 Investment_Valuation_Agent 既有 SQLite 契约的数据，由其原有 Web 流程完成估值；程序也可经其原有 API 调用同一估值引擎。不是开发另一个估值前端，也不是让原项目迁就 AlphaLake 的专项模型。

- 前端不新增或改造页面、导航、输入流程、默认参数表单、来源分支、数据类型或请求契约。先撤销本地越界改造并固定前端基线，此后数据接入不得修改前端。
- JSON 只作为后端接口的序列化格式，不要求用户上传、编辑或理解政策 JSON。参数继续通过原有估值页面手工修改，自动参数供给为后续独立任务。
- 必须保持来源数据、标准事实、确定性财务派生、估值假设四者分离。假设可以使用原模型已有默认值，但不能将缺失的历史事实补成默认值。
- 本轮不重新设计 DCF，不推广历史增长研究规则，不扩大公司专项政策，不添加金融企业专用模型，也不为了产生价格而放宽缺项或金融业务边界。
- 对外部估值应用当前契约的格式适配是本次明确目标，不是恢复 AlphaLake 的旧版本别名、兼容运行时或静默降级。

### 当前 SQLite 并未达到原生财务契约闭合

实查只读快照 `workspace/sqlite-web-20260922/valuation.sqlite`，范围为安克创新、贵州茅台、苏泊尔，报告期 2026-06-30，信息截止 2026-09-22T00:00:00Z。

- 原财务宽表有 30 行年度、24 行季度，17 个财务数值列，共 918 个单元格。
- `export_cells`：219 个 available，321 个 missing_standard_fact，378 个 requires_separate_valuation_definition。
- 378 个来自以下 7 列在全部 54 行均为空：`ebit`、`ebitda`、`d_a`、`operating_lease_expense`、`cash_and_marketable_securities`、`cross_holdings`、`bv_debt`。
- 现有导出器只给 10 列建立标准字段映射，其余 7 列直接进入“待估值定义”。这不是证明 TDX 没有相关分量，而是目标定义及组装未完成。
- 三家公司的行情价格、市值、有效税率、信用评级、期权数量等快照列均未填充；缺失类型不同，不能统一归为 TDX 财务解析问题。
- `RawFinancials.ebit` 是非空必需输入，原数据库转换会直接构造它，因此现快照不能原样通过原生财务输入验证。额外长表和 `valuation_inputs.payload_json` 的存在并不补齐原生宽表。

219/918 只是此快照此导出布局的单元格可用数，不是三家估值完成率，也不是 TDX 字段解析完成率。已有“92.15 元”证明的是定制路径与指定政策可运行，不是原版 Web 的兼容验收。

偏差根因：将“符合原估值应用的数据供给”替换成了“复用共享引擎得到可追溯的条件值”，再用专用界面承接两种输入模型之间的差异。测试跟随新流程编写，验证了实现自身，却缺少未修改原客户端的契约测试。

## 4. 目标调用链

```text
TDX 等来源 → 原始证据 → AlphaLake 标准事实 → 已定义的财务派生
                                               ↓
                                原生字段、期间、单位的适配
                                  ↙                 ↘
                  兼容 SQLite 三张原表         原生 API 输入
                                  ↘                 ↙
                       Investment_Valuation_Agent 原有后端
                               原有估值引擎和响应契约
                                               ↓
                         原有 Web 页面、编辑与分析流程
```

原三表指 `companies`、`financials_annual`、`financials_quarterly`，不是 AlphaLake 的会计三张报表。附加证据/状态表可以保留，但原页面和成功估值不能依赖读取专用 `valuation_inputs` 载荷来绕过这三张原表的缺项。

API 优先复用 `/api/valuation/from-database`、`POST /api/valuation`、既有 PATCH 与分析/导出接口。输入使用既有 `CompanyValuationInput`，响应满足既有 `ValuationResponse`；不得要求新前端分支。已有 AlphaLake 专项 API 与历史研究保留证据，但不作为本任务的替代验收入口。

## 5. 数据契约工作

第一份实现交付必须是逐字段契约表，覆盖全部公司快照列、年度/季度 17 列以及必需参考数据，不能只列已有的 10 项映射。每项须写明：目标定义与实际消费者、标准来源、确定性公式、单位/符号、流量/存量、期间、空值规则、适用条件、血缘、验证样本。

以下是必须解决的问题，不是本次已经批准的公式：

| 字段或类别 | 接下来须核对的内容 |
| --- | --- |
| EBIT | 中国营业利润与原模型 Operating income 的组成差异；投资/公允价值/处置/利息等如何归类。不能直接套用公司专项的“调整EBIT”并伪装为原始 EBIT |
| EBITDA、D&A | 折旧摊销组成、使用权资产与原模型租赁调整是否重复；按期间审核分量，不重复叠加 |
| 租赁费用 | 当期费用、使用权折旧、租赁利息、未来承诺分别是什么；缺承诺不填0、不冒充已关闭租赁调整 |
| 现金及证券 | 现金、等价物、短期证券、受限及经营保留的边界；估值回收折扣不能写进历史余额 |
| 交叉持股 | 联营/合营、其他金融投资与现金证券的交叉；不重复加回，不能一律赋0 |
| 有息债务 | 短长借款、债券、一年内到期、租赁的包含关系与重复计量；需要的附注拆分缺失则明确记录 |
| 已映射 10 列 | 仍核对净利润/权益归母与合并口径、资本开支符号与现金/会计口径，不能因为已有映射就当作全部语义已验证 |
| 年度/季度/TTM | 年度累计与单季差分、FQ 偏移、年末同季、完整窗口和期末余额；不借 `prepared_ttm` 隐藏原历史表缺口，也不强行填满10年 |
| 行情与股本 | TDX行情与财务来源分开；未复权价格、价格日和对应股数、市值/金额单位，不能混用财报日与当前股数 |
| 行业、国家、币种和风险参考 | 对齐原 mapper/参考表识别，CN 与 China 等编码需有明确映射；保留达摩达兰版本和缺项，不能让匹配失败偷偷选择第一个行业 |
| 税率、评级、期权、分部 | 历史事实与假设分开；自动可得、当前用户填写、可选缺失、阻断缺失分别标记 |

先复用现有标准目录和派生能力；官方定义允许的映射可批量推进。不另建原始编号字典，不因网页需求改变标准事实定义，也不无期限追查单公司异常。

财务数值继续遵守纯 TDX 导出边界，PDF 不静默补数；行情可从已接入的行情来源供给。行业/国家/风险参考及用户假设是独立输入，不能写成 TDX 财务事实。新增外部来源或必须使用附注时，先明确缺口和范围，再单独安排。

## 6. 修正顺序和代码边界

1. **冻结契约与恢复清单**：锁定原前端版本、记录现有改动分类，逐项给出撤销/保留原因。保留原始证据、旧运行及方法审核，不整体回退整个 `valuation/`。
2. **完成数据契约与缺口盘点**：核对 17 列及公司字段，给出安克/苏泊尔/茅台每家公司每个需要期间的实际缺口；区分未映射、源缺失、源零歧义、期间缺失和模型不适用。
3. **完善数据与导出**：在标准派生及现有导出器补目标映射；不复制估值引擎。导出值与证据原子发布，重建副本并核对源库不变，不原地覆盖现快照。
4. **恢复原生后端流程**：适配 SQLite → `CompanyValuationInput`，原请求不带 `tdx_policy` 也能按原参数机制处理；来源搜索可在后端适配但保持响应结构。移除本任务专用旁路对原流程的接管。
5. **恢复前端并冻结**：撤销专用页、隐藏侧栏、专用政策表单和前端请求改造。这是恢复操作，之后不再为接入数据修改前端。编译/已有语义提示的差异单列处置，不暗中作为新功能保留。
6. **原会话交互与证据分离**：用户经原 PATCH 调整假设或填写输入不修改 SQLite 标准事实；覆盖值标记为用户输入。原会话可继续编辑，审计记录另存新版本，不把不可变 run ID 原样套在变化结果上。
7. **双路径验收与发布**：SQL 与 API 使用相同财务、参考和假设，经过同一原引擎，逐项对齐结果后再切换8080服务。当前新页面能计算不作为完成依据。

此前已经复核的数学修复应列入保留候选：无效 Gordon 终值/ROIC/资本倍率拒绝、历史税项缺失传播、按年度重建研发资产、真实财年间隔和期初资本校验。逐项确认原调用路径、测试和方法依据，不把它们与 UI 改造一起删除，也不以“恢复原版”为名自动恢复错误。
