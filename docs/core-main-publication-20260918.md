## 发布安全与复核

`cmd/check-core-publication` 只支持本次33/39→44。发布前固定基线／候选SHA，持有与刷新流程相同的文件锁及两库的 DuckDB 原生只读锁；校验全部通过后硬链接保留旧库，再原子替换候选文件并同步目录。新库与备份是不同 inode，后续写入新库不改备份。原生锁释放后，再从正式路径重开比较、查询状态及估值。

默认只读复核（会创建空协作锁文件）：

```bash
ALPHALAKE_DUCKDB_MEMORY_LIMIT=1GB ALPHALAKE_DUCKDB_THREADS=2 \
go run ./cmd/check-core-publication \
 workspace/auto-valuation-20260909/market.duckdb.pre-core-risk-20260918 \
 workspace/auto-valuation-20260909/market.duckdb
```

参考库用对应路径。后续正常同步改变数据后，该固定基线比较可以失败，应按新增内容分析，不回滚正常新数据。`--publish` 仅在本次发布时使用，要求两个已验收文件哈希，已有备份拒绝覆盖。历史 `check-cash-publication` 继续保留原限定版本的 `ref` 查询，不能拿它替代本次跨schema复核。
