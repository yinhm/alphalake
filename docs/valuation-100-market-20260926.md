## 可复用命令

```sh
# 只选指定证券的行情；未指定--symbols时保持全市场批量语义。
./alphalake sync-daily-all workspace/alphalake.duckdb \
  --symbols sh600519,sz002032,sz300866

# 导出器既有--code参数可重复；100家按冻结sample.json构造同一列表。
.venv/bin/python valuation/backend/tools/export_alphalake_sqlite.py \
  --database workspace/alphalake.duckdb --output /tmp/valuation-check.sqlite \
  --period 2026-06-30 --as-of 2026-09-26T08:34:05.989815+00:00 \
  --code 600519 --code 002032 --code 300866

# 对库内全部公司调用原生API；固定参数、保留失败公司与原始响应。
PYTHONPATH=valuation/backend .venv/bin/python -m tools.check_native_sqlite \
  --database workspace/derived/valuation.sqlite \
  --output workspace/derived/valuation-100/recheck --risk-free-rate 0.0425
```

执行日线同步/导出/Go检查时仍使用独立systemd任务，DuckDB内存1GiB、进程硬限1.5GiB、单线程；网页进程只读SQLite。重复证券请求只同步一次；指定但未找到的证券保留失败，不静默扩大为全市场。

新增验收工具保存每家诊断和原生响应，汇总公司分母、行情状态、准入及HTTP状态，并验证读取前后SQLite哈希一致；允许明确422，遇到意外HTTP错误或被阻断公司却估值成功则失败。15项相关Python回归及1项验收工具故障回归通过；筛选同步回归覆盖排除未选证券、去重及缺失请求拒绝。`go test -p 1 ./...`、CLI构建、gofmt及差异检查均通过；结果与发布/清理收据同目录保存。

发布后删除旧全量SQLite派生副本，保留路径、哈希和原因；主库保留同步前最近一份备份`workspace/alphalake.previous.duckdb`，没有重复样本SQLite。
