# 系统整理与自动估值交付

本轮目标：对沪深普通非金融企业，稳定更新标准数据、准备估值输入，并通过原 Investment_Valuation_Agent 网页/API 交付可复现的条件估值。金融企业专用模型、前端改版及逐个解决全部异常公司不属于本轮。条件估值成功不等于公允价值或预测准确性认证。

## 当前边界

| 层次 | 权威位置与职责 |
|---|---|
| 来源与标准事实 | workspace 按来源归档；唯一主库 `workspace/alphalake.duckdb`，包括财务和已接入参考数据；TDX 提供结构化数值，CNINFO 提供披露身份、时点及核验 |
| 估值输入 | 标准查询、财务派生和显式代理；SQLite 是面向原应用的可重建发布快照，不是第二权威库 |
| 模型与政策 | valuation 共享引擎计算；事实、代理、默认假设和用户修改分别留痕 |
| 应用 | 原网页/API、CLI、Skill 使用明确输入及政策；不同政策的结果不冒充同一次估值更新 |

现有 `refresh_valuate_alphalake` 是政策批量估值入口，不能将它的成功当成原网页快照已发布。`export_alphalake_sqlite`安全创建快照，`check_native_sqlite`逐公司验收原生API，新增`publish_native_valuation`已串联发布、恢复与变化比较；离线交付与最终查询改动的回归已通过实测。当前100家样本财务87家准入、13家缺项；参考升级后默认可计算86家，另1家因缺公司行业/国家分类要求显式选择；该数字不是全市场完成率。

## 本轮交付清单

完成必须附实际证据；以下保留完整交付范围，进度与实测列在文末，不以清单本身作为功能实现证明。

1. 文档收口：README 提供最短入口，实现状态只将当前能力称为当前；历史结果明确归档。同步原生导出文档和 agent 使用指引，不留下不同的操作路径。
2. 更新流程：复用现有采集与物化，默认仅沪深；参考数据使用主库；支持合格缓存及明确的离线模式。每阶段记录成功、失败、来源新鲜度和日志位置。
3. 快照交付：标准物化后批量导出候选 SQLite，进行完整性、范围、原生准入和计算验收，比较旧版本；验收失败不替换可信发布。
4. 恢复和重放：记录发布版本、源数据/程序身份及财务时点；失败可重试，异常终止可恢复；相同有效输入不重复发布，元数据时间变化不当成财务变化。
5. 输入与政策审计：追踪原生 API、CLI 至共享引擎的实际输入；列出增长、利润率、再投资、WACC、终值及股权桥接的来源和代理。相同模型及输入应数值一致，不强行统一不同政策。
6. 真实验收：固定当前100家公司及报告期；保留13家缺项分母。验收增量、无变化重放、故障保留旧快照和发布后原生 API；保留耗时、体积与峰值内存。先小批，再串行全批，不以网页静态资源200代替估值验收。
7. 后续范围评估：复用已有就绪度扫描进行轻量覆盖统计，不全市场重复运行DCF；按高频通用缺口安排下一轮，记录分母、期间、截止及主库范围。

## 发布约束

- 保持原前端和 `{ticker, risk_free_rate}` 请求；本轮不要求用户选择政策JSON。
- 原始事实缺失不补零。允许的现金、长期投资及多股类市值代理仍显示范围限制，不为发布率取消拒绝。
- 运行结果仅写 workspace/derived。失败记录保留，成功后清理可重建候选及过期回滚副本，证据不可混删。
- 主库写入、导出和大测试串行，使用核验过 MemoryMax 的隔离 systemd 服务；不新增复杂调度平台。
- 新鲜度与可用性分开：缓存可用于估值，但不得声称已核对上游最新版本。

## 原生网页交付入口

新增`tools.publish_native_valuation`复用现有同步、导出、API和共享引擎。它不改变原前端，不使用显式政策CLI替代原生API验收。模型默认与参考消费边界见[原生输入政策审计](native-input-policy-audit.md)。

输入必须明确：主库、发布目标、报告期、证券清单、来源模式、验收无风险利率，以及读取该发布目标的本地网页地址。清单每行一个六位代码；不能以成功公司反推清单。无风险利率是验收假设，不是自动采集的公司WACC。

本机示例（先确认8080读取目标SQLite、没有其他大任务在运行）：

```bash
systemd-run --unit=alphalake-native-publish \
  --property=WorkingDirectory=/root/alphalake \
  --property=MemoryMax=1G --property=MemoryHigh=896M \
  --property=MemorySwapMax=0 --property=OOMPolicy=stop \
  --setenv=PYTHONPATH=/root/alphalake/valuation/backend \
  --setenv=ALPHALAKE_WORKSPACE=/root/alphalake/workspace \
  --setenv=ALPHALAKE_DUCKDB_MEMORY_LIMIT=512MiB \
  --setenv=ALPHALAKE_DUCKDB_THREADS=1 \
  --setenv=GOMEMLIMIT=128MiB --setenv=GOMAXPROCS=1 \
  /root/alphalake/.venv/bin/python -m tools.publish_native_valuation \
  --database workspace/alphalake.duckdb \
  --output workspace/derived/valuation.sqlite \
  --period 2026-06-30 \
  --codes-file workspace/derived/system-delivery/codes.txt \
  --source-mode offline --latest 6 \
  --risk-free-rate 0.0425 --web-url http://127.0.0.1:8080
systemctl show alphalake-native-publish -p ActiveState -p ExecMainStatus -p MemoryMax
journalctl -u alphalake-native-publish --no-pager
```

上例为已固定100家样本；不随意更换清单，缩小分母必须作为单独范围验收。源码新增不等于该命令全部模式均已在线验收，具体结果见下面进度。

| 模式 | 实际动作 | 来源新鲜度 |
|---|---|---|
| `local` | 仅导出既有标准事实、验收和发布 | 不检查上游，不声称完成同步 |
| `offline` | 本地财务缓存源同步、物化，再导出验收发布 | ZIP核验合格不等于已确认上游最新 |
| `online` | 财务同步、限定清单的公告目录与行情同步、物化、验收发布 | 须查看来源日志及缓存回退，不能用进程成功代替最新性 |

在线模式另需`--filings-start`和可选`--filings-end`，默认结束日为中国当日；行情使用`sync-valuation-quotes`，只追加报告日前14个自然日至报告日的观测，不更新完整日线及检查点；身份来自已有审核快照并逐日期核对，不按证券代码前缀猜市场。见[窗口同步](valuation-quote-window.md)。首次建立新范围先用local模式验证导出与身份；公告目录不会自动审核缺失的招股披露范围或源零。

可选`--sync-references`同步既有六类参考及23份原生US/Global行业与国家税率工作簿，offline模式重放已注册归档。原生参考随SQLite v7发布，会话绑定参考内容版本；实际网页与候选结果不同会拒绝发布。全局没有安装定时器，也不新增常驻任务平台。

## 失败与重放

- 所有阶段串行；同步下载/主数据失败、物化/导出/验收失败均返回非零，保留日志，不继续发布。财务源仅因待解析记录返回非零时，必须通过结构化完整收据证明没有下载/主数据错误、选中包的待解析项在报告期能唯一解析标准证券身份、与导出目标身份不相交，才允许继续；来源仍标记partial，受影响包不推进检查点。主库各来源已提交的有效事务保留，不把整轮失败误解释为主库从未更新。
- 候选SQLite在同目录创建；验收核对完整分母、准入及实际计算。ready却计算失败拒绝发布；财务缺项与`blocked_reference_inputs`分别统计，两类422均保留。
- 切换前记录发布日志并硬链接旧文件，原子替换后逐公司核验真实网页诊断、实际输入及最终结果。不重启网页；旧会话仍是原输入版本，新请求读取新快照。
- 网页复验失败立即恢复旧文件；切换过程中被强杀，下次同命令先恢复未提交切换，再重新执行。日志不证明后台仍在运行，应查systemd单元。
- SQLite内容（含参考快照）、程序/依赖、冻结模型参考及请求均相同时，复用已验收结果；源库物理内容和二进制也相同时不再导出。来源日志等元数据改变可能需要重新比对，不强行跳过质量检查。
- 只有导出时间或主库物理哈希变化、有效内容未变时，不替换网页文件。信息截止不同仍属于新的输入版本，不能省略披露。
- 成功收据位于目标旁的`.delivery.json`，切换日志为`.publication.json`，逐轮日志与比较在`workspace/derived/system-delivery/run-*`。后端和冻结模型参考哈希记录在每轮`runtime-inputs.json`，源参考发布/哈希随SQLite携带，不将这些动态文件提交仓库。

## 下一轮产品目标

目标从“数据能进入引擎”转为“普通非金融企业可以得到输入可解释、默认假设可修改、结果可复现的条件估值”。不以剩余13家全部解锁、全市场跑出价格或贴近股价作为唯一成功标准。

1. **统一实际参考供给**：先打通主库参考版本→原生后端WACC输入，明确币种/无风险利率/ERP/行业Beta/债务成本/权重；行业待匹配时继续明确提示。保持原页面、单一引擎，不新建参考数据库。
2. **审阅预测输入**：在固定小样本上审核增长、利润率、销售/资本倍率的共同经济约束；事实、默认、公司政策和用户修改分别留痕。既有自动预测研究复用，不为让价格好看改达摩达兰公式。
3. **按决策价值补缺口**：区分已同步无值、公告范围未闭合、源冲突及金融行业模型不适用；优先可复用的研发披露/身份机制，个案和多市场另立边界。
4. **固定发布验收**：继续使用同一100家及核心覆盖扫描，追踪数值变化、拒绝原因、耗时与内存；达到稳定后才增加定时运行，不先建设调度平台。
