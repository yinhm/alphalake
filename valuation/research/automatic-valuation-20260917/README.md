# 增长—资本输入诊断与增量重估

本轮沿三条主线交付生产功能：已审核标准资产桥接见[第一阶段](../reviewed-assets-20260917/README.md)；本阶段把公司投入证据和经济一致性诊断接入统一输出，并在现有刷新/批次工具中实现增量重估。后续苏泊尔原文归档及受限资产分量已完成[真实副本验收](../reviewed-assets-20260917/supor/README.md)；安克公司倍率经[现有证据联合审核](../company-inputs-20260917/README.md#安克公司资本效率的审核结论)仍不批准，保持显式行业代理，不能称全部公司输入完备。

## 公司证据与增长、资本需求

通用账面/历史FCFF新增`method_assessment.growth_capital_consistency`。从TDX标准TTM查询读取FN304研发费用和FN114购建长期资产现金；沿用期间、单位、源位和血缘验证，缺项返回null。它们只作投入证据，不直接充当增长率或完整净再投资，也没有再次扣减FCFF。

两公司沿用2026-06-30财务、2026-09-10T04:42:23Z冻结标准请求，原条件值126.1378/43.2526元不变；不是9月17日新市场估值。新增公司投入分量通过标准窗口验证，不扩大为本轮逐公司全部原文独立审核。安克较高研发投入说明研发口径是需要审核的资本因素，**不能据此证明20%预测增长或某个公司收入资本比正确**。现有完整历史经营资本仍缺，不用未分类小计拟合替代参数。

逐年输出增长、利润率、税率、NOPAT、净再投资、FCFF及审核信号。按当前模型税后利润率m分解：

```text
ΔNOPAT = Δ收入 × m本期 + 收入上期 × (m本期 − m上期)
```

交叉项归入收入贡献，这是代数约定而非独立因果识别。基期NOPAT使用显式税率代理，预测NOPAT从引擎现金流/投入还原（包括模型税额处理）。仅在收入增量及净投入均正时显示“收入贡献/净投入”的增量回报代理；无投入、收缩或资本释放时留空，不替代公司实际ROIC，也不恢复此前修正为空的完整隐含ROIC。

资本释放提示需要可回收资产证据；负FCFF提示资金来源问题，保留数值而不直接拒绝；正增长的增量回报代理低于WACC提示复核。行业历史平均仍明确为边际再投资代理，研发费用化与行业研发/租赁资本化口径尚未协调，`company_capital_efficiency_verified=false`。现金资本开支不能代替净资本投入；研发费用不另扣第二遍，也不自动转为未来收入。

方法依据：[达摩达兰增长基本面](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/growth.htm)区分投入、未来回报和既有资产效率变化，要求研发与租赁处理一致；[收入增量法](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/littlebook/growthvaluedrivers.htm)用收入增长和收入资本比估计再投资。新增诊断不修改其FCFF、净再投资、ROIC或WACC定义，未因诊断通过而批准新预测参数。

## 增量重估与失败恢复

`tools.batch_valuate_alphalake`仍调用同一API/引擎，新增`--previous-report`：先校验当前标准输入、政策有效期及参考新鲜度，再计算输入签名。签名保留全部事实、补充证据、政策、参考及解析后经济输入，仅排除查询截止等上下文时点及引擎事后生成的公司诊断。查询时点改变不能绕过到期检查；历史查询倒退不复用未来运行。

- 输入/证据及引擎未变：`reused_unchanged`，保留原run ID及原估值信息时点，另记`checked_as_of`，不重跑DCF。
- 输入、参考或政策变化：`recalculated`，保存新运行，复用既有比较工具逐组解释差异；不把多因素变化强行分摊为单因素贡献。
- 当前缺项、冲突、过期或执行失败：没有本次成功run ID/价格，仅保留`last_success`作历史证据，不回退旧值。
- 旧运行文件或索引签名被篡改：拒绝复用，不覆盖原文件。引擎升级后旧报告无法重放时，允许新计算，但比较标为不可重放，不能伪造归因。

批次`automation_counts`分别计数可计算、条件每股估值、需人工审核、拒绝及执行失败；这些维度有重叠，不相加当证券分母。成功模型仍有显式经济假设，所以成功计算不自动获得“无需人工审核”标签。保留未分配政策、零事实和失败公司。

日常`tools.refresh_valuate_alphalake`继续按原顺序同步、物化、读取参考、批量估值，在同一`--output-dir`中原子维护`incremental-state.json`。它是最新尝试及各公司最后成功记录，不是全市场成功检查点。子进程失败、输出损坏、物化失败均不得覆盖这份状态。数据库锁沿用现有实现；不同数据库不得复用同一状态文件。批次查询时限承接阶段时限，避免外层允许长任务、内层却固定300秒提前失败。

```bash
# 项目根目录、已安装backend依赖的Python环境
export PYTHONPATH=valuation/backend
export ALPHALAKE_VALUATION_RUN_DIR=workspace/valuation-runs
python -m tools.batch_valuate_alphalake <db> --period <报告期> --as-of <带时区截止> \
  --policy <已审核政策.json> --previous-report <前一批次.json> \
  --query-timeout 3600 --output-dir workspace/batches
```

第一次省略`--previous-report`。定时刷新沿用[现有命令](../../../docs/a-share-automation-acceptance-20260910.md)，保持output-dir及run目录稳定即可；没有另建守护进程或安装定时任务。新报告期仍须审核相应政策，不能跨期偷偷沿用旧审核；嵌入的参考快照是冻结输入，只有显式参考库/行业路由才自动选新参考。

## 实际验收范围

[回执](acceptance.json)包括真实隔离归档库的五轮CLI：首次计算、同输入重放、仅推进一天信息时点、审核过期、恢复有效时点。分母为该库安克/茅台2家：安克产生条件估值，茅台未配置政策保留在分母。两次未变化及恢复均复用同一run ID；过期轮明确拒绝且没有本次价格。另以受控财务/参考值变动验证触发重算，明确不是声称取得了新的真实财报或参考文件。刷新阶段调度/状态发布使用真实子进程与受控返回，不冒称在线全市场刷新验收。

主库苏泊尔单公司CLI最初因全市场就绪度扫描300秒超时。本轮增加`valuation-readiness --code`，先限定主数据候选再复用原查询，保留同代码歧义；全市场批次仍保留完整分母。主库重验得到`blocked_review_exclusion`、候选分母1、无估值，约2.72秒（单线程/1536MiB配置，不把此数称为仅SQL改动的独立性能基准）。排除政策现在被标为`company_exclusion`，与显式公司政策同级，不能让行业候选静默覆盖排除。

苏泊尔[2026H1原文网页索引](https://static.cninfo.com.cn/finalpage/2026-08-28/1225522987.PDF)第86/87页可读：一年内到期及非流动大额存单分别有7.5亿元、0.2亿元受限。原PDF文件经HTTPS、浏览器头、HTTP及download参数尝试仍返回403，未取得可归档原件。这是当轮取证结果。后续已取得新浪托管完整原文并显式关联到CNINFO公告，四项补充在主库副本入库；两个科目仅扣除受限额后按账面代理加回，没有整项无限制批准，详情见前述真实副本验收。

Python全套曾运行431项通过、4项因上游CIQ TEST_DATA缺失跳过；随后源投入诊断/单公司范围等最后修改的105项相关回归通过，排除优先级最后修正另单项复验通过。Go全套与构建通过，四项skip不属于本轮真实资产链测试。无依赖/数据库迁移，无主库写入。当前功能未证明公司边际资本效率已核验、全部A股可估值、预测更准确或上述条件值是市场目标价。

剩余数据工作：补齐安克完整经营资本分类、租赁及非现金投入桥接后再审核公司倍率。已有研发/年度分量已联合复验并纳入CI，三期使用权资产新增已通过生产补充入口接入标准长期投入分量链，结论仍是不足以采用公司边际资本参数；不重复计算局部倍率，不把拒绝结论说成实证闭合。三条主线保持此范围，不扩大异常公司研究或重新扫描预测阈值。
